## 关键约束（防止幻觉）

1. **架构**: 纯 Web + PWA，无 Electron，无原生 APP，无小程序
2. **移动端**: 仅文字团，无语音，无视频，锁屏断线可接受
3. **V1.0 范围**: 仅招募/求组板（模式 B），无实时招募，无 AI 主持人
4. **规则引擎**: Recipe 配方源 + 编译产物（atoms/connections）双层模型，无可视化原子画布，无工业级 PLC
5. **地图**: 2D 网格，单层，无迷雾，无 3D，V1.0 极简
6. **实时通信**: Socket.IO + HTTP，无 WebRTC，无直播
7. **数据库**: 单库 + Redis，4GB 内存，无分库分表，无 ES
8. **AI 功能**: 仅规划中，V1.0 不做任何 AI 功能
9. **社交**: 无公会，无战队，无排行榜，仅简单圈子和关注
10. **经济**: 无 C2C 交易，无拍卖行，仅创作者-玩家单向购买
11. 无emoji
12. **房间发现**: 无独立的“房间大厅”或“公开房间列表”。所有公开招募均通过社区-招募板的帖子进行，成团后房间仅出现在参与者“我的房间”中。

若以上约束与文档内容冲突，以本约束为准。

## 0.2 2026-04-27 创作者入口与权限修缮（新增）

### 创作者入口信息架构

| 平台 | 入口路径 |
|------|---------|
| 桌面端 | 主顶栏右侧"创作台"按钮（`/creator`），仅创作者可见 |
| 移动端 | ① 顶栏 `icon-workshop` 图标；② 个人页首屏创作台入口卡片（位于用户信息卡与 Stats 卡之间） |
| 共同 | 底部导航固定 5 项，**不新增**第 6 项 |

### 权限闭环约定

- `subscription_type === 'creator'` 或 `user_type` 含 `'creator'`/`'admin'` 的用户视为创作者
- 前端：路由 `/creator/**` 均设置 `requiresCreator: true`；全局守卫非创作者跳转 `Forbidden`
- 后端：rulesets/modules 写接口接入 `requireCreator` 中间件；返回 403
- 创作者状态写入 `authStore.isCreator` 并缓存至 `localStorage.is_creator`；用户信息加载中时入口不显示（骨架态）

### 加载与异常处理

- 用户信息加载中：显示骨架占位卡片，不显示任何创作台入口
- 用户信息加载失败：显示错误提示与重试按钮，明确反馈而非静默吞错
- 创作台内容未完成模块（素材库/我的作品）：显示"建设中"标签与下一步引导

## 0.4 术语锚点（统一口径）

为避免跨文档同义词并行维护，以下术语作为全局锚点，冲突时以本节为准：

1. 团 vs 房间：对外统一用“房间”（用户视角），数据模型统一用 `Campaign`（文档可写“房间（Campaign）”）。
2. 招募帖 vs 发车：统一用“招募帖”，“发车”不出现在任何控件、状态名和流程名中。
3. 场 vs 场景：统一用“场”（如剧情场、私密场、公共场）；历史文本中的“场景”逐步替换。
4. 角色卡 vs 人物卡：统一用“角色卡”。
5. KP vs GM vs 主持人：平台内统一用 `GM`；面向用户的产品文案可辅以“主持人”，但 API、表单、状态字段只使用 `GM`。

## 1. 术语定义与核心概念

### 1.1 基础术语

| 术语                      | 说明                                     | 示例                     |
| ----------------------- | -------------------------------------- | ---------------------- |
| **团（Campaign）**         | GM创建的顶层容器，包含剧情时间标签记录、所有场、成员列表、角色卡绑定      | "黑暗边缘团"                |
| **场（Scene）**            | 团内的子空间，分为剧情场、私密场、公共场三种类型               | "酒馆"、"刺客小队密谈"          |
| **剧情场（Spatial）**        | 真实叙事位置，玩家可移动至此，参与位置矩阵                  | "废弃教堂"、"警局档案室"         |
| **私密场（Virtual）**        | 秘密对话空间，不记录位置但记录时间线                     | "刺客小队"、"GM-张三密谈"       |
| **公共场（Lobby）**          | 非剧情闲聊空间，不参与时间同步                        | "银光酒馆大厅"               |
| **助理台（Assistant Desk）** | 固定置顶的个人沙盒面板，不视为场，测试掷骰不进log，GM暗骰记录仅自己可见 | 指令大全、暗骰记录（仅GM）         |
| **剧情时间标签**              | GM在聊天流中手动宣布的时间标记，格式 `HH:MM`（仅时、分）    | "08:30"            |
| **个人剧情时间**              | 角色进出场时 GM 可选填的剧情时间，仅用于轨迹矩阵与日志记录       | 角色A到达教堂时GM标记"08:30" |
| **轨迹矩阵**                | 可视化展示所有角色在各剧情场的时间分布图                   | 灰白分区表格                 |
| **写扩散**                | 消息发送时预计算可见角色列表并存储，避免查询时 JOIN 参与时间段表。                   | 灰白分区表格                 |
| **雪花 ID**                | 分布式唯一 ID 生成算法，保证消息 ID 全局单调递增，用于排序。                   | 灰白分区表格                 |

### 1.2 角色卡术语

| 术语 | 说明 |
|------|------|
| **角色卡（Character Sheet）** | 玩家创建的虚拟角色数据，包含属性、技能、资源 |
| **规则包（Ruleset）** | 定义角色卡结构、检定公式、派生计算的逻辑包 |
| **职业（Occupation/Class）** | 规则包定义的角色模板，影响属性成长和技能 |
| **派生值（Derived）** | 由基础属性自动计算的值（如HP、SAN、熟练加值） |

## 五、关键交互流程

### 5.1 简化开团流程

当用户从首页"快速组车卡片"或资产库"已拥有模组/规则包"点击 `[开团]` 时，系统将：
1. 自动创建私密团并按入口资产类型落库：
  - 从“模组资产”进入：绑定 `module_id` 与对应 `ruleset_id`。
  - 从“规则包资产”进入（无模组）：`module_id = null`，仅绑定 `ruleset_id`，创建空白团。
2. 跳过房间名填写、招募选项等步骤，直接进入房间。
3. 房间默认名规则：有模组时为"{模组名} 的团"；无模组时为"{规则包名} 的团"。GM 可后续在房间设置中修改。

此流程旨在将"从拥有资产到开始游戏"的点击次数降至最低。

### 5.2 用户目标路径汇总

| 用户目标 | 路径 | 点击次数 |
|----------|------|----------|
| 开一个私密团（和朋友玩） | 资产库点击`[开团]` → 填房间名 → 创建 | 2次（含表单确认） |
| 开一个公开招募团 | 资产库点击`[开团]` → 填房间名 + 勾选"公开招募" → 创建 → 跳转招募板 → 补充信息发布 | 4-5次 |
| GM招募玩家 | 社区→招募板→发布招募帖 → 填写表单 → 发布 | 3-4次 |
| 玩家找团 | 社区→招募板→找团玩 → 筛选 → 申请加入 | 3次 |
| GM邀请求组玩家 | 社区→招募板→当GM → 点击`[邀请入团]` → 选择现有/新建房间 → 发送 | 3次 |
| 玩家接受邀请 | 收到通知 → 点击接受 | 2次 |
| 观看一场公开招募团的游戏 | 社区→招募板→找团玩 → 筛选"可观战" → 点击`[观看直播]` | 3-4次 |
