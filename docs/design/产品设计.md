## 关键约束（防止幻觉）

1. **架构**: 纯 Web + PWA，无 Electron，无原生 APP，无小程序
2. **移动端**: 仅文字团，无语音，无视频，锁屏断线可接受
3. **V1.0 范围**: 仅招募/求组板（模式 B），无实时招募，无 AI 主持人
4. **规则引擎**: Recipe 配方源 + 编译产物（atoms/connections）双层模型，无可视化原子画布，无工业级 PLC
5. **地图**: 2D 网格，单层，无迷雾，无 3D，V1.0 极简
6. **实时通信**: Socket.IO + HTTP，无 WebRTC，无直播
7. **数据库**: 单库 + Redis，4GB 内存，无分库分表，无 ES
8. **AI 功能**: 仅规划中，V1.0 不做任何 AI 功能
9. **社交**: 无公会，无战队，无排行榜，仅简单圈子和关注
10. **经济**: 无 C2C 交易，无拍卖行，仅创作者-玩家单向购买
11. 无emoji：除「帖子表态表情」与「共用笔记内嵌表情包」外，全局禁止 emoji 与字符图标，统一使用 SvgIcon 体系。
12. **房间发现**: 无独立的“房间大厅”或“公开房间列表”。所有公开招募均通过「招募」标签发布招募帖进行，成团后房间仅出现在参与者「房间」标签中。
13. **作品阅览**: 全平台所有可阅览作品（模组、规则包、故事录等）统一使用「叙阅器」组件渲染。叙阅器采用内核+插件架构，内核负责基础渲染与权限校验，插件按品类与创作者配置动态加载。各品类不再单独开发阅览界面。

若以上约束与文档内容冲突，以本约束为准。

### 4. 代码生成规范

#### 4.1 组件与复用

*   **布局容器**：所有后台类页面（创作者后台、个人中心、「团途」页等）必须使用 `PageLayout` 组件，**不得手写独立布局**。
*   **空状态**：列表/搜索结果为空时，必须使用 `EmptyState` 组件，包含 SVG 占位图（来自 `icons.svg`）、标题、描述和操作按钮（如适用）。
*   **图标**：所有图标必须使用 `<SvgIcon name="icon-xxx" />`，**严禁使用 Emoji**。图标名参考 `附录 A04：SVG图标系统规范.md`。
*   **按钮**：主次顺序为“次操作在左，主操作在右”。主操作按钮背景色使用 `var(--btn-primary-bg)`。一个页面最多一个主操作。
*   **状态机**：涉及按钮状态（如申请加入、GM审批）必须使用对应附录中定义的 **Composable**（如 `useApplyButtonState`），禁止在组件内 `if-else` 手写状态判定。

#### 4.2 样式

*   **设计令牌**：所有颜色、间距、圆角、阴影必须使用设计令牌变量（`var(--color-*)`, `var(--space-*)`, `var(--radius-*)` 等）。**严禁硬编码** `#fff`、`#333`、`10px` 等裸值。
*   **作用域**：组件样式必须使用 `<style lang="scss" scoped>`。全局样式仅放在 `src/styles/` 目录。

#### 4.3 API 与网络

*   **封装层**：所有 HTTP 请求必须通过 `api/` 目录下封装的函数，组件内 **不得直接调用** `axios` 或 `fetch`。
*   **Socket.IO**：实时通信事件（跑团房间、私信）必须通过 `composables/useSocket.ts` 管理，组件内不得直接 `socket.emit`。
*   **幂等键**：所有写操作（POST/PUT/DELETE）的请求体中必须携带 `idempotent_key`（UUID v4 字符串），由前端生成。
*   **错误处理**：API 错误响应格式为 `{ success: false, error_code: string, message: string }`。前端必须处理常见错误码（如 `ROOM_FULL`, `PERMISSION_DENIED`）并给出用户提示。

#### 4.4 数据库与后端

*   **主键**：所有表主键使用 UUID v4（`VARCHAR(64)`），用户可见的公开 ID（如 UID、房间码）单独字段。
*   **JSON 字段**：扩展数据使用 `JSON` 类型字段（如 `extras`, `metadata`），避免频繁 ALTER TABLE。
*   **时间字段**：世界标准时间使用 `TIMESTAMP`，仅用于排序；剧情时间使用 `JSON` 格式 `{ day, hour, minute }`。

### 权限闭环约定

- `subscription_type === 'creator'` 或 `user_type` 含 `'creator'`/`'admin'` 的用户视为创作者
- 前端：路由 `/creator/**` 均设置 `requiresCreator: true`；全局守卫非创作者跳转 `Forbidden`
- 后端：rulesets/modules 写接口接入 `requireCreator` 中间件；返回 403
- 创作者状态写入 `authStore.isCreator` 并缓存至 `localStorage.is_creator`；用户信息加载中时入口不显示（骨架态）

### 加载与异常处理

- 用户信息加载中：显示骨架占位卡片，不显示任何创作台入口
- 用户信息加载失败：显示错误提示与重试按钮，明确反馈而非静默吞错
- 创作台内容未完成模块（素材库/我的作品）：显示"建设中"标签与下一步引导

## 1. 术语定义与核心概念

### 1.1 基础术语

| 术语                      | 说明                                     | 示例                     |
| ----------------------- | -------------------------------------- | ---------------------- |
| **团（Campaign）**         | GM创建的顶层容器，包含剧情时间标签记录、所有场、成员列表、角色卡绑定      | "黑暗边缘团"                |
| **场（Scene）**            | 团内的子空间，分为剧情场、私密场、公共场三种类型               | "酒馆"、"刺客小队密谈"          |
| **剧情场（Spatial）**        | 真实叙事位置，玩家可移动至此，参与位置矩阵                  | "废弃教堂"、"警局档案室"         |
| **私密场（Virtual）**        | 秘密对话空间，不记录位置但记录时间线                     | "刺客小队"、"GM-张三密谈"       |

## 14. 叙阅器（统一作品阅览器）

### 14.1 定位

叙阅器是全平台统一的作品阅览组件，所有可阅览作品类型（模组、规则包、故事录等）共用同一套内核，通过插件实现品类差异化。

### 14.2 核心原则

1. **一套内核，插件化扩展**：共用渲染引擎与权限框架，按需加载插件
2. **沉浸式优先**：默认隐藏非必要元素，聚焦内容本身
3. **创作者主权**：所有保护规则与功能开关由创作者自主配置
4. **阅览-执行闭环**：从阅读到开团的核心路径不超过 3 步
5. **分层保护**：保护核心叙事资产，放开工具性使用数据

### 14.3 架构分层

**内核层（全品类通用）**：
- 沉浸式渲染引擎：统一富文本、图片、结构化内容渲染，适配多端
- 权限校验引擎：按用户权限（游客/已获取/作者/管理员）匹配保护规则
- 基础操作框架：顶部悬浮栏、底部进度条、目录锚点体系

**插件层（按需开关）**：

| 插件 | 适用品类 | 说明 |
|------|---------|------|
| 划线笔记 | 全品类 | 分私密笔记（默认）、副GM共享笔记（模组专属）、公开划线评论三级 |
| 章节目录 | 全品类 | 自动抓取标题层级生成可跳转悬浮目录 |
| 阅读进度 | 全品类 | 自动记录阅读位置，支持多设备同步 |
| 分享 | 全品类 | 生成带平台Logo与作品封面的分享海报 |
| 导入开团 | 模组专属 | 将模组内容实例化到导演台，创建新团 |
| 结构化数据导出 | 模组专属 | 支持导出NPC、场、线索等 JSON/CSON 数据 |
| 房规引用 | 规则包专属 | 支持将规则包条款一键导入团房规 |

### 14.4 权限分层与界面差异

| 用户状态 | 可见内容 | 可用功能 |
|:---|:---|:---|
| 游客（未解锁） | 仅创作者设定的试读章节 | 禁用复制、划线、导出 |
| 已获取（已购买/免费领取） | 完整内容 | 所有创作者开启的插件功能 |
| 作者本人 | 完整内容 | 外加「编辑作品」快捷入口 |
| 管理员 | 完整内容 | 外加审核、违规处理入口 |

### 14.5 创作者权益保护体系

**内容层保护（全品类）**：

| 开关 | 规则 |
|------|------|
| 防批量复制 | 限制单次选中 ≤200 字，禁止全选/右键/打印；始终允许 ≤200 字选中用于划线笔记和 GM 引用 |
| 禁止公开评论 | 仅允许私密笔记，关闭公开展示划线评论 |
| 试读比例 | 创作者可自定义免费试读比例 |

**作品层保护（模组专属）**：

| 开关 | 规则 |
|------|------|
| 开放结构化数据导出 | 默认开启，导出数据自动嵌入作者信息与版权声明 |
| 禁止二次分发 | 禁止用户修改原作品后二次分发、售卖 |
| 导入开团权限限制 | 仅已购买用户可导入开团 |

**商业层保护（全品类）**：

| 开关 | 规则 |
|------|------|
| 禁止PDF导出 | 付费作品默认开启 |
| 溯源水印 | 付费作品默认开启，含用户UID |
| 版权声明自动嵌入 | 全作品默认开启 |

### 14.6 划线笔记的三级权限

所有划线笔记数据归属于用户账号，作者无权查看、删除或修改读者的私密笔记。

| 层级 | 可见范围 | 适用场景 |
|:---|:---|:---|
| 私密个人笔记（默认） | 仅自己 | GM备团记录、个人读后感；支持一键导出全本笔记 |
| 副GM共享笔记（模组专属） | 指定团的副GM | 多GM联合备团协作；完团后的故事分享统一发到讨论区-跑团分享 |
| 公开划线评论 | 所有读者 | 创作者开启后可用，营造社区氛围 |

### 14.7 导入开团流程（模组专属）

1. 点击阅览器顶部「导入开新团」→ 弹出侧边浮层
2. 选择导入内容：默认全选模组的剧情章节、NPC、场、线索、道具（GM可按需取消勾选）
3. 团基础配置：自动填充模组标题与简介，GM可选择目标规则包、招募状态、人数限制
4. 确认创建：系统生成团房间，选中的模组内容实例化到导演台对应模块，自动跳转导演台

导入后原模组更新不会同步到已创建的团。GM可在导演台内一键跳转回叙阅器查看原模组。

### 14.8 创作者后台配置

作品发布/编辑页底部新增「叙阅器设置」板块：
- 功能设置：勾选开启的插件，提供「全量开启」「极简阅读」一键预设
- 保护设置：分层配置保护规则，提供「付费作品严保护」「免费作品开放」「纯私密创作」三套预设模板
- 外观设置：自定义主题色、字体、行间距（默认使用平台统一主题）




## 五、关键交互流程

### 13.2 简化开团流程

当用户从「团途」→个人馆藏 或「探索」页中的"已拥有模组/规则包"点击 `[开团]` 时，系统将：
1. 自动创建私密团并按入口资产类型落库：
  - 从“模组资产”进入：绑定 `module_id` 与对应 `ruleset_id`。
  - 从“规则包资产”进入（无模组）：`module_id = null`，仅绑定 `ruleset_id`，创建空白团。
2. 跳过房间名填写、招募选项等步骤，直接进入房间。
3. 房间默认名规则：有模组时为"{模组名} 的团"；无模组时为"{规则包名} 的团"。GM 可后续在房间设置中修改。

此流程旨在将"从拥有资产到开始游戏"的点击次数降至最低。

### 13.3 用户目标路径汇总

| 用户目标 | 路径 | 点击次数 |
|----------|------|----------|
| 开一个私密团（和朋友玩） | 「我的资产」点击`[开团]` → 填房间名 → 创建 | 2次（含表单确认） |
| 开一个公开招募团 | 「我的资产」点击`[开团]` → 填房间名 + 勾选"公开招募" → 创建 → 跳转招募板 → 补充信息发布 | 4-5次 |
| GM招募玩家 | 「招募」→发布招募帖 → 填写表单 → 发布 | 3-4次 |
| 玩家找团 | 「招募」→找房间 → 筛选 → 申请加入 | 3次 |
| GM邀请求组玩家 | 「招募」→开团招人 → 点击`[邀请入团]` → 选择现有/新建房间 → 发送 | 3次 |
| 玩家接受邀请 | 收到通知 → 点击接受 | 2次 |
| 观看一场公开招募团的游戏 | 「招募」→找房间 → 筛选"可观战" → 点击`[观看直播]` | 3-4次 |
