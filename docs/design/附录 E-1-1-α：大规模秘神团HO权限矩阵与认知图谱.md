## E-1-1-α.1 适用场景

**触发条件（同时满足）**：
- 玩家角色数量 ≥ 6
- 每个角色拥有至少 1 条隐 HO（仅 KP + 该玩家可见）
- 模组包含 PVP 信息战机制（玩家间互相隐瞒或博弈）

**典型场景**：大规模秘神团、政治阴谋型 LARP、多方势力博弈型剧本杀改编。

**不适用场景**：普通 CoC 团（≤5 玩家，HO 无交叉）——此时大纲面板的标准"条件可见节点"机制即可满足需求。

## E-1-1-α.2 三层信息结构

| 层级 | 名称 | 可见范围 | 说明 |
|------|------|---------|------|
| **表 HO** | 公开信息 | 全体玩家 + KP | 角色公开背景、已知关系 |
| **隐 HO** | 私密信息 | KP + 该玩家本人 | 角色秘密、隐藏动机、私人线索 |
| **交叉暗线** | 跨角色关联 | 仅 KP | 多个角色的隐 HO 之间的隐藏关联，需玩家推理发现 |

**核心问题**：14 个角色 × 20+ 条 HO 条目 = 280+ 个单元格。需要工具支撑 KP 管理三层信息结构。

## E-1-1-α.3 四态认知状态机

### 状态定义

| 状态 | 标识 | 含义 | 视觉表现 |
|------|------|------|---------|
| `UNKNOWN` | — | 玩家尚未接触相关线索 | 灰色虚框 + 灰底 |
| `FUZZY` | ~ | 玩家有相关线索但推理链不完整 | 灰底 + 黄色边框 |
| `PERSONAL_CONFIRMED` | ✓ | 玩家推理完整，KP 已确认 | 主题色底 + 左侧 3px 色条 |
| `PUBLIC_CONFIRMED` | ✓✓ | 玩家主动向其他角色公开 | 主题色底 + 左侧 3px 色条 + 公开标记 |

### 状态转移规则

```
UNKNOWN ──[线索触发]──▶ FUZZY
FUZZY ──[KP确认 + 推理链完整度达标]──▶ PERSONAL_CONFIRMED
PERSONAL_CONFIRMED ──[玩家主动公开]──▶ PUBLIC_CONFIRMED
```

**约束**：
- `PUBLIC_CONFIRMED` 不可逆——公开后无法撤回
- KP 可强制将任意状态推进到 `PERSONAL_CONFIRMED`（剧情需要时）
- 推理链完整度 < 50% 时，系统对"允许确认"操作发出 ⚠ 警告，KP 需二次确认

## E-1-1-α.4 主视图：热力图矩阵

### 布局

```
             ┌─────────────────────────── 可见者（横轴）──────────────────────────┐
             │  玩家A  玩家B  玩家C  玩家D  玩家E  玩家F  ...  KP  │
┌────────────┼─────────────────────────────────────────────────────┤
│ 玩家A      │  [自身]  15%   0%    8%    ⚠️35%   0%   ...  100%│
│ 玩家B      │  0%    [自身]  22%   ⚠️41%  0%    12%  ...  100%│
│ 玩家C      │  🔶18%  0%   [自身]  0%    30%   ⚠️52% ...  100%│
│ ...        │  ...                                               │
└────────────┴────────────────────────────────────────────────────┘
  归属者（纵轴）
```

### 单元格说明

| 显示内容 | 含义 |
|---------|------|
| 百分比数字 | 信息密度（该归属者的信息中，可见者已解锁的比例） |
| 灰→蓝→紫 热力图 | 信息密度可视化（0%=灰，50%=蓝，100%=紫） |
| ⚠️ | 该单元格存在交叉线索风险（解锁过多可能触发角色冲突） |
| 🔶 | 该单元格信息归属于底层时间线，与表层时间线存在分歧 |
| `[自身]` | 角色对自身信息的认知（通常为 100%，但可设置"失忆"场景） |

### 点击行为

点击任意单元格，右侧弹出**抽屉详情面板**（见 §E-1-1-α.5）。

## E-1-1-α.5 抽屉详情面板

**触发**：点击热力图矩阵中的任意单元格（归属者 × 可见者）。

**面板内容**：

```
┌─────────────────────────────────────────────────────┐
│ 玩家C → 玩家F 的信息可见性                            │
│ 信息密度：52%（⚠ 高风险）                             │
├─────────────────────────────────────────────────────┤
│ ☑ HO-C-01：与受害者的隐秘关系   [已解锁] [个人确认✓] │
│    时间线：底层 🔶    交叉线索：→ 玩家A HO-A-03（红字）│
│    解锁条件：（已满足）                                │
│                                                     │
│ ○ HO-C-02：案发当晚的行踪       [已解锁] [模糊感知~]  │
│    时间线：表层       推理链完整度：35%               │
│    解锁条件：需发现"日记本"线索                       │
│                                                     │
│ □ HO-C-03：真实身份             [未解锁]              │
│    时间线：底层 🔶                                    │
│    解锁条件：推理链完整度 ≥ 80% 且 KP 批准            │
├─────────────────────────────────────────────────────┤
│ [单个解锁▼]  [Ctrl多选批量操作]  [撤销]               │
└─────────────────────────────────────────────────────┘
```

**操作**：
- **单个解锁**：点击 HO 条目右侧的解锁按钮，将该条目对"可见者"解锁
- **批量操作**：Ctrl/Shift 多选后，底部工具栏显示"批量解锁/批量锁定"
- **高风险二次确认**：批量解锁 5 条以上，或解锁会导致⚠冲突时，弹出确认对话框

## E-1-1-α.6 认知图谱视图

**触发**：在大纲面板顶部切换到"认知图谱"视图标签。

**图谱说明**：

力导向图，节点为角色，边线为角色间的信息关联。

| 边线样式 | 含义 |
|---------|------|
| 灰色实线 | 表 HO 关联（公开信息已建立连接） |
| 紫色虚线 | 隐 HO 关联（双方均知晓对方有关联，但内容保密） |
| 红色点划线（透明度随认知状态变化） | 交叉暗线（仅 KP 可见，玩家推理中） |

**交互**：
- 点击节点（角色）：高亮该角色的所有关联边线，侧栏显示该角色的信息密度汇总
- 点击边线：右侧抽屉显示该关联涉及的 HO 条目列表，可筛选
- 拖拽节点：调整布局（不影响数据）

## E-1-1-α.7 推理链验证面板

**触发**：点击任意 HO 条目的"查看推理链"按钮。

**面板内容**：

```
┌────────────────────────────────────────────────────┐
│ 玩家F 对 HO-C-02（玩家C行踪）的推理进度             │
│ 完整度：35%  ⚠ 不足以确认（需 ≥ 60%）              │
├────────────────────────────────────────────────────┤
│ ✓ 已收集：证人陈述（+15%）                          │
│ ✓ 已收集：现场照片（+20%）                          │
│ ○ 缺失：日记本线索（+30%）    → 位于"书房"场景     │
│ ○ 缺失：监控录像（+20%）      → 需检定成功         │
│ ○ 缺失：其他证人证词（+15%）  → 尚未触发           │
├────────────────────────────────────────────────────┤
│ KP裁决：[允许确认（越过门槛）]  [拒绝（条件不足）]  │
└────────────────────────────────────────────────────┘
```

**裁决规则**：
- 完整度 ≥ 60%：系统建议"允许确认"，KP 可一键批准
- 完整度 30%–60%：KP 可裁量，选择"允许"或"拒绝"
- 完整度 < 30%：系统标注"条件严重不足"，KP 强行批准需二次确认

## E-1-1-α.8 情报战概览面板

**触发**：大纲面板底部"情报战"标签。

### 8.1 信息优势分布图

横向条形图，每个玩家一行，显示：
- 已确认的秘密数量（深色）
- 模糊感知中的秘密数量（浅色）
- 未知秘密数量（灰色，仅 KP 可见）

### 8.2 潜在冲突引爆点

按"冲突风险分值"排序的列表（风险公式：信息不对称度 × 角色关系紧张度）：

```
🔴 高风险：玩家A ↔ 玩家C（风险 87/100）
   原因：玩家A 即将获得玩家C 的核心秘密，而玩家C 尚未知晓
🟡 中风险：玩家D ↔ 玩家F（风险 52/100）
🟢 低风险：玩家B ↔ 玩家E（风险 18/100）
```

### 8.3 推演模拟

点击任意冲突引爆点，可预览：
- **若冲突现在爆发**：哪些信息会被迫公开？影响哪些 HO 状态？
- **信息传播路径**：A 公开 → B 知晓 → B 的哪些推理链会因此完整？

预览操作不产生实际状态变更，仅可视化显示。

## E-1-1-α.9 双时间线叠层视图

### 定义

| 时间线 | 名称 | 内容 |
|--------|------|------|
| **表层时间线** | 行动记录 | 玩家可见的角色行动和事件 |
| **底层时间线** | 真相意图 | KP 设定的角色真实目的（对应标记 🔶 的内容） |

### 视图布局

```
时间线 ──── [表层] ────────────────── [底层]
             │                          │
19:00 ────── A出现在案发现场 ─── ← KP：A实际在取证据
19:30 ────── B在餐厅用餐     ─── ← KP：B在见线人
20:00 ────── 发现受害者       ─── ← KP：真实顺序不同
```

**跨层绑定**：KP 可将表层某个事件节点与底层某个"真相节点"绑定（拖拽连线）。

**推理触发预警**：当玩家的推理进度触及某个表层节点时，系统在 KP 界面显示对应底层节点的⚠预警提示。

## E-1-1-α.10 三态视觉语义（HO 矩阵专用）

| 状态 | 背景 | 左侧标记 | 文字颜色 |
|------|------|---------|---------|
| 未解锁 | 灰色虚框 + `#F5F5F5` 灰底 | 无 | `#AAAAAA` |
| 已解锁不可见（其他玩家视角） | `#FFFFFF` 白底 | 空心圆 ○ | `#CCCCCC`（不可读） |
| 已解锁可见 | 主题色底色 | 左侧 3px 实色条 | 正常色 |

## E-1-1-α.11 防错机制

| 机制 | 触发条件 | 表现 |
|------|---------|------|
| 操作撤销栈 | 任何状态变更 | Ctrl+Z 支持至少 5 步撤销 |
| 高风险二次确认 | 批量解锁 ≥ 5 条，或操作含⚠标记 | 弹出确认对话框，列出影响范围 |
| 全量操作确认 | 触发"向所有玩家解锁" | 对话框警告："此操作将影响 N 个角色的 M 条 HO" |
| 变更高亮反馈 | 任何状态变更后 300ms | 对应单元格或节点闪烁高亮动画 |
| 冲突保留 | 操作流同步冲突时 | 双方内容保留，KP 手动裁决（见附录 E-1-2 §E-1-2.3） |

## E-1-1-α.12 TypeScript 数据 Schema

```typescript
/** 认知状态 */
type CognitiveState = 
  | 'UNKNOWN'             // 未知
  | 'FUZZY'               // 模糊感知
  | 'PERSONAL_CONFIRMED'  // 个人确认
  | 'PUBLIC_CONFIRMED';   // 公开确认

/** 时间线层级 */
type TimelineLayer = 'surface' | 'underlying';

/** 单条 HO 条目 */
interface HOEntry {
  id: string;                    // 格式："HO-{角色缩写}-{序号}"，如 "HO-C-01"
  ownerId: string;               // 归属者的 playerId
  title: string;
  content: string;               // Markdown 格式
  timelineLayer: TimelineLayer;
  visibilityScope: {
    type: 'kp_only' | 'kp_and_owner' | 'selected' | 'all';
    selectedPlayerIds?: string[]; // type === 'selected' 时使用
  };
  unlockCondition?: string;      // 解锁条件的自然语言描述
  crossReferences: string[];     // 交叉引用的其他 HO id
}

/** 认知状态记录（某玩家对某条 HO 的认知） */
interface CognitionRecord {
  playerId: string;
  hoId: string;
  state: CognitiveState;
  reasoningChainProgress: number; // 0-100，推理链完整度百分比
  collectedClueIds: string[];      // 已收集的线索 id 列表
  confirmedAt?: Date;              // PERSONAL_CONFIRMED 的时间
  publishedAt?: Date;              // PUBLIC_CONFIRMED 的时间
  _version: number;                // 供后续 Yjs 接入预留
  _lastModified: Date;
}

/** 跨角色交叉暗线 */
interface CrossLine {
  id: string;
  involvedHOIds: string[];    // 至少包含 2 个不同归属者的 HO
  description: string;        // KP 专属描述
  riskScore: number;          // 0-100，冲突风险分值
  timelineLayer: 'surface' | 'underlying' | 'cross';
}

/** 推演模拟快照（不持久化） */
interface SimulationSnapshot {
  triggeredBy: string;            // 引爆点描述
  forcedPublicHOIds: string[];    // 将被迫公开的 HO
  affectedCognitionChanges: Array<{
    playerId: string;
    hoId: string;
    from: CognitiveState;
    to: CognitiveState;
  }>;
}
```
