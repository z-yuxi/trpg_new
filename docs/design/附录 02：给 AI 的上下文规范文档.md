# 给 AI 的上下文规范文档

> **版本**：V1.0  
> **最后更新**：2026-04-29  
> **适用范围**：所有 AI 辅助开发任务（前端/后端/全栈）  
> **前置阅读**：在开始任何开发任务前，AI 必须完整阅读本文档。

---

## 一、核心原则

1. **本文档是唯一真理**：任何与本文档冲突的旧文档、注释、示例，以本文档为准。
2. **禁止脑补**：本文档未明确定义的行为、状态、文案，必须询问人类开发者，不得自行推断。
3. **术语词典优先**：所有 UI 文案、变量命名、API 字段必须严格遵循术语词典，禁止使用同义词或自造词。
4. **组件复用检查**：生成任何新页面或组件前，必须先检查本文档中是否已有可复用的组件或状态机。

---

## 二、术语词典（强制遵循）

以下术语在整个平台中必须保持绝对统一，违者视为 Bug。

| 业务概念 | UI 文案（用户所见） | 前端变量/路由/组件 | 后端 API 字段/数据库 | **禁止使用** |
| :--- | :--- | :--- | :--- | :--- |
| 核心游戏载体 | **房间** | `room` | `campaign` | 团、Team、Game、Campaign（仅内部数据模型保留） |
| 寻找/组建游戏 | **招募** | `recruit` | `recruitment` | 组队、开黑、发车、约局 |
| 游戏主持人 | **GM** | `gm` | `gm` | KP、DM、主持人、ST |
| 玩家角色数据 | **角色卡** | `characterCard` | `character_sheet` | 人物卡、角色、Sheet、Character |
| 游戏内的子空间 | **场景**（或**场**，全文统一） | `scene` | `scene` | 地图、Scene（仅内部数据模型保留）、空间 |
| 创建游戏房间 | **创建房间** | `createRoom` | `create_campaign` | 开团、建团、开房 |
| 加入游戏房间 | **加入房间** | `joinRoom` | `join_campaign` | 参团、进团、进房 |
| 招募帖评论区楼层 | **楼层** | `floor` | `post_replies` | 回复、评论（仅指主楼层对帖子的直接回复） |
| 楼层下的子回复 | **楼中楼** | `subComment` | `reply_comments` | 回复的回复、二级评论 |

**实施要求**：
- 生成任何 UI 时，面向用户的文本必须使用“UI 文案”列。
- 生成任何前端代码时，变量、路由、组件名必须使用“前端变量/路由/组件”列（驼峰命名）。
- 生成任何后端接口、数据库 Schema、API 文档时，字段名必须使用“后端 API 字段/数据库”列（蛇形命名）。
- 严禁在任何新代码、新文案中出现“禁止使用”列中的词汇。

## 三、全局组件状态机

以下是平台核心操作的状态机定义。**所有相关按钮/入口的交互必须通过这些函数生成状态，严禁在组件中硬编码 if-else。**

### 3.1 申请加入招募帖按钮状态机

**使用场景**：招募帖卡片上的操作按钮、招募帖详情页的申请按钮。

```typescript
// 文件: src/composables/useApplyButtonState.ts

/**
 * 申请加入招募帖的按钮状态
 * 
 * @param applicationStatus 当前用户对该帖子的申请状态
 * @param recruitmentStatus 当前招募帖的状态
 * @param isGM 当前用户是否为该帖子的发布者 GM
 * @param isFull 是否已无席位
 * @param allowSpectate 是否允许观战（已成团后）
 * @param isLoggedIn 当前用户是否已登录
 */
export function getApplyButtonState({
  applicationStatus,
  recruitmentStatus,
  isGM,
  isFull,
  allowSpectate,
  isLoggedIn,
}: {
  applicationStatus: 'none' | 'pending' | 'invited' | 'confirmed' | 'waiting' | 'rejected';
  recruitmentStatus: 'draft' | 'open' | 'full' | 'grouped' | 'dissolved' | 'closed' | 'archived';
  isGM: boolean;
  isFull: boolean;
  allowSpectate: boolean;
  isLoggedIn: boolean;
}): { text: string; disabled: boolean; action: string | null; extra?: { countdown?: number; position?: number } } {
  // 1. 未登录 → 拦截
  if (!isLoggedIn) {
    return { text: '申请加入', disabled: false, action: 'showLogin' };
  }

  // 2. 已成团 → 根据观战权限显示
  if (recruitmentStatus === 'grouped') {
    if (allowSpectate && !isGM) {
      return { text: '观看直播', disabled: false, action: 'spectate' };
    }
    return { text: '已满员', disabled: true, action: null };
  }

  // 3. 已关闭/已解散/归档 → 无操作
  if (['closed', 'dissolved', 'archived'].includes(recruitmentStatus)) {
    return { text: '已结束', disabled: true, action: null };
  }

  // 4. 当前用户是发帖 GM
  if (isGM) {
    return { text: '管理招募', disabled: false, action: 'manage' };
  }

  // 5. 根据申请状态处理
  switch (applicationStatus) {
    case 'confirmed':
      return { text: '已加入', disabled: true, action: null };
    case 'invited':
      return { text: '确认入团', disabled: false, action: 'confirm', extra: { countdown: /* 剩余秒数 */ 0 } };
    case 'pending':
      return { text: '已申请', disabled: true, action: null };
    case 'waiting':
      return { text: '候补中', disabled: true, action: null, extra: { position: /* 候补序号 */ 0 } };
    case 'rejected':
      return { text: '申请被拒', disabled: true, action: 'viewReason' };
    case 'none':
    default:
      // 6. 招募帖开放且未满员
      if (recruitmentStatus === 'open' && !isFull) {
        return { text: '申请加入', disabled: false, action: 'apply' };
      }
      // 7. 已满员（但帖子仍 open，允许候补）
      if (recruitmentStatus === 'open' && isFull) {
        return { text: '加入候补', disabled: false, action: 'applyWaitlist' };
      }
      return { text: '不可用', disabled: true, action: null };
  }
}
```

**AI 指令**：所有“找团玩”/招募帖卡片的操作按钮，**必须**通过此函数生成状态。前端实现时，`action` 为字符串，由统一的事件处理函数分发；`extra` 中的数据仅用于展示。

### 3.2 软删除占位符规范

**使用场景**：评论区主楼层、楼中楼被删除后的占位显示。

```typescript
// 文件: src/components/DeletedPlaceholder.vue
// 这是一个全局组件，不应在业务页面中重新实现

interface DeletedInfo {
  type: 'floor' | 'subComment';        // 被删类型
  deletedBy: 'admin' | 'gm' | 'author'; // 删除者角色
}
```

**渲染规则**：

| 条件 | 占位文本 | 样式 |
| :--- | :--- | :--- |
| `type === 'floor' && deletedBy === 'admin'` | `[该楼层已被管理员删除]` | 灰色背景，高度 48px，居中灰字 14px |
| `type === 'floor' && deletedBy === 'gm'` | `[该楼层已被管理员删除]` | 同上 |
| `type === 'floor' && deletedBy === 'author'` | `[该回复已被作者删除]` | 同上 |
| `type === 'subComment'` | `[该回复已被删除]` | 40px 高灰色块，内含灰字 |

**AI 指令**：所有被软删除的内容，**必须**使用 `DeletedPlaceholder` 组件渲染。占位区域不可点击、不可展开、不可选中。严禁自行编写占位样式。

### 3.3 消息发送失败占位符

**使用场景**：聊天消息列表中发送失败的消息。

```typescript
// 文件: src/composables/useMessageStatus.ts
export type MessageStatus = 'pending' | 'sent' | 'failed';
```

**渲染规则**：

| 状态 | UI 表现 | 可执行操作 |
| :--- | :--- | :--- |
| `pending` | 气泡半透明（opacity 0.6），左侧加载动画 | 无 |
| `sent` | 正常气泡，右侧绿色对勾（可选显示） | 无 |
| `failed` | 气泡微红背景，右下角红色感叹号图标（20px） | 点击感叹号弹出菜单：重新发送 / 删除 |

**AI 指令**：所有聊天消息的气泡状态必须通过 `useMessageStatus` 管理。发送失败时，必须使用统一的感叹号图标（`icon-warning`），严禁使用 Emoji 或自建图标。

## 四、架构与代码红线

### 4.1 技术栈（不可偏离）

- **前端**：Vue 3 + TypeScript + Vite
- **状态管理**：Pinia
- **HTTP 客户端**：Axios（封装在 `api/` 目录下）
- **实时通信**：Socket.IO（仅用于 `/room` 和 `/user` 命名空间）
- **CSS**：SCSS，全局变量定义在 `src/styles/tokens.css`
- **后端**：Node.js + Express + TypeScript
- **数据库**：MySQL + Redis

### 4.2 禁止事项

1. **禁止在组件中直接调用 `axios` 或 `socket.emit`**：所有 API 请求必须通过 `api/` 目录下的封装函数，所有 Socket.IO 事件通过 `composables` 管理。
2. **禁止硬编码样式值**：所有颜色、间距、圆角、阴影必须使用设计令牌变量（`var(--color-*)` 等）。
3. **禁止引入 React/Angular 的库**：UI 库只能使用 Element Plus（Vue 3 版本）。
4. **禁止手写状态机逻辑**：如按钮状态、软删除占位符等，必须使用本文档中定义的对应 composable 或组件。
5. **禁止使用 Emoji**：界面中的所有图标必须来自 SVG 精灵图（`SvgIcon` 组件）。

### 4.3 强制复用

- **EmptyState 组件**：所有空状态页面（列表为空、404、错误）必须使用。
- **PageLayout 组件**：所有后台管理页面（创作者后台、设置页等）必须使用。
- **按钮主次顺序**：次按钮在左，主按钮在右。主按钮使用 `--btn-primary-bg`，且一个页面最多一个。

## 五、API 约定

1. 所有接口路径前缀为 `/api/`。
2. 所有写操作（POST/PUT/DELETE）必须携带幂等键 `idempotent_key`（UUID v4）。
3. 错误响应格式：
```json
{
  "success": false,
  "error_code": "ROOM_FULL",
  "message": "房间已满，无法加入"
}
```
4. 分页参数统一为 `page` 和 `limit`，返回 `{ data, total, page, limit }`。

## 六、开发流程

当 AI 接收到一个具体功能的任务时，执行以下步骤：

1. **阅读上下文**：先看本文档，确认有没有相关的术语、状态机、组件可直接复用。
2. **检查对应附录**：例如社区功能看附录 B，跑团房间看附录 C，规则引擎看附录 D01。
3. **输出代码**：严格遵循红线，复用已有逻辑。
4. **自检清单**：
   - [ ] 所有变量名、文案符合术语词典。
   - [ ] 按钮状态是否来自对应的 composable。
   - [ ] 颜色/间距等是否使用设计令牌变量。
   - [ ] 有无硬编码 API 路径或重复组件。
   - [ ] 空状态是否使用了 EmptyState 组件。
