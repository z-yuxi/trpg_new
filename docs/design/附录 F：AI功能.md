### 5.1A AI 模组导入的分片与上下文策略

#### 设计原则

AI 模组导入的核心挑战是：用户上传的模组文档可能长达数万字，而 AI 模型的上下文窗口有限。直接全文送入模型不仅成本高昂，且容易丢失中间段落的结构化信息。

因此，导入流程采用**分片-识别-合并**策略，将长文档切分为逻辑段落，逐片交给 AI 识别结构化实体，最后合并去重。

#### 分片规则

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| 按标题层级切分 | 有明确 H1/H2 结构的文档 | 识别 Markdown 标题或 Word 大纲层级，以 H2 为最小分片单元 |
| 按固定长度切分 | 无标题层级的纯文本文档 | 每 3000 字为一个分片，相邻分片保留 200 字重叠，避免实体跨片丢失 |

#### 上下文传递策略

每个分片送入 AI 时，携带以下精简上下文：

| 上下文字段 | 内容 | Token 预算 |
|-----------|------|:---:|
| 系统指令 | 当前任务描述（提取 NPC/场景/线索） | ~200 tokens |
| 前一片摘要 | 前一片中已识别的实体列表（仅名称+类型） | ~300 tokens |
| 当前分片正文 | 当前待处理的文本 | 受模型窗口限制 |
| 术语白名单 | 用户设定的专属名词，不可被 AI 改写 | ~100 tokens |

#### 合并与去重

1. 所有分片处理完毕后，系统将所有识别结果合并。
2. 同名实体（名称相似度 > 80%）自动合并，合并前展示给用户确认。
3. 合并后生成最终的 `mentions` 数组，回填到模组编辑器的文档 JSON 中。

#### 验收标准

- 分片导入的实体识别准确率 ≥ 70%（与全文导入持平）
- 单次导入的总 Token 消耗不超过全文导入的 120%
- 分片导入支持断点续传：某一片失败不影响其他片的处理

### 5.1B AI 校对的分段处理策略

#### 设计原则

AI 校对与模组导入不同：校对不需要全文上下文来理解故事脉络，每个段落是独立的校对单元。因此，校对采用**逐段独立处理**策略，不携带跨段落上下文，以最小化 Token 消耗和响应延迟。

#### 校对 Prompt 结构

每次校对请求只携带以下内容：

| 上下文字段 | 内容 | 说明 |
|-----------|------|------|
| 校对指令 | 错别字、标点、术语统一的检查规则 | 固定，可缓存 |
| 当前段落正文 | 待校对文本 | 单次不超过 1000 字 |
| 术语白名单 | 用户设定的专属名词 + 当前规则包的术语表 | 动态加载，不写死在 prompt 中 |

#### 分段规则

| 策略 | 实现方式 |
|------|---------|
| 按段落切分 | 以空行或 `<p>` 标签为分界，每个段落独立提交校对 |
| 超长段落处理 | 单段落超过 1000 字时，按句号切分，保留最后一个完整句子 |

#### 校对结果缓存

- 已校对且用户未修改的段落，其校对结果缓存 24 小时
- 用户修改段落后，缓存失效，下次校对重新处理
- 缓存的 key 为 `段落内容哈希 + 术语白名单版本`

#### 验收标准

- 单段落校对响应延迟 < 2 秒（使用 flash 端点）
- 缓存命中率 ≥ 60%（用户在编辑期间反复校对同一段落的场景）
- 校对结果不影响正文中骰子表达式、角色名、地名等受保护内容

### 5.1E 分层 Prompt 按需加载策略

#### 设计原则

每次 AI 调用只携带当前任务所需的最少上下文，不加载无关信息。Prompt 分为固定层和动态层，固定层可缓存，动态层按需加载。

#### Prompt 分层结构

| 层级 | 内容 | 缓存策略 | 示例 |
|------|------|:---:|------|
| **固定层** | 任务指令（校对规则、实体提取规则） | 可缓存，按任务类型复用 | 「你是一个 TRPG 模组校对助手，检查以下文本的错别字和术语一致性」 |
| **动态层-术语表** | 当前规则包的术语白名单 | 按规则包缓存 | 「受保护术语：侦查、SAN、1d100、d20」 |
| **动态层-上下文** | 当前段落的上下文（前一段摘要、当前章节标题） | 不可缓存，每次加载 | 「当前章节：第二章-丰庄外街；前文已出现 NPC：老罗、酒馆老板」 |

#### 缓存规则

| 缓存键 | 失效条件 |
|--------|---------|
| 固定层 | 任务指令变更 |
| 术语表 | 规则包版本更新 / 用户自定义术语白名单变更 |
| 上下文 | 不缓存，每次动态加载 |

#### Token 预算约束

| 层级 | 最大 Token 占比 | 说明 |
|------|:---:|------|
| 固定层 | ≤ 20% | 保证任务指令清晰但不占用过多窗口 |
| 动态层 | ≤ 15% | 术语表 + 上下文合计 |
| 正文 | ≥ 65% | 保证待处理文本有足够的窗口空间 |

### 5.1F AI 输出自动化正则验证

#### 设计原则

AI 校对和导入任务处理完成后，系统自动对 AI 输出进行正则扫描，验证受保护内容是否被意外改写。这是 AI 输出质量的最后一道自动化防线。

#### 验证清单

| 验证项 | 检测方式 | 检测范围 |
|--------|---------|---------|
| 骰子表达式完整性 | 正则匹配 `\d+d\d+` 模式，对比输入和输出中的骰子表达式是否一致 | 校对任务、导入任务 |
| 角色名/地名完整性 | 从输入中提取专有名词列表，正则扫描输出中是否全部保留且未被改写 | 校对任务 |
| 术语一致性 | 检查规则包术语表中的术语在输出中是否保持了原有写法 | 校对任务 |
| JSON Schema 校验 | 验证 AI 输出的结构化数据是否符合预期的 JSON Schema | 导入任务 |
| 特殊符号保护 | 检查 `@`、`#`、`[]` 等 Mention 标记符号是否被转义或删除 | 校对任务 |

#### 处理规则

| 验证结果 | 行为 |
|---------|------|
| 全部通过 | 正常输出 |
| 部分未通过 | 标记受影响的字段/段落，在预览中高亮提醒用户，不自动修改 |
| JSON Schema 校验失败 | 该段标记为处理失败，不生成预览 |

#### 验收标准

- 骰子表达式误改检出率 ≥ 95%
- 专有名词误改检出率 ≥ 90%
- JSON Schema 校验失败不进入合并流程

### 5.1C AI 角色卡一键导入

#### 功能定位

用户在创建角色卡时，可直接上传现有角色卡的截图或 PDF，AI 自动识别文字和数值，匹配当前规则包的 field_aliases 字段映射表，填充到角色卡模板中，用户确认后完成导入。将传统 15 分钟的手动录入压缩为 30 秒的上传确认。

#### 支持格式

| 格式 | 处理方式 |
|------|----------|
| PNG / JPG 截图 | OCR 提取文字 → AI 语义解析 |
| PDF 角色卡 | 提取文本 → AI 语义解析 |
| 粘贴代码（骰子机器人 .st 指令等） | AI 语义解析，与截图导入共享同一配额池 |

#### 导入流程

1. **上传**：拖拽或选择文件（PNG / JPG / PDF，≤ 10MB）
2. **AI 识别**：OCR 提取文字 → AI 按 field_aliases 匹配字段 → 返回字段-数值映射表
3. **预览确认**：按基础信息、属性、技能、资源分组展示识别结果，逐字段可修正或标记待确认
4. **完成导入**：已确认字段写入角色卡，跳转角色卡预览页

#### 隐私与安全

- 上传文件仅用于当次识别，识别完成后不保留原始文件
- 识别结果由用户确认后才写入，AI 不做自动决策
- 不上传角色卡中的私人笔记、背景故事等纯文本内容用于模型训练

#### 与现有导入体系的关系

| 导入方式 | 识别技术 | 消耗 AI 配额 |
|---------|:---:|:---:|
| CSON 文件导入 | 直接字段映射 | 否 |
| 粘贴代码导入 | AI 语义解析 + field_aliases | 是 |
| AI 截图/PDF 导入 | OCR + AI 语义解析 | 是 |
| 手动创建 | — | 否 |

### 5.1D 粘贴代码导入角色卡

#### 功能定位

用户将骰子机器人（Dice! / Seal / Olivo 等）或其他平台生成的角色卡代码粘贴到输入框中，系统自动解析出属性、技能、资源等字段，匹配当前规则包的 field_aliases 字段映射表后，预览确认并完成导入。

#### 支持格式

| 格式来源 | 识别方式 |
|---------|:---:|
| Dice! `.st` 指令 | 关键词 + 模板匹配 |
| Seal 角色卡 | 同上 |
| Olivo 人物卡 | 同上 |
| JSON 格式 | 直接解析（如有歧义再走 AI 语义解析） |
| 纯文本属性列表 | AI 语义解析 |

#### 导入流程

1. **粘贴**：将角色卡代码粘贴到输入框中，点击「预览解析结果」
2. **AI 解析**：识别格式来源 → 提取字段名和数值 → 按 field_aliases 匹配
3. **预览确认**：与 AI 截图导入共用同一套确认界面（基础信息/属性/技能/资源分组预览，逐字段可修正）
4. **完成导入**：已确认字段写入角色卡

#### 配额与计费

粘贴代码导入与 AI 截图/PDF 导入共享同一配额池（任务类型 `import_character`），遵循附录 H04 的 AI 配额体系：

| 会员等级 | 角色卡导入次数/月 |
|:---|:---:|
| 免费版 | 0 |
| 专业版 | 3 |
| 创作者版 | 10 |

导入失败（识别质量过低无法解析）不消耗配额。

**AI 安全**：

- **输入消毒**：XML 标签边界隔离用户内容，前置意图分类器检测越狱（准确率≥80%）
    
- **输出过滤**：敏感词匹配 + Azure Content Safety 语义分析
    
- **数据隐私**：明确声明用户跑团日志、模组内容**绝不用于**模型训练，提供 Opt-out 选项， 默认不用于训练
    
- **提示注入防护**：禁止执行系统指令修改，检测到可疑指令返回 `{"error": "suspicious_instruction_detected"}`

### 5.1G AI 辅助社区冷启动（测试脚本驱动）

#### 功能定位

社区上线前，通过测试脚本直接调用后端 API，驱动 5 个系统机器人账号（UID 1000095–1000099）自动完成发帖、表态、评论、举报全链路，兼顾种子内容投放与功能验收两个目标。

#### 工作流

```
node ai-bot-test.js
       │
       ├─ AI 生成文案（DeepSeek V4，按人设 Prompt 模板）
       │         ↓
       ├─ POST /api/posts              发帖（20 篇，分布到 3 个板块）
       ├─ POST /api/posts/:id/reactions 表态（每帖 3 条，随机表情）
       ├─ POST /api/posts/:id/replies   楼层评论（每帖 2 条）
       └─ POST /api/reports             举报（每帖 1 条，测试审核流程）
               ↓
       自动打印测试报告（成功/失败计数，覆盖板块与标签统计）
```

#### 文案生成策略

| 板块 | Prompt 模板关键词 | 字数 |
|------|----------------|:---:|
| 技巧交流（technique） | 规则讨论、技巧分享、机制分析 | 300-500 字 |
| 跑团分享（sharing） | 跑团感触、印象深刻的场景、角色成长 | 200-400 字 |
| 同好闲谈（lounge） | 轻松话题、社区互动、推荐讨论 | 100-200 字 |

- 文案由 DeepSeek V4 按各机器人人设生成，风格与平台社区调性一致。
- 不同机器人账号在不同板块发帖，避免单账号集中发帖。
- 每条帖子携带 `is_bot_generated=TRUE` 标记，与真实用户内容区分。

#### 脚本关键配置（`ai-bot-test.config.js`）

| 配置项 | 默认值 | 说明 |
|-------|:---:|------|
| `AI_POSTS.totalPosts` | 20 | 总发帖数 |
| `AI_POSTS.boards` | `['technique','sharing','lounge']` | 覆盖板块 |
| `AI_POSTS.longPostRate` | 0.2 | 长篇（≥1000字）占比 |
| `SIMULATION.reactions` | true | 是否模拟表态 |
| `SIMULATION.comments` | true | 是否模拟评论 |
