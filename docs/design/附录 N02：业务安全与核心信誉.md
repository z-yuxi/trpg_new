## N02.1 职责边界

本附录负责：

1. 掷骰公平性、可追溯性与防篡改机制。
2. 规则引擎沙箱安全加固口径。
3. 错误态、空状态与权限态的统一视觉规范。

本附录不负责：

1. 法律协议、隐私、侵权投诉与版权存证。
2. 社区信誉分体系、处罚等级与管理员执纪。
3. 账号登录、Token 与后台网络隔离。

## N02.2 掷骰公平性模块

核心原则：掷骰结果由服务端生成，不可篡改、可追溯、实时公开。

| 组件 | 必要性 | 核心价值 |
| --- | --- | --- |
| 随机数生成 | 必须保留 | 保证结果不可预测 |
| 结果记录 | 必须保留 | 支撑争议举证与审计追溯 |
| 结果展示 | 建议保留核心 | 增强透明度 |
| 资源限制 | 建议保留 | 防滥用、防服务崩溃 |

### 暗骰规则

1. 暗骰同样由服务端生成随机数。
2. 结果仅写入 GM 的暗骰记录，不广播聊天场。
3. 暗骰记录同样带哈希，支持争议核验。

### 防篡改机制

每次掷骰写库时同时计算 SHA-256 哈希，哈希输入至少包含：

1. campaign_id
2. character_id
3. 服务端毫秒时间戳
4. 骰子表达式
5. 随机结果
6. 上一条掷骰记录哈希

平台提供校验接口验证任意掷骰记录的真实性。掷骰记录一旦写入，不可编辑、不可删除。

## N02.3 规则引擎沙箱加固

1. 采用 isolated-vm 或等价安全沙箱。
2. 内存限制不高于 64MB。
3. 单次执行时间限制不高于 1 秒。
4. 禁止 eval、new Function 等动态代码执行。
5. 编译产物、白名单规则和参数变更都应触发缓存失效校验。

---

## N02.4 错误与空状态视觉规范

所有错误页面、空状态、离线提示统一使用 SVG 占位图，不使用纯文字代替。

| 状态 | Symbol ID | 场景 |
| --- | --- | --- |
| 404 页面未找到 | state-404 | 访问不存在页面 |
| 网络连接失败 | state-offline | WebSocket 断开、请求超时 |
| 无数据 | state-empty | 投骰历史为空、轨迹矩阵无记录 |
| 系统错误 | state-error | 服务端 5xx、数据解析失败 |
| 权限不足 | state-forbidden | 玩家访问 GM 功能 |

补充要求：

1. 禁用按钮必须同时展示锁图标和 tooltip 原因。
2. 图标颜色跟随主题变量 currentColor。
3. 后续替换视觉资源只允许替换 SVG symbol，不修改业务语义。

## N02.5 与 N03 的关系

1. 本附录定义“系统可信”和“执行安全”。
2. N03 定义“社区信誉”和“治理规则”。
3. 若业务安全事件需要影响社区信誉分，只能通过交叉引用进入 N03 的处罚体系，不得在本附录内重复定义分值。
