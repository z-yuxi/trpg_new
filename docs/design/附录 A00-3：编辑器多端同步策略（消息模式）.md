# 附录 A00-3：编辑器多端同步策略（消息模式）

> **定位**：将编辑器的跨端同步从"文件保存/覆盖"模式改为"聊天消息流"模式，彻底消灭多端覆盖风险。

---

## 1. 核心原则

**编辑器的每一次修改，都是一个不可变的事件，被追加到文档的操作流中。所有端消费同一个操作流，本地重放得到最终状态。**

此机制与平台聊天系统**完全一致**，复用已有的 Socket.IO 基础设施和环形缓冲区机制，无需引入新的技术栈。

---

## 2. 操作事件结构

```typescript
interface EditOperation {
  op_id: string;        // 雪花 ID，全局单调递增
  document_id: string;  // 所属文档
  user_id: string;
  device_id: string;    // 操作来源设备（同一用户多端区分）
  type: 'insert' | 'delete' | 'replace';
  position: number;     // 操作在文档中的字符位置
  content: string;      // 插入 / 替换的内容（delete 时为空）
  timestamp: number;    // 服务端接收时间戳（毫秒）
  base_version: number; // 操作基于的文档版本号，用于冲突检测
}
```

---

## 3. Socket.IO 事件定义

| 方向 | 事件名 | Payload | 说明 |
|------|--------|---------|------|
| Client → Server | `join_document` | `{ document_id, last_event_id }` | 加入文档编辑频道；`last_event_id` 用于请求补发断线期间的操作 |
| Client → Server | `leave_document` | `{ document_id }` | 离开文档编辑频道 |
| Client → Server | `edit_op` | `EditOperation` | 提交一个编辑操作 |
| Server → Client | `edit_op_broadcast` | `EditOperation` | 广播给频道内**其他**客户端（不回显给发送方） |
| Server → Client | `missed_ops` | `EditOperation[]` | 重连后补发断线期间的操作流 |

---

## 4. 命名空间

使用独立的 **`/documents`** 命名空间，与现有的 `/room`、`/user` 完全隔离。

---

## 5. 离线处理

- 移动端输入时本地 **500ms 防抖**，生成一个操作事件后提交。
- 断网时操作事件写入 **IndexedDB 队列**。
- 恢复网络后按 **FIFO** 顺序提交，携带相同的 `op_id` 进行幂等去重。
- 在收到服务端确认前，本地草稿**不清除**。

## 7. 与现有 HTTP 保存接口的关系

HTTP 保存接口（如 `POST /api/modules/{id}/save`）保留，用于：

1. **冷启动全量加载**：页面首次打开时通过 HTTP 获取当前文档快照。
2. **手动备份保存**：无实时编辑场景（如纯 API 调用）下的手动保存。

在有实时编辑的场景下，操作流通过 Socket.IO 提交，HTTP 接口**不作为**主要写入通道。
