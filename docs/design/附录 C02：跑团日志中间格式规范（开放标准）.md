## C02.1 设计目标

本规范定义开放、结构化、可扩展的跑团日志中间格式（ILF），用于：

1. 跨平台交换跑团数据。
2. 保留场、角色、剧情时间等叙事语义。
3. 作为下游转换器（HTML/PDF/Markdown/Replay/AI）的统一输入。

## C02.2 顶层结构

// [P1] 已实现
interface ILFDocument {

  character_id: string;     // [P1]

## C02.3 时间与事件模型

### C02.3.1 消息类型（P1 当前实现）

| type | 含义 | 实现状态 |
|------|------|---------|
| `dialogue` | 角色对话 | ✅ P1 |
| `narration` | 叙事描述（GM/系统叙述） | ✅ P1 |
| `dice` | 骰子检定结果（含 `dice_result` 附属字段） | ✅ P1 |
| `system` | 系统消息（进出场、公告、场景过渡） | ✅ P1 |
| `ooc` | 场外闲聊 | ✅ P1 |

> **P2 规划类型**：`scene_transition`（场景过渡专用）、`system_event`（可结构化查询的系统事件）、`gm_note`（GM 私有笔记，默认不导出）。P1 中场景过渡统一编码为 `type='system'`；GM 私有笔记不进入日志流。

### C02.3.2 时间字段约定

1. **`story_time`**（P1）：剧情内时间，可为 `null`。
2. **现实时间**：P1 通过 `metadata.export_at` + 消息序号 `seq` 保序，不强制 `real_time` 字段。
3. **P2**：扩展 `real_time` 字段用于按现实时间轴检索与 Replay 回放。

### C02.3.3 角色快照

- P1 不包含角色状态快照字段。
- P2：在 `ILFMessage` 中可选携带 `character_snapshot`，用于关键时刻复盘。

## C02.4 扩展机制

1. 允许 `x_*` 扩展字段。
2. 解析器必须忽略未知扩展字段，不得因扩展字段中断解析。
3. 主版本内保持向后兼容：新增字段可选、现有字段语义不变。

## C02.5 转换器约束

1. 采用单向转换：ILF -> 目标格式。
2. 支持按权限过滤（例如过滤 `gm_only` 内容）。
3. 转换失败必须返回可定位的结构化错误，不得静默吞错。

## C02.7 最小示例

### C02.7.1 P1 最小合法示例（当前可用）

```json
{
  "campaign": {
    "metadata": {
      "version": "1.0",
      "campaign_title": "午夜教堂异闻录",
      "rule_system": "COC7",
      "export_at": "2026-04-30T12:00:00Z"
    },
    "players": [
      { "character_id": "char_1", "character_name": "阿尔文", "player_name": "玩家A" }
    ],
    "scenes": [
      {
        "id": "scene_1",
        "name": "钟楼",
        "messages": [
          {
            "seq": 1,
            "scene_id": "scene_1",
            "scene_name": "钟楼",
            "story_time": { "day": 1, "hour": 20, "minute": 15 },
            "speaker": "阿尔文",
            "type": "dialogue",
            "content": "我推开门，手电照向楼梯。"
          }
        ]
      }
    ]
  }
}
```
