> 状态：v1.0（权威口径）
> 用途：统一关键状态机，供产品、前后端与测试共同引用。

## 表 8：招募帖状态机

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| draft | open | 发布招募帖 |
| open | full | 席位达到上限 |
| full | open | 席位释放或扩容 |
| open | grouped | GM 成团成功 |
| full | grouped | GM 成团成功 |
| open | closed | GM 手动关闭或截止时间到达 |
| full | closed | GM 手动关闭或截止时间到达 |
| grouped | dissolved | 流团/解散 |
| grouped | archived | 超时归档（策略触发） |
| closed | archived | 超时归档（策略触发） |

补充约束：
- grouped 后不可回退为 open 或 full。
- dissolved 与 archived 为终态，不可新增申请。

## 表 9：预约移动状态机

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| pending | approved | GM 批准并填写预约到达时间 |
| pending | executed | GM 批准时未填时间（立即执行） |
| pending | cancelled | 玩家取消或 GM 拒绝 |
| approved | executed | 时间推进触发自动执行（到达 execute_at_story） |

补充约束：
- 自动调度仅处理 approved 且 execute_at_story 非空的记录。
- pending 到 executed 属于快捷路径，允许与主路径并存。

## 表 11：模组（Module）发布状态机

| 当前状态 | 允许转换到 | 触发条件 | 触发方 |
|---|---|---|---|
| draft | reviewing | 创作者提交审核 | 创作者 |
| reviewing | public_notice | 管理员审核通过 | 管理员 |
| reviewing | suspended | 管理员直接拒绝并暂停 | 管理员 |
| public_notice | public | 公示期满 7 天，自动转换 | 系统（定时任务） |
| public_notice | suspended | 公示期内管理员介入 | 管理员 |
| public | suspended | 管理员暂停上架 | 管理员 |
| suspended | draft | 创作者修改后重新进入草稿，可再次提交 | 创作者 |
| public | archived | 创作者手动下架 | 创作者 |

补充约束：
- `suspended` 状态下创作者只可编辑，不可直接跳过审核重新发布；必须经由 draft → reviewing 路径。
- `archived` 为软终态：创作者可将 archived 改回 draft 重新编辑发布；数据不删除。
- `public_notice` 期间已购买用户不受影响；若最终 suspended 则购买入口关闭，已购保留。
- 公示期时长由运营参数 `PUBLIC_NOTICE_DAYS`（默认 7）控制，不硬编码。

UI 文案映射：

| 存储枚举 | 创作者后台文案 | 叙阅器/市场展示 |
|---|---|---|
| draft | 草稿 | 不展示 |
| reviewing | 审核中 | 不展示 |
| public_notice | 公示中（X 天后上架） | 公示中（倒计时） |
| public | 已上架 | 正常展示 |
| suspended | 已暂停（含原因） | 不展示 |
| archived | 已下架 | 不展示 |

## 表 12：规则包（Ruleset）发布状态机

| 当前状态 | 允许转换到 | 触发条件 | 触发方 |
|---|---|---|---|
| draft | reviewing | 创作者提交审核 | 创作者 |
| reviewing | published | 管理员审核通过 | 管理员 |
| reviewing | draft | 管理员驳回，附驳回理由 | 管理员 |
| published | deprecated | 创作者弃用，或平台因兼容问题强制弃用 | 创作者 / 管理员 |

补充约束：
- 规则包不设 `public_notice` 和 `suspended` 状态，审核通过即上线。
- `deprecated` 后已绑定该规则包的团仍可继续使用；新团不可选择已弃用的规则包。
- 规则包弃用前系统应提示已关联的模组数量。

UI 文案映射：

| 存储枚举 | 创作者后台文案 | 市场展示 |
|---|---|---|
| draft | 草稿 | 不展示 |
| reviewing | 审核中 | 不展示 |
| published | 已发布 | 正常展示 |
| deprecated | 已弃用 | 标注"已弃用"，不可新建团时选择 |

## 表 13：房间（Campaign）状态机

| 当前状态 | 允许转换到 | 触发条件 | 触发方 |
|---|---|---|---|
| preparing | running | GM 宣布开始 | GM |
| running | paused | GM 暂停房间 | GM |
| paused | running | GM 恢复房间 | GM |
| running | ended | GM 结束跑团 / 流团解散 | GM |
| paused | ended | GM 直接结束（不需恢复） | GM |

补充约束：
- `preparing` 状态下玩家可进入公共场聊天，但剧情场不可用。
- `ended` 为终态，不可回退；日志在 ended 后自动冻结为只读。
- 房间无 `archived` 状态，`ended` 即为归档态；前端房间列表区分"进行中"与"已结束"靠 status 过滤。
- 房间数量超出免费版限制（≤3）时，GM 不可新建团，但现有团不强制结束。

UI 文案映射：

| 存储枚举 | 房间列表文案 | 操作按钮 |
|---|---|---|
| preparing | 准备中 | 进入 / 开始 |
| running | 进行中 | 进入 |
| paused | 已暂停 | 进入 / 恢复 |
| ended | 已结束 | 查看日志 |

## 表 14：订单（Order）状态机

### 14.1 购买订单（orders 表）

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| pending | paid | 支付回调确认成功 |
| pending | failed | 支付超时（30 分钟）或支付渠道返回失败 |
| paid | refunded | 退款申请审核通过，款项原路退回 |

补充约束：
- `failed` 为终态，不可重试；用户需重新下单。
- `refunded` 后平台收回已授权的内容访问权（模组/规则包）。
- 订单创建时须携带前端生成的 `idempotent_key`，防止重复下单。

### 14.2 创作者收益结算（creator_earnings 表）

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| pending | settled | 结算周期到达，平台批量结算 |
| settled | refunded | 对应购买订单发生退款，收益回撤 |

### 14.3 创作者提现申请（withdrawal_requests 表）

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| pending | processing | 平台受理提现申请 |
| processing | paid | 资金打款成功 |
| processing | rejected | 审核不通过（附原因） |

补充约束：
- `rejected` 后对应金额返回创作者余额，可重新申请。
- 最小提现金额由运营参数控制（默认 100 元）。

UI 文案映射（购买订单）：

| 存储枚举 | 用户可见文案 |
|---|---|
| pending | 待支付 |
| paid | 已完成 |
| failed | 支付失败 |
| refunded | 已退款 |

## 表 15：创作者申请（creator_applications 表）状态机

| 当前状态 | 允许转换到 | 触发条件 | 触发方 |
|---|---|---|---|
| pending | approved | 管理员审核通过 | 管理员 |
| pending | rejected | 管理员驳回（附驳回理由） | 管理员 |
| approved | revoked | 管理员撤销创作者资格（附原因） | 管理员 |
| rejected | pending | 7 天冷却期后用户重新提交申请 | 用户 |
| revoked | pending | 用户重新提交申请（无冷却期限制） | 用户 |

补充约束：
- `approved` 触发后：`users.user_type` 写入 `creator`，`subscription_type` 保持不变（由用户自主升级）。
- `revoked` 触发后：`users.user_type` 移除 `creator` 标签；已上架作品不强制下架，但新内容提交通道关闭，直至重新通过审核。
- 管理员驳回时必须填写驳回原因，系统通知创作者站内信 + 推送。
- 重申请时系统自动检查冷却期是否已过，未到期则返回 `COOLDOWN_NOT_EXPIRED` 错误。

UI 文案映射：

| 存储枚举 | 申请人可见文案 |
|---|---|
| pending | 审核中 |
| approved | 已通过 |
| rejected | 已驳回（含原因） |
| revoked | 资格已撤销（含原因） |

## 表 16：角色卡（character_sheets 表）状态机

| 当前状态 | 允许转换到 | 触发条件 | 触发方 |
|---|---|---|---|
| draft | active | 玩家将角色卡绑定到团 | 玩家 |
| active | draft | 玩家从团中解绑角色卡 | 玩家 |
| active | archived | 团结束（ended）时系统自动归档所有绑定角色卡 | 系统 |
| draft | archived | 玩家手动归档不再使用的角色卡 | 玩家 |
| archived | draft | 玩家从归档中恢复，重新激活为草稿 | 玩家 |

补充约束：
- 同一角色卡在同一时间只能绑定到一个团（`active` 时不可再次绑定至其他团）。
- `archived` 非终态，玩家可恢复为 `draft` 后重新使用。
- 删除角色卡需先归档；`active` 状态下不可直接删除。
- 角色卡无 `reviewing` 状态，不需平台审核；创作者归属完全属于用户。

UI 文案映射：

| 存储枚举 | 角色档案列表文案 | 操作 |
|---|---|---|
| draft | 空闲 | 编辑 / 绑定到团 / 归档 |
| active | 使用中（团名） | 查看 / 解绑 |
| archived | 已归档 | 恢复 / 删除 |
