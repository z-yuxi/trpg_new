> 状态：v1.0（权威口径）
> 用途：统一关键状态机，供产品、前后端与测试共同引用。

## 表 8：招募帖状态机

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| draft | open | 发布招募帖 |
| open | full | 席位达到上限 |
| full | open | 席位释放或扩容 |
| open | grouped | GM 成团成功 |
| full | grouped | GM 成团成功 |
| open | closed | GM 手动关闭或截止时间到达 |
| full | closed | GM 手动关闭或截止时间到达 |
| grouped | dissolved | 流团/解散 |
| grouped | archived | 超时归档（策略触发） |
| closed | archived | 超时归档（策略触发） |

补充约束：
- grouped 后不可回退为 open 或 full。
- dissolved 与 archived 为终态，不可新增申请。

## 表 9：预约移动状态机

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| pending | approved | GM 批准并填写预约到达时间 |
| pending | executed | GM 批准时未填时间（立即执行） |
| pending | cancelled | 玩家取消或 GM 拒绝 |
| approved | executed | 时间推进触发自动执行（到达 execute_at_story） |
| approved | cancelled | GM 手动取消或目标场景失效自动取消 |

补充约束：
- 自动调度仅处理 approved 且 execute_at_story 非空的记录。
- pending 到 executed 属于快捷路径，允许与主路径并存。

## 表 11：房间（Campaign）状态机

> 来源：`packages/server/src/services/campaign-service.ts` — `CampaignService`

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| *(初始)* | preparing | 调用 `create()` 写入，固定初始状态 |
| preparing | running | GM 启动游戏（`update({ status: 'running' })`） |
| running | paused | GM 暂停游戏（`update({ status: 'paused' })`） |
| paused | running | GM 恢复游戏（`update({ status: 'running' })`） |
| running | ended | GM 结束游戏（`update({ status: 'ended' })`） |
| paused | ended | GM 结束游戏（`update({ status: 'ended' })`） |

补充约束：
- `ended` 为终态，不可回退至 `running` 或 `paused`。
- `preparing` 仅在 `create()` 时写入，不应通过 `update()` 外部设置。
- `preparing → paused` 不存在合法路径（未启动不可暂停）。

## 表 12：招募申请（RecruitmentApplication）状态机

> 来源：`packages/server/src/services/recruitment-service.ts` + `recruitment-domain.ts`

| 当前状态 | 允许转换到 | 触发条件 |
|---|---|---|
| *(无申请)* | pending | 玩家申请加入（帖状态 `open` 且席位未满，`createApplication`） |
| *(无申请)* | waiting | 玩家申请加入（帖状态 `full` 或 `apply_type=waiting`，`createApplication`） |
| pending | invited | GM 审批通过（`reviewApplication approve`），写入 24h 确认截止时间 |
| pending | rejected | GM 审批拒绝（`reviewApplication reject`），自动触发候补升级 |
| waiting | invited | 席位释放时自动提升候补首位（`promoteNextWaiting`），候补队列整体前移 |
| invited | confirmed | 玩家在截止时间前确认入团（`confirmApplication`），触发席位重新计算 |
| invited | rejected | 邀请 24h 超时未确认（`expireInvites` 定时任务），自动提升下一候补 |
| pending/invited/waiting | rejected | GM 发起成团（`formGroup`），批量拒绝所有未处理申请，原因：招募帖已成团 |

补充约束：
- `INVITE_EXPIRY_HOURS = 24`，`invited_expires_at` 字段记录截止时间戳。
- `confirmed` 状态计入 `player_count_joined`，联动招募帖 `open ↔ full` 切换。
- `waiting_position` 在候补被提升后整体 `decrement(1)`，保持队列连续。
- 同一用户对同一帖子只能有一条申请记录，重复申请抛出异常。
