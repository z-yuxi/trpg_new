## E-1.1 核心设计原则

1. **不打扰写作流**：任何 UI 元素、自动补全、弹窗，都不应在写作过程中意外打断光标。工具栏在停止输入 3 秒后淡出，鼠标移回顶部时淡入。
2. **结构化软融入**：结构化块（▼/◆/☆/▸/【】/[]）使用左侧色条 + 极浅灰背景融入正文流，不使用硬边框卡片。
3. **上下文感知**：右侧面板根据光标位置动态切换内容，浮动面板支持从面板拖出独立置顶对照。
4. **场景分离**：桌面端是深度创作工作站，移动端是灵感捕获与轻量阅读器。两端不是功能缩水，而是工序分工。

## E-1.3 桌面端页面架构

### E-1.3.1 可变三栏 + 浮动面板系统

桌面端不采用固定三栏，而是根据当前任务动态重组空间：

**构思期（单栏专注）**：
- 顶部极简工具栏，停止输入 3 秒后透明度降至 0.3
- 编辑器全宽（90% 视口），最大化写作区域

**结构化期（双栏对照）**：
- 左侧大纲面板（240px 固定宽度，不支持拖拽调整）
- 右侧编辑器核心区域

**精修期（三栏 + 浮动）**：
- 左侧大纲面板
- 中间编辑器核心区域
- 右侧上下文属性面板（280px，可折叠）
- NPC 卡片、线索详情、规则速查可从右侧面板拖出成为独立浮动窗

### E-1.3.2 大纲导航面板

大纲面板支持三种组织视图，一键切换：时间轴、空间树、节点网络。完整交互规范见 [《附录 E-1-1：大纲面板交互基线》](./附录%20E-1-1：大纲面板交互基线.md)。

**核心约束**：
- 场景节点右侧显示完成度指示条（绿色=已填写，灰色=空）
- 拖拽场景调整顺序时，被拖拽场景在编辑器中高亮边框
- 节点支持最多五层嵌套，默认展开到第二层
- 当前编辑器光标所在的节点在大纲中高亮
- KP专属节点（☆标记）在大纲中仅在KP视角可见，显示黄色锁图标
- 条件可见节点显示为灰色虚框，提示"尚未解锁"

### E-1.3.3 浮动面板系统

**创建方式**：
- 右侧面板中，每个卡片标题栏有拖拽手柄（hover 显示）
- 按住手柄拖拽，或按住卡片空白处 + `Alt + 拖拽`

**拖拽反馈**：
- 按下鼠标瞬间：卡片缩小至 80%，透明度 60%，跟随光标
- 拖出右侧面板边界（>20px）：原位置留下虚影占位框
- 释放后：卡片恢复 100% 大小，带有弹性动画（scale 0.95→1.0，200ms ease-out）

**吸附行为**：
- 靠近屏幕边缘（<40px）：自动贴边吸附
- 靠近其他浮动面板（<20px）：自动对齐，显示蓝色对齐辅助线
- 释放时位于编辑器文本区域正上方：不穿透，浮于最上层

**空间管理**：
- 多个面板重叠时，点击任意面板将其置顶
- `Shift + 点击`标题栏：自动平铺排列，基于可用屏幕空间计算布局（2×2、3列等）
- `Alt + 点击`标题栏：收起为侧边标签（宽 40px，高 120px），hover 滑出，移开收缩
- 最小化按钮 `[_]`：面板收缩为屏幕边缘的垂直标签

**四种浮动窗类型**：

| 类型 | 专属交互 | 用途 |
|------|---------|------|
| **NPC 卡片浮动窗** | 点击属性值可原地编辑；点击“出现场景”跳转编辑器；拖拽到正文插入 Mention | 写作时对照角色属性 |
| **线索详情浮动窗** | 拖拽到 ▼ 节点自动创建条件分支；状态切换同步更新正文引用 | 管理线索与场景的关联 |
| **场景对照浮动窗** | 默认滚动同步（按内容长度比例）；解锁后可独立滚动；选中文字自动复制 | 写结局时对照导入章节 |
| **规则速查浮动窗** | 一键插入检定标签；自动统计本模组使用次数 | 写作时快速引用规则 |

**固定到当前场景**：每个浮动窗有“固定到当前场景”开关，开启后切换场景时自动隐藏。

## E-1.4 结构化块视觉规范

所有结构化块使用左侧色条 + 极浅灰背景融入正文流，不使用硬边框卡片。

| 块类型 | 触发符号 | 色条颜色 | 背景 | ProseMirror Node 名 | 说明 |
|--------|---------|---------|------|-------------------|------|
| 交互节点 | `▼` | `#4A90D9`（品牌蓝） | `#F5F9FF` | `investigable_node` | 玩家可调查/对话的点，光标可进入编辑正文，Enter 新建段落 |
| NPC 点名 | `◆` | `#9013FE`（紫） | `#FAF5FF` | `npc_mention` | 首次出现或关键 NPC，存储 entityId 和 label，不存储完整属性 |
| KP 信息 | `☆` 或 `👁` | `#F5A623`（黄） | `#FFFBF0` | `kp_info`（虚线边框） | GM 隐藏层，切换“玩家模式”时自动折叠为细线 |
| 后果提示 | `▶` | `#4A90D9`（同交互节点） | 无独立背景 | `consequence_hint` | 触发条件→后果描述 |
| 玩家资料 | `【】` | `#F5A623`（橙） | `#FFFBF0` | `player_handout` | 可发放信息卡 |
| 规则引用 | `[]` | `#B0B0B0`（灰） | 无 | `rule_ref` | 检定/伤害/属性值，内联显示 |
| 条件分支 | `▸` | `#50C878`（绿） | `#F5FFF8` | `branch_node` | 条件→结果，可嵌套 |
| 自由文本 | 无 | 无 | 无 | `paragraph` | 氛围描写、叙事过渡 |

**通用交互规则**：
- 原子块 hover 时显示轻量边框（1px solid `#E0E0E0`）
- 原子块内部的 Backspace/Delete 行为：标记前 Backspace 删除整个节点；标记后 Delete 删除整个节点
- 原子块内部不支持嵌套另一个原子块（保持文档模型扁平）

### E-1.4.1 Markdown 快捷输入对应

| 输入 | 结果 | 说明 |
|------|------|------|
| `# ` | H2 标题 | 仅在英文输入模式下生效 |
| `## ` | H3 标题 | 同上 |
| `- ` | 无序列表 | 同上 |
| `>` | 引用块 | 同上 |
| `@` | 触发 Mention 选择器 | 前有空格或段落开头 |
| `/` | 触发块类型选择器（▼/◆/☆/▸） | 内置命令面板 |

**约束**：中文输入法预上屏期间，以上所有符号不触发 Markdown 转换或 Mention 选择器（仅在英文输入模式下生效）。

## E-1.5 KP/玩家双视图切换

编辑器顶部工具栏提供模式切换按钮：

| 模式 | 显示内容 | 用途 |
|------|---------|------|
| **编辑模式** | 所有内容，包括 KP 专属块高亮标记 | 创作和修改 |
| **KP 视角** | 所有内容，KP 信息块以虚线边框展开 | 跑团时 GM 查看 |
| **玩家视角** | 仅 `visibility !== "kp"` 的节点，KP 块折叠为细线 | 预览/导出玩家版 |

**技术实现**：
- KP 信息节点存储 `attrs: { visibility: "kp" | "all" }`（默认为 `"all"`）
- 切换视图时，直接过滤节点而不是修改原文档内容
- 导出时自动跳过 KP 信息节点，无需额外操作

## E-1.6 Mention 系统

**触发方式**：输入 `@` 弹出选择器（主），`Cmd/Ctrl + Shift + M` 备用

| 交互 | 行为 |
|------|------|
| `@` + 空格前/段落开头 | 触发 Mention 选择器 |
| `@` + 汉字前 | 不触发（避免邮箱地址等误触发） |
| 选择器无输入 | 显示最近使用的 NPC/场景/线索 |
| 选择器有输入 | 实时过滤，按名称匹配 |
| `Esc` | 关闭选择器，`@` 保留为普通文本 |
| `Enter` / `Tab` | 选中高亮项，插入 Mention 原子节点 |

**Mention 数据结构**：
```typescript
{
  type: "mention",
  attrs: {
    id: "npc_001",        // 实体库中的唯一 ID
    label: "城见美苗",     // 显示文本
    type: "npc",          // 实体类型：npc | scene | clue | skill
  }
}
```

**约束**：
- Mention 只存储 id 和 label，不存储实体完整属性。权威数据源始终在实体库。
- NPC 属性修改后，所有 Mention 显示文本自动更新。
- 第一版中跨文档复制粘贴降级为纯文本，同一模组内复制保留 Mention 链接。
- 第一版不做多人实时协同编辑，但每个自定义 Node 的 attrs 预留 `_version` 和 `_lastModified` 字段供后续 Yjs 接入。

### E-1.7.2 移动端：灵感捕获与轻量阅读器

移动端定位为桌面端的上游工序——只做内容消费和素材捕获，不做复杂结构化编辑。

| 功能 | 支持程度 | 说明 |
|------|---------|------|
| 模组阅读 | ✅ 单栏沉浸 | 打开默认进入上次离开位置，左右滑切换场景 |
| 大纲导航 | ✅ 折叠树 + 点击跳转 | 不展示完成度指示条 |
| NPC 卡片浏览 | ✅ 卡片左右滑动 | 无编辑入口，仅查看属性 |
| 线索板浏览 | ✅ 卡片浏览 + 状态切换 | 右滑标记已查看，左滑标记待处理 |
| 速记 | ✅ 核心功能 | 文字/语音/拍照，自动打上当前场景标签 |
| 撤销/重做 | ❌ 不做 | 速记进入 Inbox 后在桌面端整理采纳，移动端本身不产生结构性修改 |
| ▼ 节点/结构化块编辑 | ❌ 不做 | 小屏不适合任何形式的复杂结构化编辑 |
| 场景拖拽排序 | ❌ 不做 | 触摸拖拽易误触 |

### E-1.7.3 移动端速记系统

**四种输入方式**：

| 方式 | 触发 | 技术约束 |
|------|------|---------|
| **文字速记** | 默认入口 | 键盘弹起时文本框自动上滚，光标保持屏幕下 1/3 处；输入 `#` 触发标签选择器；输入 `@` 触发实体联想（只读，不插入链接） |
| **语音速记** | 长按录音按钮 | 最长 60 秒；离线保留音频文件，联网后转文字；识别准确率 <80% 时保留音频 + 文字双份 |
| **拍照速记** | 点击相机按钮 | 直接调用系统相机（不经过相册）；拍照后可双指缩放裁剪；可选填文字批注 |
| **位置关联** | 自动 | 每条速记自动附加当前阅读场景、时间戳、设备信息 |

**速记数据结构**：
```typescript
interface InboxItem {
  id: string;           // UUID
  type: 'text' | 'voice' | 'image';
  content: string;      // 文字内容 / 语音转文字 / 图片 URL
  raw_media?: string;   // 原始音频/图片文件（语音时保留）
  tags: string[];       // #场景 #NPC #线索 #待办 #素材
  source_scene?: string; // 速记时正在阅读的场景名
  created_at: Date;
  synced_at: Date | null;
  status: 'pending' | 'processed' | 'archived';
}
```

**离线体验**：
- 速记存入 IndexedDB，顶部横幅“⚠️ 离线模式 速记已保存至本地 联网后自动同步”
- 网络恢复后自动同步队列，显示“✓ 已同步”
- 图片速记离线时保存至本地，联网后上传云端，本地保留低分辨率缩略图

### E-1.7.4 桌面端 Inbox 流转

桌面端右侧面板新增“Inbox (N)”标签。每条速记根据类型提供不同处理操作：

| 速记类型 | 处理操作 |
|---------|---------|
| **文字速记** | [转为场景段落] 选场景 → 末尾插入 → 标记 processed；[关联到当前场景] 插入批注；[归档] |
| **语音速记** | [播放音频] 校对识别结果；[编辑文字] 修正错误；[创建 NPC 备注] 关联到具体 NPC；[归档] |
| **图片速记** | [插入到当前光标] 图片 + 占位符；[入素材库] 全局可见；[关联到场景]；[归档] |

**双向同步**：桌面端处理完速记后，移动端草稿箱对应条目显示“已在桌面端处理”标记。已归档条目 30 天后进入归档库，保留下载和搜索权限。

## E-1.8 输入行为基线

### E-1.8.1 光标与响应

| 细节点 | 预期行为 |
|--------|---------|
| 光标闪烁 | 停止输入后 530ms 间隔稳定闪烁，输入时光标暂停闪烁 |
| 拼音预上屏 | 拼音字母出现在光标位置，确认后替换为汉字，期间不触发任何快捷键或 Markdown 转换 |
| 移动端键盘 | 键盘弹起时编辑区自动上移，光标始终在可视区域内（屏幕下 1/3 处最佳） |
| 标点配对 | 全角 `「`、`（`、`"` 自动补全右半；Delete 键删除左半时，若右半紧邻且未修改则同时删除 |
| 撤销/重做 | 以用户可感知的操作为单位（不是每个字符），被撤销内容有 0.3s 浅黄色背景闪烁 |

### E-1.8.2 快捷键体系

| 快捷键 | 功能 |
|--------|------|
| `Cmd/Ctrl + K` | 命令面板（跳转场景/NPC/线索） |
| `Cmd/Ctrl + 1/2/3` | 切换左侧面板（大纲/NPC 库/线索板） |
| `Cmd/Ctrl + Shift + N` | 新建 NPC 并插入当前光标位置 |
| `Cmd/Ctrl + Shift + L` | 新建线索 |
| `Cmd/Ctrl + .` | 标记当前行为 KP 信息（☆） |
| `Cmd/Ctrl + Shift + M` | 触发 Mention 选择器 |
| `Tab / Shift + Tab` | ▼ 节点内缩进/反缩进 |

### E-1.8.3 Markdown 快捷输入

输入 `# `、`- `、`>` 后自动转为对应块类型（仅在英文输入模式下生效，中文输入时禁用）。

## E-1.9 协作与架构基线

**第一版 MVP**：不做多人实时协同编辑。但文档模型预留字段供后续接入。

**多端同步**：编辑器间通过操作流同步（与平台聊天系统相同的 Socket.IO 机制），不是文件覆盖模式。每个编辑操作是一个不可变事件，追加到文档操作流中。具体参见 [《附录 A00-3：编辑器多端同步策略》](./附录%20A00-3：编辑器多端同步策略.md)。

**数据完整性**：所有编辑操作遵循“永不覆盖”原则。保存操作是追加操作流而不是覆盖旧版本。具体参见 [《附录 A00：非破坏性操作与数据完整性声明》](./附录%20A00：非破坏性操作与数据完整性声明.md)。

## E-1.10 第一版 MVP 边界

### 必须实现（P0 核心体验）

流式文本编辑、原子块结构化（▼/◆/☆）、Mention（@NPC/场景/线索，只存 entityId+label）、KP/玩家视图切换、大纲面板（场景树）、快捷键体系、Markdown 快捷输入。

### 应该在 MVP 中（P1 增强）

浮动面板系统、移动端速记 + PWA、桌面端 Inbox、导出 PDF/文本。

### 第一版明确不做

多人实时协同编辑、跨文档 Mention 粘贴、JSON 序列化压缩、移动端结构化编辑、规则计算引擎。
