## 1. 订单状态机

```
                    ┌──────────────────────────────────────────────┐
                    │                                              │
               创建订单                                            │
                    │                                              │
                    ▼                                              │
              ┌─────────┐  用户取消 / 超时  ┌────────┐            │
              │ pending │────────────────►  │ failed │            │
              └────┬────┘                   └────────┘            │
                   │                                              │
                   │ webhook paid                                 │
                   ▼                                              │
              ┌─────────┐  退款申请通过      ┌──────────┐         │
              │  paid   │────────────────►  │ refunded │─────────┘
              └─────────┘                   └──────────┘
```

| 状态 | 含义 | 允许转换 |
|------|------|----------|
| `pending` | 待支付 | → `paid`（回调）→ `failed`（取消/超时） |
| `paid` | 已支付 | → `refunded`（退款，Phase 2）|
| `failed` | 已失败/已取消 | 终态 |
| `refunded` | 已退款 | 终态（Phase 2 实现）|

## 2. 回调幂等策略

**幂等键**：`payment_orders.external_order_id`（三方流水号 `transaction_id`）

```
回调到达
   │
   ├─► 查订单（order_id）
   │      │
   │      ├─ 订单不存在 → 404
   │      ├─ 订单已取消 → 400
   │      └─ 订单存在 ──►──────────────────────────────────────────┐
   │                                                               │
   │      ┌────────────────────────────────────────────────────────┘
   │      │
   │      ├─ status=paid && external_order_id == transaction_id
   │      │     → 幂等跳过，写 idempotent_skip 审计日志 → 200 OK
   │      │
   │      └─ status=pending（未处理）
   │             └─► 开事务：
   │                   1. UPDATE payment_orders SET status=paid
   │                   2. grantBenefits()（按 product_type 分发）
   │                   3. INSERT payment_audit_log (grant_success)
   │                 提交事务 → 200 OK
   │
   └─► 事务异常 → 回滚 → 在事务外写 grant_failed 审计 → 500
```

## 3. 到账-发放一致性方案

所有权益发放操作（`grantBenefits`）与订单状态更新在**同一 DB 事务**内执行：

```ts
await db.transaction(async (trx) => {
  // 1. 更新订单状态
  await trx('payment_orders').where({ id: orderId }).update({ status: 'paid', ... });

  // 2. 发放权益（按 product_type）
  await grantBenefits(trx, order);

  // 3. 写审计日志
  await trx('payment_audit_log').insert({ event_type: 'grant_success', ... });
});
```

**防重复发权益**：`content_access_grants` 表有联合唯一约束 `(user_id, content_type, content_id)`，使用 `.onConflict().ignore()` 保证即使事务重试也不会重复插入。

## 4. 异常补偿流程

```
Level 1：自动重试（三方渠道侧）
  支付渠道在回调失败（5xx）后按指数退避重试，最多 5 次
  每次到达均触发完整幂等校验

Level 2：主动查单（平台侧补偿，Phase 2 工程化）
  cron 任务：每小时扫描 status=pending 且 created_at < now-2h 的订单
  主动调用三方查单接口，拉取实际支付状态
  若查单结果=paid → 调用 paymentService.handleCallback() 补单
  若查单结果=failed → 更新订单状态

Level 3：手工补单（运营侧）
  POST /api/payments/admin/manual-grant { order_id }
  要求 admin 权限，写 manual_grant 审计日志（含 operator_id）
  适用场景：查单也失败、用户提工单申诉
```

## 5. 错误码规范

| 错误码 | HTTP | 含义 | 处理建议 |
|--------|------|------|----------|
| `ORDER_NOT_FOUND` | 404 | 订单不存在 | 检查 order_id 是否正确 |
| `ORDER_ALREADY_CANCELLED` | 400 | 订单已取消 | 用户需重新下单 |
| `UNSUPPORTED_PRODUCT_TYPE` | 400 | 不支持的商品类型 | 检查 product_type 枚举 |
| `RATE_LIMIT_EXCEEDED` | 429 | 请求频率超限 | 客户端指数退避，检查 RateLimit-Reset 响应头 |
| `AI_QUOTA_EXCEEDED` | 429 | AI 配额超限 | 等到下月重置或升级会员 |
| `AI_FEATURE_LOCKED` | 403 | 会员等级不足 | 引导升级页 |
| （无错误码）| 500 | 服务器内部错误 | 渠道方重试，平台记录 grant_failed 事件 |

## 6. 关键监控点位

| 指标 | 采集方式 | 告警阈值 |
|------|----------|----------|
| `payment_callback` 5分钟计数 | `GET /api/metrics/business` → `window_5m.payment_callback` | < 预期流量 50% 告警（支付渠道异常） |
| `grant_failed` 5分钟计数 | 同上 | > 5 次/5min 触发回滚 |
| `payment_orders` pending 超 2h | DB 查询 | > 10 条告警（查单任务异常）|
| webhook 响应时间 P99 | request-logger 慢日志 | > 1000ms 告警 |

## 7. 生产上线前必改项

1. **签名验证**：`POST /api/payments/webhook/:channel` 中的 HMAC 验证目前仅在 `PAYMENT_WEBHOOK_SECRET_*` 环境变量存在时生效，生产上线前必须注入此变量。  
2. **微信/支付宝正式签名**：替换为真实渠道的 RSA/MD5 签名方案（非 HMAC）。  
3. **查单补偿 cron**：Level 2 主动查单尚未实现，正式上线前须补充。  
4. **退款流程**：`status=refunded` 转换逻辑尚未实现。  
5. **分布式锁**：对账扫描脚本运行时需加 Redis 分布式锁，防多实例重复补单。
