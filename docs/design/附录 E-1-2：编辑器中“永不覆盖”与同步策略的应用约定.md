## E-1-2.1 数据完整性：确认平台级约束

《附录 A00》中定义的“永不覆盖”原则，在模组编辑器中具体表现为：

1. **保存 = 追加操作事件**，不是覆盖文档快照
2. **编辑操作的粒度**是一个段落 / 一个 Markdown 块的修改，不是整个文档
3. **操作流是权威数据源**，当前文档状态是所有操作重放的结果
4. **本地草稿清除时机**：仅在收到服务端确认（含版本号或 op_id 确认）后

---

## E-1-2.2 多端同步：确认技术方案

模组编辑器采用与平台聊天系统相同的 Socket.IO 操作流同步机制，不采用“文件保存/覆盖”模式。

具体事件定义、离线处理策略、冲突保留规则见《附录 A00-3》。

**适用范围**：
- 模组正文编辑器
- GM 共用笔记
- 团内文档库 / 后日谈空间
- 故事录编辑器
- 角色卡编辑器

---

## E-1-2.3 冲突时的 HO 信息保留

当编辑器操作流同步与 HO 权限矩阵的状态变更同时发生时（例如：KP 正在修改某条隐 HO 的解锁条件，同时该 HO 被玩家推理确认）：

1. 两个操作都是独立事件，按时间戳追加，不互相覆盖
2. 如果导致权限冲突（HO 已解锁但解锁条件同时被修改为更严格），矩阵面板显示 ⚠ 冲突警告，KP 手动载决
3. 任何冲突处理都不静默丢弃数据——双方内容都保留，后续可通过“操作日志”回滚

**KP 载决界面**（冲突警告）：

```
⚠ 同步冲突：HO-C-02 解锁条件变更 vs. 玩家F 推理确认请求
─────────────────────────────────────────────────────
[操作 A]（23:14:52）KP 修改解锁条件 → “需完整度 ≥ 80%”
[操作 B]（23:14:53）玩家F 申请确认（当前完整度 52%）

载决选项：
  [以操作A为准，拒绝确认]  [以操作B为准，允许确认]  [保留双方，稍后载决]
─────────────────────────────────────────────────────
```

## E-1-2.4 移动端速记与桌面端 Inbox 的数据保护

移动端速记遵循同样的“永不覆盖”原则：

- 离线速记先写入 IndexedDB，联网后追加至服务端
- 桌面端 Inbox “处理”一条速记 = 追加一条 `note_process` 事件，速记原始数据不被删除
- 已归档速记永久保留，可搜索

**禁止行为**：
- 移动端“处理”操作直接删除 IndexedDB 中的速记原始数据
- 服务端在归档时物理删除记录（只允许标记 `status: 'archived'`）
