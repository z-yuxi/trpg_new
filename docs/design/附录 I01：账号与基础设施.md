## I01.2 账号与身份系统

### I01.2.1 设计原则

- 极简优先：手机号 + 验证码完成注册登录，密码为后续备用能力。
- 渐进式收集：手机号为唯一强制字段，昵称、头像、身份标签后置补完。
- 最小权限：身份标签用于推荐和展示，功能权限以业务角色和后台中间件为准。
- 安全优先：Access Token 1 小时，Refresh Token 7 天，采用滑动续期与吊销机制。

### I01.2.2 注册与登录流程

| 步骤 | 操作 | 后端行为 | 前端行为 |
| --- | --- | --- | --- |
| 1 | 输入手机号，点击获取验证码 | 校验格式与频率限制，生成 6 位验证码并写入 Redis，TTL 5 分钟 | 展示 60 秒倒计时 |
| 2 | 输入验证码，点击登录/注册 | 校验验证码有效性，查询手机号是否已存在 | 登录按钮禁用并展示 loading |
| 3（新用户） | 自动创建账号 | 生成 UUID 主键、7 位 UID、临时昵称，签发 Access/Refresh Token | 跳转完善资料或首页 |
| 3（老用户） | 直接登录 | 签发新 Token，更新最后登录时间 | 跳转首页或回跳来源页 |

### I01.2.3 验证码安全策略

| 限制项 | 值 | 说明 |
| --- | --- | --- |
| 同一手机号 | 1 次/60 秒，5 次/天 | 防止短信轰炸 |
| 同一 IP | 10 次/小时，50 次/天 | 防止恶意请求 |
| 验证码有效期 | 5 分钟 | 一次性使用 |
| 错误次数限制 | 连续 5 次错误锁定 15 分钟 | 防爆破 |
| 短信模板 | 【TRPG平台】您的验证码是：123456，5分钟内有效。请勿泄露。 | 标准模板 |

### I01.2.4 临时昵称与身份标签

- 临时昵称格式固定为 叙事者_ + 4 位数字。
- 禁止用户自定义与临时昵称格式完全相同的名称，避免伪装。
- identity_tags 仅用于展示与推荐，允许值为 player、gm、creator。
- creator 标签不等于创作者权限；创作者实际权限判定见附录 H01 与附录 A03。

### I01.2.5 登录态管理

| 令牌 | 类型 | 有效期 | 存储位置 | 续期规则 |
| --- | --- | --- | --- | --- |
| Access Token | JWT | 1 小时 | HttpOnly Cookie | 过期后通过 Refresh Token 刷新 |
| Refresh Token | 随机字符串 | 7 天 | HttpOnly Cookie | 每次刷新时轮换并立即吊销旧 Token |

刷新接口固定行为：

1. 校验旧 Refresh Token 未过期、未吊销。
2. 生成新 Access Token 与新 Refresh Token。
3. 将旧 Refresh Token 标记 revoked。
4. 返回新 Access Token，并通过 Set-Cookie 下发新 Refresh Token。

### I01.2.6 密码备用登录

- MVP 不默认开放密码注册登录。
- 用户可在后续版本于账号安全中主动设置密码。
- 密码采用 bcrypt 哈希存储，强度 10。
- 忘记密码只能通过手机号验证码重置。

## I01.3 管理员账号与后台访问控制

### I01.3.1 管理员创建方式

- 管理员账号不走普通手机号验证码注册流程。
- 由平台运维直接写入 users 表。
- uid 固定使用保留号段 1000000-1000099。
- user_type 必须包含 admin。
- 管理员账号必须配置 password_hash，不支持纯验证码登录后台。

**保留号段细化分配**：

| 号段范围 | 用途 | 备注 |
|---------|------|----- |
| 1000000–1000009 | 超级管理员账号 | 平台运维直接写入 |
| 1000010–1000094 | 预留（测试账号、运营账号等） | 按需分配 |
| 1000095–1000099 | AI 机器人账号 | `is_bot=TRUE`，前台强制展示「机器人」标签 |

**机器人账号（1000095–1000099）识别规则**：

| UID | 昵称 | 人设 |
|-----|------|------|
| 1000095 | 叙言者 | COC 解谜爱好者（偏硬核） |
| 1000096 | 帷幕之后 | 叙事型 GM（带团经验丰富） |
| 1000097 | 墨菲斯 | 规则研究者（严谨文风） |
| 1000098 | 夜骐 | 新手友好、活跃气氛 |
| 1000099 | 旅人说书人 | 故事录常驻作者（文笔好） |

- 前台昵称旁强制叠加「机器人」标签，头像右下角叠加机器人小图标。
- 该标识不可隐藏、不可修改，由系统通过 `is_bot=TRUE` 字段强制渲染。
- 机器人账号生成的所有内容自动标记 `is_bot_generated=TRUE`，便于清理和数据统计。

### I01.3.2 后台访问双层保护

1. 业务权限层：后端 requireAdmin 校验 user_type 包含 admin。
2. 网络层：同时校验请求 IP 位于 WireGuard 内网白名单。
3. 任一条件不满足，统一返回 HTTP 403 Forbidden。
4. 管理员可以作为普通玩家使用平台，但进入后台仍必须满足内网限制。

### I01.3.3 创作者与管理员权限闭环

- 创作者权限判定：subscription_type === 'creator' 或 user_type 含 creator/admin。
- /creator/** 路由需设置 requiresCreator: true。
- /admin/** 路由仅允许 requireAdmin 中间件通过后访问。
- 结构化错误码统一使用 FORBIDDEN。

## I01.4 基础表结构与审计

### I01.4.1 核心表

```sql
CREATE TABLE users (
  id VARCHAR(64) PRIMARY KEY,
  uid INT UNSIGNED NOT NULL UNIQUE,
  phone VARCHAR(20) NOT NULL UNIQUE,
  nickname VARCHAR(64) NOT NULL,
  avatar_url VARCHAR(255),
  identity_tags JSON,
  user_type JSON,
  has_password BOOLEAN DEFAULT FALSE,
  password_hash VARCHAR(255),
  status ENUM('active', 'banned') DEFAULT 'active',
  last_login_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE refresh_tokens (
  id VARCHAR(64) PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  token_hash VARCHAR(255) NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  revoked BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_token_hash (token_hash),
  INDEX idx_user_revoked (user_id, revoked)
);

CREATE TABLE login_logs (
  id VARCHAR(64) PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  ip VARCHAR(45) NOT NULL,
  user_agent VARCHAR(255),
  device_fingerprint VARCHAR(64),
  login_result ENUM('success', 'failure') DEFAULT 'success',
  failure_reason VARCHAR(64),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_time (user_id, created_at)
);
```

### I01.4.2 验证码存储

- 主存储：Redis，key = sms:{phone}，TTL = 300 秒。
- 审计需要时，可异步写入 sms_codes 表。
- 落库不是 MVP 强制要求，但频率限制与日志必须保留。

## I01.5 部署与基础设施

### I01.5.1 基线配置

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| 服务器 | 轻量应用服务器 | 初期支撑 100-200 并发 |
| CPU | 2 核 | Socket.IO 单线程为主 |
| 内存 | 2GB | 满足 MVP |
| 存储 | 40GB SSD | 系统、应用与数据初期容量 |
| 带宽 | 200Mbps 峰值 | 不限流量 |
| 域名 | conxu.cn | 国内备案 |

### I01.5.2 容器化与供应链安全

- 基础镜像：node:20-alpine。
- 构建阶段：npm ci --ignore-scripts。
- 运行阶段：非 root 用户、只读根文件系统。
- 镜像扫描：Trivy，高危漏洞阻断发布。
- 配置通过环境变量注入，不硬编码密钥。

### I01.5.3 备份与日志

- 数据库每日自动备份，保留 30 天。
- 房间日志按冷热分层：3 个月热数据在 MySQL，历史压缩归档至 OSS。
- 登录日志、后台操作日志、审计日志按合规要求保留。
