# 附录 02-1：AI 辅助开发流程 (AI-Assisted Dev Workflow)

> **版本**: V1.0
> **前置阅读**: [附录 02：给 AI 的上下文规范文档](./附录%2002：给%20AI%20的上下文规范文档.md)
> **核心价值**: 解决当前 AI 无法独立完成复杂、跨模块任务的问题。通过“原子化”拆分，将 AI 的输出从“不可控的代码块”变为“可信赖的、可组装的构件”。

## 1. 方法论：从“写功能”到“组装原子任务”

我们不直接给 AI “实现招募功能”这种易产生幻觉的指令。而是由架构师将其拆解为一系列上下文单一、输入/输出明确的**原子任务**。AI 只负责其中“代码生成”的环节。

## 2. 原子任务定义标准

一个合格的原子任务必须包含：
- **任务 ID**: `TASK-APPLY-BUTTON-LOGIC`
- **授权上下文**: 精确到段落的文档引用列表。
- **明确输入**: TypeScript 类型定义或接口描述。
- **明确输出**: 一个单一、可运行的文件路径。
- **可验证的验收标准**: 一份可用于 Code Review 或自动化测试的清单。

## 3. 任务拆解与组装范例 (以招募帖申请功能为例)

我们不直接实现功能，而是执行一条任务流水线：

| 步骤 | 原子任务 ID | 任务目标 | AI 的输入 | AI 的输出 | 验收标准 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. 逻辑** | `TASK-APPLY-BUTTON-LOGIC` | 封装状态机逻辑 | `附录 00 状态机表`、`附录 02 状态规则` | `useApplyButtonState.ts` | 逻辑完全由配置表驱动，无 `if-else`。 |
| **2. 组件** | `TASK-APPLY-BUTTON-COMPONENT` | 实现 UI 组件 | `设计令牌 A02`、上一步的输出 | `RecruitCard.vue` | 样式使用令牌变量，状态调用 Composable。 |
| **3. 异常** | `TASK-APPLY-BUTTON-ERRORS` | 处理错误与文案 | `工程约定 A03-1`、`附录 G01 文案` | `error-handler` 补丁 | 所有错误码均有用户提示。 |

**组装方式**: 由开发者在 `RecruitCard.vue` 中引入 `useApplyButtonState`，传入响应式上下文即可。

## 4. 实施要求

- 任何新的复杂功能开发，必须先由架构师输出一份**原子任务清单**（如本文档第3节表格），存入 `docs/tasks/` 目录。
- AI 和开发者的协作严格围绕原子任务展开：AI 生成代码，开发者负责集成、后端改动和最终审核。
