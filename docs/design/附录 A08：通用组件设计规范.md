# 附录 A08：通用组件设计规范 (Composable/Component Spec)

> **版本**: V1.0
> **核心权威来源**: [附录 00：状态行为映射表](./附录%2000：状态行为映射表.md), [附录 02：给 AI 的上下文规范文档](./附录%2002：给%20AI%20的上下文规范文档.md)
> **目标**: 将复杂的状态机转化为封装好的 Vue 3 Composable/Component，作为平台唯一实现。

## 1. 核心原则：配置驱动

所有涉及多状态切换的交互，如按钮、流程等，**必须在`composables/`目录下封装成专用函数**。`.vue` 组件只负责消费它们返回的响应式状态，严禁在模板或组件逻辑中手写 `if-else` 判定。

## 2. 关键状态机实现模式

### 2.1 申请加入按钮状态机
**权威规则**: 详见 [附录 02 (3.1)](./附录%2002：给%20AI%20的上下文规范文档.md) 及 [附录 00 (状态机表)](./附录%2000：状态行为映射表.md)。

**要求**: 必须提供 `composables/useApplyButtonState.ts`，其内部逻辑采用**配置表驱动**，将“状态-行为”的映射文档直接转化为代码字典。

**实现模板**:
```typescript
// composables/useApplyButtonState.ts
export function useApplyButtonState(context: Ref<ButtonContext>) {
  // RULES 配置表是整个函数的灵魂，它直接映射产品文档中的状态规则
  const RULES: Record<string, (ctx: ButtonContext) => ButtonState> = {
    notLogin: () => ({ text: '申请加入', disabled: false, action: 'showLogin' }),
    confirmed: () => ({ text: '已加入', disabled: true, action: null }),
    invited: () => ({ text: '确认入团', disabled: false, action: 'confirm' }),
    // ... 其他状态均在此配置
  };

  const buttonState = computed(() => {
    const ctx = context.value;
    if (!ctx.isLoggedIn) return RULES.notLogin(ctx);
    // 通过组合身份和业务状态，在 RULES 中查找对应行为
    const ruleKey = getRuleKey(ctx); 
    return (RULES[ruleKey] || RULES.default)(ctx);
  });
  return { buttonState };
}
