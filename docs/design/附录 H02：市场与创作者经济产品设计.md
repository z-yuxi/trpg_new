## 5. 市场与创作者经济

_市场是连接创作者与消费者的核心枢纽，涵盖规则模板、模组、组件的交易以及创作者的运营管理工具。_

### 5.0 与会员身份的交叉口径

1. 创作者经营身份的权限入口由 `user_type` 与审核状态控制，订阅权益等级由附录 H01 的 `subscription_type` 控制。
2. 免费版与专业版创作者默认平台抽成 20%，创作者版抽成 0%，不得在本附录另起一套费率定义。
3. 市场页面若展示“创作者版专享”“会员折扣”“AI 配额加成”等信息，必须回指附录 H01 或附录 H04，不在本附录重复定义完整细则。

### 5.2 探索/我的资产（两层结构 + 状态标签优化）

**页面结构**：

1. 一级入口归属：探索（模组集/规则包）与我的（资产管理）分离。
2. 探索内承接发现流；我的内承接已获取资产与个人管理流。

#### 4.2.1 发现（原"浏览"）
- **二级Tab**：模组集市 / 规则集市
- **模组集市**：
  - 三级Tab：推荐、新上、**公示**、关注
  - 筛选栏：规则、题材、难度、人数、风格、排序
  - 卡片网格（4列），**每个卡片增加状态标签**：
    - **未拥有**：按价格单义处理：`price = 0` 显示 `[免费获取]`；`price > 0` 显示 `[购买]`。
    - **已拥有**：显示绿色标签"已在库中"，操作按钮 `[开团]`
  - 公示期卡片：显示倒计时 + `[提出异议]` 按钮
- **规则集市**：类似结构，卡片显示规则包名称、作者、类型、价格；已拥有显示"已在库中"

#### 4.2.2 我的
- **二级Tab**：模组 / 规则 / 角色卡 / 我创作的（仅创作者可见）
- 展示用户已购买、收藏、自创的内容
- 每个资产卡片操作：`[开团]`（已拥有资产）、`[编辑]`（自创草稿）、`[删除]`等

> **边界澄清**：用户购买模组后，在「探索」中该卡片会变为“已在库中”状态，点击 `[开团]` 可直接使用；在「我的-资产」中同样可见该模组，作为永久资产列表。

### 5.3 创作者后台（新增完整章节）

> **⚠️ 关键约束**：创作者后台是独立页面组，必须通过左侧导航栏的"创作者后台"入口进入，**不在底部 5 个主导航中**。  
> **页面框架**：所有创作者后台页面严格复用 `PageLayout` 容器（见第 2 章），禁止手写独立布局。

- 统一的 `PageLayout` 容器


### 5.4 作品评价系统

#### 核心理念

评价系统旨在收集和展示作品的使用反馈，帮助创作者改进，引导社区发掘优质内容。它服务于创作者和社区，而非交易仲裁。

#### 评价资格

- **免费作品**：任何已“获取”该作品的用户。
- **付费作品**：任何已“购买”或“获取”该作品的用户。

评价资格与金钱脱钩，与“拥有/使用”挂钩。

#### 评价内容

- **评分**：1-5 星（**可选填**，不强制）。
- **文字**：**必填**，10-500 字。纯评分无文字的评价不被接受。

#### 修改与删除

- **修改**：✅ 允许。修改后显示“该评价已于 YYYY-MM-DD 编辑”。
- **删除**：✅ 允许。用户可随时删除自己的评价。

**设计理由**：用户对作品的理解可能随着时间的推移而改变（如作者更新了模组、用户重玩后发现新的亮点）。允许修改和删除，是对创作者和用户之间流动关系的尊重，不把评价固化为“永久的判决”。

#### 展示规则

- 评价列表在作品叙阅器页展示。
- 默认按**时间倒序**排列（最新评价在前）。
- 创作者可**置顶一条优质长评**（≥200 字），始终显示在评价列表首位，替代“作者回复”功能。
- 平均评分在作品卡片和作品叙阅器页展示。

#### 社区激励（V1.5）

被创作者置顶或获得 ≥10 赞的评价，可获得社区积分奖励（见附录 H03 积分规则）。

#### 数据结构（在 `reviews` 表上扩展）

```sql
ALTER TABLE reviews ADD COLUMN review_type ENUM('campaign','product') DEFAULT 'campaign';
ALTER TABLE reviews ADD COLUMN product_id VARCHAR(64) NULL COMMENT '商品ID（review_type=product时必填）';
ALTER TABLE reviews ADD COLUMN is_edited BOOLEAN DEFAULT FALSE COMMENT '是否被编辑过';
ALTER TABLE reviews ADD COLUMN edited_at TIMESTAMP NULL COMMENT '最后编辑时间';
ALTER TABLE reviews ADD COLUMN is_pinned BOOLEAN DEFAULT FALSE COMMENT '创作者置顶';
```

### 5.5 作品收藏

> **设计参考**：Steam 心愿单，让用户在不获取/购买的前提下表达兴趣，降低决策门槛，同时为创作者提供前置兴趣信号。

#### 核心理念

用户在浏览模组/规则包时，如果感兴趣但暂时不想获取（如等玩家凑齐、等正式版发布、等打折），可将其加入收藏列表。收藏是比“获取”更轻量的兴趣表达。

#### 交互入口

模组/规则包叙阅器页的操作按钮区：

| 用户状态 | 主按钮 | 次按钮 |
|:---|:---|:---|
| 未获取 + 未收藏 | [获取] / [购买]（品牌色） | [收藏]（幽灵按钮，书签图标） |
| 未获取 + 已收藏 | [获取] / [购买]（品牌色） | [已收藏]（填充书签图标，点击取消收藏） |
| 已获取 | [已拥有] + [开团] | - |

#### 收藏列表

用户可在「我的」→收藏 中查看和管理自己的收藏列表。列表按收藏时间倒序排列，支持取消收藏。

#### 通知触发

| 事件 | 通知内容 | 渠道 | 实现版本 |
|:---|:---|:---|:---|
| 收藏的作品**正式发布**（从公示/草稿变为已发布） | “你收藏的模组「XXX」已正式发布” | 站内通知 | V1.0 |
| 收藏的作品**更新版本** | “你收藏的模组「XXX」已更新至 V2.0” | 站内通知 | V1.0 |
| 收藏的付费作品**打折** | “你收藏的模组「XXX」正在限时折扣” | 站内通知 + 可选邮件 | V1.5 |

#### 对创作者的价值

在创作者后台的“我的作品”数据面板中，增加以下统计：

| 指标 | 说明 |
|:---|:---|
| **收藏数** | 有多少用户收藏了该作品 |
| 获取数 | 已获取/购买的用户数 |
| 评价数 | 已提交评价的用户数 |

收藏数是比获取更前置、更轻量的兴趣信号。它帮助创作者在作品尚未被大量获取时，就能感知到社区关注度。

#### 与评价系统的联动

```plain
收藏 → 获取/购买 → 体验 → 评价
  │                    │
  └────────────────────┴── 两者均为作品发现的信号
```

用户获取作品后，系统可在首次获取后第 7 天推送一条提醒：“你对「XXX」的使用体验如何？可以写一条评价帮助其他玩家。”用户可关闭此类提醒。

#### 数据结构

```sql
CREATE TABLE product_collections (
  id VARCHAR(64) PRIMARY KEY,
  user_id VARCHAR(64) NOT NULL,
  product_id VARCHAR(64) NOT NULL,
  product_type ENUM('module', 'ruleset') NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_product (user_id, product_id)
);
```


### 5.6 创作者后台移动端布局基线

创作者后台（仪表盘、素材库、我的作品、规则工坊）移动端必须复用 PageLayout 框架，不允许页面各自实现。

| 桌面端（已重组） | 移动端规范 | 说明 |
|---|---|---|
| PageLayout（Header + Stats + FilterBar + Content） | 垂直堆叠：Header（吸顶）→ Stats → FilterBar → Content | 统一信息层级，避免页面分裂 |
| Stats 4 列网格 | 2 列 x 2 行卡片网格 | 卡片高度一致，数字优先 |
| FilterBar 与内容并排 | FilterBar 位于 Stats 下方，横向滑动 + 抽屉二级筛选 | 首屏只保留高频筛选项 |
| 内容区卡片网格 | 默认单列；仅当视口宽度 >= 390px 且卡片最小宽度 >= 168px 时切换双列 | 卡片标题、状态、更新时间三段式 |
| 主操作按钮 | 按 1.1.1 规则自动选择 Header 右上角或 FAB，不下沉到底栏 | 保持与桌面端入口语义一致 |
