## 一、服务架构概览

```
客户端（Vue3）
    │  HTTP REST / WebSocket
    ▼
Nginx（灰度路由，X-Canary: 1 → server-canary:3001）
    │
    ├── /api/*  → server:3000（Express）
    │              ├── MySQL（主存储）
    │              └── Redis（Session / 幂等缓存 / 限流计数）
    └── /socket.io/* → server:3000
```

## 三、数据库迁移操作

### 正向迁移（上线时执行）
```bash
cd packages/server
pnpm tsx src/db/migrate.ts
# 或通过 npm script：
pnpm migrate
```

### 回滚迁移（紧急回退时）
```bash
pnpm tsx src/db/migrate-rollback.ts
# 回滚一个 batch
```

```bash
pnpm tsx src/scripts/migrate-rollback-test.ts
```

## 四、定时任务（Cron Jobs）

| 任务                            | 调度表达式  | 说明                              |
|--------------------------------|------------|----------------------------------|
| `moduleService.hourlyTask()`   | `0 * * * *`| 每小时模组相关定时任务             |
| `recruitmentService.expireInvites()` | `*/5 * * * *` | 每5分钟扫描并过期邀请       |

**监控要点**：
- `expireInvites` 执行时间不应超过 5 秒（正常 < 500ms）
- 若 Redis 不可用，cron 继续执行（仅影响幂等缓存，不影响 DB 操作）

## 五、健康检查

```bash
# 检查服务状态
curl http://localhost:3000/api/health

# 期望返回（全部健康）
{
  "status": "ok",
  "uptime": 3600,
  "version": "1.0.0",
  "checks": { "db": "ok", "redis": "ok" }
}

# 异常返回（任一组件故障）
# HTTP 503 + "status": "degraded"
```

**告警阈值**：
- 连续 3 次 `/api/health` 返回 503 → 触发页面告警
- `checks.db === "error"` → 立即升级处理（核心服务不可用）
- `checks.redis === "error"` → 中等优先级（限流/幂等降级，业务仍可运行）

## 六、日志规范

### 请求日志（request-logger）
- 正常 2xx（慢于 2 秒）→ INFO + `[SLOW]` 标记
- 4xx → WARN（始终打印）
- 5xx → ERROR（始终打印）
- `/api/health` 跳过（避免监控探针刷日志）

### 审计日志（audit-log）
- 格式：JSON，字段 `event: "audit"`, `action`, `userId`, `ip`（脱敏）, `statusCode`
- 覆盖操作：登录/注册/申请/审批/确认/成团/解散
- **IP 脱敏规则**：IPv4 保留前两段（如 `192.168.x.x`）
- **禁止在日志中出现**：密码、手机号完整内容、JWT 完整 token

### 日志采集建议
```yaml
# docker-compose 中挂载日志目录
volumes:
  - ./logs:/app/logs
# 或使用 Loki / ELK 采集 stdout JSON 日志
```

## 七、灰度发布操作流程

### 启动灰度实例
```bash
# 构建新版本镜像（打 canary 标签）
docker build -t trpg-server:canary .

# 启动灰度实例（不影响 server:stable）
docker compose --profile canary up -d server-canary

# 验证灰度实例健康
curl http://localhost:3001/api/health
```

### 切流验证
```bash
# 使用 X-Canary: 1 请求头路由到灰度实例
curl -H "X-Canary: 1" http://localhost/api/health

# 观察日志
docker logs -f trpg_new-server-canary-1
```

### 全量上线
```bash
# 确认灰度无问题后，更新 server 镜像
docker compose up -d --no-deps server
# 停止灰度实例
docker compose --profile canary stop server-canary
```

### 快速回滚
```bash
# 方法一：回滚镜像（立即生效）
docker compose up -d --no-deps server  # 使用上一个标签的镜像

# 方法二：数据库回滚（配合镜像回滚）
cd packages/server
pnpm tsx src/db/migrate-rollback.ts    # 回滚最新 batch
```

## 八、常见故障排查

### 故障：招募帖无法发布（400 Bad Request）
1. 检查帖子状态是否为 `draft`
2. 检查请求用户是否为帖主（403 排查）
3. 检查 DB 迁移是否最新（`021_recruitment_state_machine` 已执行）

### 故障：玩家确认入团失败（`RECRUITMENT_INVITE_EXPIRED`）
- 原因：`invited_expires_at` 已过（默认 24 小时）
- 处理：GM 可重新审批申请，重置邀请倒计时

### 故障：幂等键缓存未生效（重复操作产生重复数据）
1. 检查 Redis 连接：`docker exec -it trpg_redis redis-cli -a $REDIS_PASSWORD ping`
2. 检查 key 是否存在：`keys idempotency:*`
3. 若 Redis 不可用，幂等中间件会降级（让请求直通），DB 唯一约束兜底

### 故障：cron 邀请过期任务不执行
1. 检查 `server.ts` 是否有 `expireInvites` 注册
2. 检查 MySQL 时区设置（需与服务器时区一致）
3. 手动触发测试：`curl -X POST http://localhost:3000/api/internal/expire-invites`（若有管理路由）
