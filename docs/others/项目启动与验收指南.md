## 1. 系统环境准备

在首次启动项目前，需要在 Ubuntu 系统上安装以下 5 个软件。请按顺序执行。

---

### 1.1 Node.js 20.x

**推荐方式：使用 NodeSource 仓库安装**

```bash
# 添加 NodeSource 官方仓库
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -

# 安装 Node.js
sudo apt-get install -y nodejs
```

**备选方式：使用 nvm（Node 版本管理器）**

```bash
# 安装 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 重新加载终端配置
source ~/.bashrc

# 安装并启用 Node.js 20
nvm install 20
nvm use 20
```

**验证命令：**

```bash
node -v
```

预期输出示例：`v20.x.x`（版本号以 20 开头即可）

```bash
npm -v
```

预期输出示例：`10.x.x`

---

### 1.2 pnpm（包管理器）

```bash
npm install -g pnpm
```

**验证命令：**

```bash
pnpm -v
```

预期输出示例：`9.x.x` 或 `10.x.x`

> 如果提示 `pnpm: command not found`，请关闭终端重新打开后再试。

---

### 1.3 MySQL 8.0

**方式一：APT 仓库安装（推荐，数据持久化）**

```bash
# 更新包列表
sudo apt update

# 安装 MySQL Server
sudo apt install -y mysql-server

# 启动 MySQL 服务
sudo systemctl start mysql
sudo systemctl enable mysql

# 创建项目用到的数据库和用户
sudo mysql -u root <<EOF
CREATE DATABASE IF NOT EXISTS trpg_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'trpg'@'localhost' IDENTIFIED BY 'trpg_password';
GRANT ALL PRIVILEGES ON trpg_platform.* TO 'trpg'@'localhost';
FLUSH PRIVILEGES;
EOF
```

**方式二：Docker 运行（开发测试用，无需安装 MySQL）**

```bash
# 需要先安装 Docker：sudo apt install -y docker.io
docker run -d \
  --name trpg-mysql \
  -e MYSQL_ROOT_PASSWORD=root_password \
  -e MYSQL_DATABASE=trpg_platform \
  -e MYSQL_USER=trpg \
  -e MYSQL_PASSWORD=trpg_password \
  -p 3306:3306 \
  mysql:8.0
```

**验证命令：**

```bash
mysql -u trpg -p trpg_password -e "SELECT VERSION();"
```

预期输出示例：`8.0.x` 开头的版本号

## 2. 一键启动脚本（可选）

项目根目录已内置 `start.sh` 一键启动脚本，自动完成依赖安装、数据库迁移、前后端启动全流程。

### 使用方法

**第一步：进入项目目录**

```bash
cd /home/ubuntu/trpg-platform
```

**第二步：赋予脚本执行权限（只需执行一次）**

```bash
chmod +x start.sh
```

**第三步：运行脚本**

```bash
./start.sh
```

### 脚本会自动完成以下操作：

1. ✅ 检查 Node.js、pnpm、MySQL、Redis 是否已安装
2. ✅ 自动执行 `pnpm install` 安装所有依赖
3. ✅ 自动生成 `.env` 环境配置文件（如不存在）
4. ✅ 自动执行数据库迁移，创建所有数据表
5. ✅ 在后台启动后端服务（端口 3000）
6. ✅ 在后台启动前端服务（端口 5173）
7. ✅ 输出访问地址 `http://localhost:5173`

### 停止服务

```bash
# 停止所有后台服务
kill $(cat .pids) 2>/dev/null && rm -f .pids
```

> **注意：** 如果脚本执行过程中报错，请参考第 6 节「常见问题排查」，或按照第 3 节手动启动步骤逐步执行。

## 3. 手动启动步骤

如果一键脚本出现问题，请按以下步骤逐一执行。每行命令后有注释说明用途。

> 假设代码已放置在 `/home/ubuntu/trpg-platform` 目录下。

```bash
# ── 第 1 步：进入项目根目录 ──────────────────────────────────
cd /home/ubuntu/trpg-platform

# ── 第 2 步：安装所有依赖（约 2～5 分钟，仅首次需要）──────────
pnpm install

# ── 第 3 步：检查并创建后端环境变量文件 ─────────────────────
# 查看是否已存在 .env 文件
ls packages/server/.env 2>/dev/null || echo "需要创建 .env 文件"

# 如果不存在，执行以下命令创建默认配置
cat > packages/server/.env <<'EOF'
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=trpg
DB_PASSWORD=trpg_password
DB_NAME=trpg_platform
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
JWT_SECRET=请替换为一段随机字符串例如trpg_secret_2024
PORT=3000
EOF

# ── 第 4 步：确保 MySQL 已启动 ───────────────────────────────
sudo systemctl start mysql
# 验证 MySQL 运行状态（应看到 "active (running)"）
sudo systemctl status mysql --no-pager | grep Active

# ── 第 5 步：确保 Redis 已启动 ───────────────────────────────
sudo systemctl start redis-server
# 验证 Redis 正常响应（应回显 PONG）
redis-cli ping

# ── 第 6 步：执行数据库迁移（创建所有数据表）────────────────
cd packages/server
pnpm exec knex migrate:latest --knexfile src/db/knex-config.ts
cd ../..
# 成功输出示例：Batch 1 run: 1 migrations

# ── 第 7 步：启动后端开发服务器（在终端 1 中运行）────────────
# 打开一个新的终端窗口，执行：
cd /home/ubuntu/trpg-platform/packages/server
pnpm dev
# 成功后终端会显示：Server listening on port 3000
# 可使用 http://localhost:3000/api/health 测试是否正常

# ── 第 8 步：启动前端开发服务器（在终端 2 中运行）────────────
# 打开另一个新的终端窗口，执行：
cd /home/ubuntu/trpg-platform/packages/client
pnpm dev
# 成功后终端会显示：Local: http://localhost:5173/

# ── 第 9 步：在浏览器中打开应用 ─────────────────────────────
# 在浏览器地址栏输入：
# http://localhost:5173
# 看到登录页面即表示启动成功 ✓
```

### 验证后端服务正常

在浏览器或终端执行：

```bash
curl http://localhost:3000/api/health
```

预期输出：`{"status":"ok"}`

### Phase 1：骰子引擎验收

| 验收场景 | 操作步骤 | 期望结果 |
|----------|----------|----------|
| 基础骰子指令 | 登录后进入任意跑团房间，在底部聊天输入框输入 `/r 1d6`，点击发送 | 消息区出现骰子结果卡片，显示 1～6 之间的随机整数 |
| 多骰加法 | 输入 `/r 2d6+3`，发送 | 结果为 2 个 d6 之和再加 3，范围 5～15 |
| 优势骰（取高） | 输入 `/r 2d20kh1`，发送 | 掷 2 个 d20，取较大值显示，并注明"取高" |
| 劣势骰（取低） | 输入 `/r 2d20kl1`，发送 | 掷 2 个 d20，取较小值显示，并注明"取低" |
| 叙事指令 | 输入 `/n 调查员小明一脸紧张地推开了门`，发送 | 消息以"叙事"样式（斜体或不同颜色）显示在聊天区 |
| 幕后指令 | 输入 `/ooc 这段剧情太刺激了！`，发送 | 消息以"幕后"标识（如灰色气泡）显示在聊天区 |
| P0 组件渲染 | 发送含骰子结果的消息后，查看消息卡片 | 消息卡片正常展示骰子类型、点数、总计等信息，无乱码 |

## 6. 常见问题排查

| 错误现象 | 可能原因 | 解决命令或操作 |
|----------|----------|----------------|
| `pnpm: command not found` | pnpm 未安装，或安装后未刷新终端 | 执行 `npm install -g pnpm`，然后关闭终端重新打开 |
| `npm: command not found` | Node.js 未安装 | 参考第 1.1 节重新安装 Node.js |
| `connect ECONNREFUSED 127.0.0.1:3306` | MySQL 服务未启动 | 执行 `sudo systemctl start mysql`，Docker 方式请确认容器运行：`docker start trpg-mysql` |
| `Access denied for user 'trpg'` | MySQL 用户不存在或密码错误 | 参考第 1.3 节重新创建数据库用户 |
| `Redis connection error` 或 `ECONNREFUSED 127.0.0.1:6379` | Redis 服务未启动 | 执行 `sudo systemctl start redis-server`，Docker 方式：`docker start trpg-redis` |
| `Error: Cannot find module '@trpg/shared'` | 依赖未安装或 workspace 链接失效 | 在项目根目录执行 `pnpm install`，然后重新启动后端 |
| 端口 3000 已被占用 | 已有其他进程在使用 3000 端口 | 执行 `lsof -i :3000`，找到 PID 后执行 `kill -9 <PID>` |
| 端口 5173 已被占用 | 已有其他前端进程在运行 | 执行 `lsof -i :5173`，找到 PID 后执行 `kill -9 <PID>` |
| 页面白屏，控制台显示 404 | 后端未启动，/api 请求失败 | 确认后端服务是否运行（`curl http://localhost:3000/api/health`），如无响应则按第 3 节重启后端 |
| 前端页面一直转圈不加载 | WebSocket 连接后端失败 | 检查后端是否启动，确认防火墙未拦截 3000 端口（`sudo ufw allow 3000`） |
| `pnpm install` 失败，提示网络错误 | npm 镜像源访问超时 | 切换国内镜像源：`pnpm config set registry https://registry.npmmirror.com` |
| 数据库迁移失败，提示表已存在 | 先前已执行过迁移 | 正常现象，可忽略；若报错，执行 `pnpm exec knex migrate:rollback --knexfile src/db/knex-config.ts` 后重新迁移 |
| `tsx: command not found` | tsx 工具未安装（通常随 pnpm install 安装） | 在 packages/server 目录执行 `pnpm install`，再重试 |
| Docker 命令提示权限不足 | 当前用户不在 docker 组中 | 执行 `sudo usermod -aG docker $USER`，然后重新登录系统 |
| 页面样式混乱/按钮消失 | 客户端依赖缺失 | 进入 `packages/client` 目录执行 `pnpm install`，再执行 `pnpm dev` |
