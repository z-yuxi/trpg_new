# 附录 Q：设计质量检查清单

> **文档版本**：v1.0  
> **适用范围**：TRPG 平台所有前端页面（桌面端 + 移动端 PWA）  
> **检查时机**：开发完成后的 UI 还原走查、主题切换测试、新增页面评审  
> **关联文档**：《附录 B：设计令牌》、《附录 D：页面设计》、《附录 J：移动端适配》、《附录 X：页面框架与布局规范》

---

## 一、页面一致性检查（Page Coherence）

所有后台页面必须遵循统一的框架规范，消除"切换导航后割裂感"。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 1.1 | **PageLayout 复用** | 页面是否复用了统一的 `PageLayout` 容器？禁止每个页面独立手写布局。 | 🔴 阻断 |
| 1.2 | **Header 结构** | 标题区是否为"左：标题+描述 | 右：主操作按钮"？按钮是否垂直居中对齐？ | 🔴 阻断 |
| 1.3 | **主操作按钮位置** | 主操作按钮（新建/上传/发布）是否固定在 Header 右上角？ | 🔴 阻断 |
| 1.4 | **按钮主次顺序** | 按钮顺序是否为"次操作 → 主操作"（从左到右）？主操作是否使用品牌色？ | 🟡 严重 |
| 1.5 | **Stats 区规范** | 统计卡片是否使用了 `DashboardStats` 组件？是否左对齐（禁止居中）？ | 🟡 严重 |
| 1.6 | **FilterBar 位置** | 筛选栏是否在 Stats 下方（如有）或 Header 下方？是否与内容区间距 16px？ | 🟡 严重 |
| 1.7 | **内容区网格** | 卡片网格是否遵循响应式规则（桌面 4/2 列、平板 2 列、移动 1-2 列）？ | 🟡 严重 |
| 1.8 | **空状态统一** | 空状态是否使用了 `EmptyState` 组件？包含 SVG 占位图 + 标题 + 描述 + 操作按钮？ | 🟢 一般 |
| 1.9 | **全局内边距** | 页面内边距是否为 24px（桌面）/ 16px（移动）？内容区最大宽度是否 1280px 居中？ | 🟡 严重 |
| 1.10 | **跨页面组件复用** | 同一组件（卡片、按钮、标签）在不同页面样式是否一致？禁止独立写样式。 | 🔴 阻断 |

## 二、主题适配检查（Theme Adaptation）

确保日间/夜间模式切换后，无元素"掉色"、无硬编码白斑、对比度达标。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 2.1 | **品牌色锁定** | `--color-primary` 是否为 `#5B8DB8`（日间）/ `#6B9DC8`（夜间）？禁止改为 Slate 灰或其他蓝色。 | 🔴 阻断 |
| 2.2 | **危险色锁定** | `--color-danger` 是否为 `#B85450`（日间）/ `#C86460`（夜间）？ | 🔴 阻断 |
| 2.3 | **无硬编码颜色** | 组件 CSS 中是否存在 `#f5f5f5`、`#ddd`、`#222`、`#fff` 等裸色值？必须替换为语义变量。 | 🔴 阻断 |
| 2.4 | **无幽灵变量** | 是否存在 `--fg-1`、`--bg-2`、`--bg-3`、`--border` 等未定义变量？必须迁移到新语义命名。 | 🔴 阻断 |
| 2.5 | **夜间模式对比度** | 所有文字在背景上对比度是否 ≥ 4.5:1？（正文）/ ≥ 3:1？（大文字） | 🔴 阻断 |
| 2.6 | **按钮反色** | 夜间模式下主按钮是否为品牌蓝背景 + 白色文字？禁止变成"隐形按钮"（浅灰背景+白字）。 | 🔴 阻断 |
| 2.7 | **输入框背景** | 夜间模式下输入框背景是否为 `--surface-card`（深灰），而非 `--surface-page`（更浅）？ | 🟡 严重 |
| 2.8 | **卡片背景** | 夜间模式下卡片背景是否为 `--surface-card`（`#161B22`），无硬编码白色或浅灰色？ | 🟡 严重 |
| 2.9 | **阴影适配** | 夜间模式下阴影是否加深（`rgba(0,0,0,0.4+)`），而非沿用日间浅色阴影？ | 🟢 一般 |
| 2.10 | **切换动画** | 日/夜切换时，背景色、文字色、边框色是否有 350ms 的平滑过渡？ | 🟢 一般 |

## 三、响应式与布局检查（Responsive & Layout）

确保宽屏无单侧留白、移动端触控友好、信息架构不崩塌。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 3.1 | **留白对称** | 宽屏（1920px+）下，主内容区是否居中（`margin: 0 auto`）？禁止左对齐导致右侧大块留白。 | 🔴 阻断 |
| 3.2 | **断点遵循** | 是否使用标准断点（桌面 ≥1280px、平板 ≥768px、移动 <768px）？ | 🟡 严重 |
| 3.3 | **触摸目标** | 移动端所有可点击元素（按钮、卡片、列表项）尺寸是否 ≥ 44px x 44px？ | 🔴 阻断 |
| 3.4 | **底部栏切换** | 跑团房间内是否隐藏全局底部导航，显示专属底部快捷栏？切换是否有动画？ | 🟡 严重 |
| 3.5 | **表单排版模式** | 窄容器（<300px）内是否使用水平标签模式？宽容器（≥600px）内是否使用垂直标签模式？ | 🔴 阻断 |
| 3.6 | **控件密度** | 边栏/工具栏是否使用 Dense 密度（28-32px）？常规表单是否使用 Normal 密度（40px）？ | 🟢 一般 |
| 3.7 | **模态框适配** | 移动端模态框是否为全屏底部抽屉（圆角顶部 16px），而非居中弹窗？ | 🟡 严重 |
| 3.8 | **筛选栏折叠** | 移动端筛选栏是否只显示 2-3 个高频项，其余折叠进"更多筛选"底部抽屉？ | 🟢 一般 |
| 3.9 | **Stats 响应式** | 移动端 Stats 卡片是否为 2 列网格（或 2x2）？禁止 4 列导致卡片过窄。 | 🟡 严重 |
| 3.10 | **内容区单列** | 移动端内容区是否为单列卡片流？必要时双列，禁止三列以上。 | 🟡 严重 |

## 四、信息架构检查（Information Architecture）

确保功能层级清晰、导航不重复、边栏职责不越界。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 4.1 | **功能 Tab 映射** | 桌面端 Ribbon 的 5 个功能 Tab（场景/NPC/线索/笔记/骰子）在移动端是否有对应入口？ | 🔴 阻断 |
| 4.2 | **左侧栏职责** | 左侧导航栏是否只放列表/导航/只读卡片？禁止嵌套表单输入框或操作按钮。 | 🔴 阻断 |
| 4.3 | **配置项位置** | 场景配置（背景音乐/天气/时间流速）是否在顶部 Ribbon/工具栏，而非左侧边栏？ | 🔴 阻断 |
| 4.4 | **顶部信息栏纯净** | 跑团房间顶部栏是否只展示元信息（房间名/时间/在线状态）？禁止放置配置表单。 | 🔴 阻断 |
| 4.5 | **GM 控制台边界** | 导演模式与叙事模式的边界是否清晰？叙事模式下是否隐藏复杂配置功能？ | 🟡 严重 |
| 4.6 | **底部快捷栏功能** | 跑团房间底部 4 个按钮（🎲/角色卡/指令/更多）是否覆盖核心高频操作？ | 🟡 严重 |
| 4.7 | **创作者入口可发现性** | 创作者账号：桌面端顶栏"创作台"按钮可见；移动端顶栏创作台图标可见且个人页首屏有入口卡片；非创作者访问 `/creator/**` 路由被拦截到 403 | 🔴 阻断 |
| 4.8 | **降级提示统一** | 禁用功能点击时，是否统一提示"请在电脑上使用此功能"？禁止无提示或文案不一致。 | 🟢 一般 |
| 4.9 | **空状态引导** | 空状态是否提供明确的下一步操作按钮（如"去招募板找团"、"创建团"）？ | 🟢 一般 |
| 4.10 | **跨页面导航一致性** | 切换左侧导航后，各页面的布局结构、组件样式、操作位置是否遵循同一套规则？ | 🔴 阻断 |

## 五、组件规范检查（Component Compliance）

确保组件使用正确、无 Emoji、SVG 规范、状态完整。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 5.1 | **无 Emoji** | 界面中是否使用了 Emoji 作为图标？必须使用 SVG（`fill="currentColor"`）。 | 🔴 阻断 |
| 5.2 | **SVG 尺寸规范** | SVG 图标是否为标准尺寸（16px 小 / 20px 标准 / 24px 大）？ | 🟢 一般 |
| 5.3 | **按钮状态完整** | 按钮是否包含 default / hover / active / disabled / focus 五种状态？ | 🟡 严重 |
| 5.4 | **卡片状态完整** | 卡片是否包含 default / hover / active / disabled 状态？hover 是否有阴影+位移？ | 🟢 一般 |
| 5.5 | **输入框状态完整** | 输入框是否包含 default / hover / focus / disabled / error 状态？ | 🟡 严重 |
| 5.6 | **标签样式统一** | 标签（Tag/Badge）是否使用统一的 `Tag` 组件？不同页面的标签样式是否一致？ | 🟡 严重 |
| 5.7 | **加载状态** | 列表/卡片加载时是否使用骨架屏（Skeleton）而非空白或转圈？ | 🟢 一般 |
| 5.8 | **错误状态** | 表单提交失败时是否有明确的错误提示（边框变红 + 文字说明）？ | 🟡 严重 |
| 5.9 | **禁用状态对比度** | 禁用文字对比度是否 ≥ 3:1（大文字）？禁用按钮是否 `opacity: 0.5` + `cursor: not-allowed`？ | 🟢 一般 |
| 5.10 | **color-mix 兼容性** | 使用 `color-mix()` 的地方是否提供了 `@supports` 回退或预计算色值？ | 🟢 一般 |

## 六、跨端同步检查（Cross-Device Sync）

针对模组编辑器移动端与桌面端的近实时同步场景。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 6.1 | **防抖策略区分** | 移动端是否为 1.5s 防抖？桌面端是否为 3s 防抖？ | 🟡 严重 |
| 6.2 | **强制保存触发** | 点击"完成"、路由离开、切后台时是否立即触发保存（不等待防抖）？ | 🔴 阻断 |
| 6.3 | **保存状态指示** | 顶部是否常驻保存状态（已保存 ✅ / 保存中 ⏳ / 保存失败 ❌）？ | 🟡 严重 |
| 6.4 | **冲突提示非阻断** | 桌面端收到移动端更新时，是否显示非阻断 Toast（3秒自动消失）？禁止弹窗打断输入流。 | 🟡 严重 |
| 6.5 | **离线队列** | 弱网/断网时，输入是否先写入 IndexedDB？恢复网络后是否自动重试？ | 🔴 阻断 |
| 6.6 | **幂等去重** | 保存请求是否携带 `op_id`？弱网重试时是否避免重复写入？ | 🟡 严重 |
| 6.7 | **版本号机制** | 服务端是否保存单调递增的 `revision`？乐观锁是否生效？ | 🔴 阻断 |
| 6.8 | **WebSocket 频道** | 是否按资源订阅（`/modules/{id}/changes`），而非按用户广播？ | 🟡 严重 |
| 6.9 | **跨端可见延迟** | 同一账号手机改文后，电脑端可见延迟 P95 是否 < 3 秒？ | 🔴 阻断 |
| 6.10 | **离线恢复率** | 锁屏/断网后内容不丢，离线恢复成功率是否 > 99%？ | 🔴 阻断 |

## 七、无障碍检查（Accessibility）

确保平台对所有用户可用，包括键盘用户和视障用户。

| # | 检查项 | 通过标准 | 严重等级 |
|---|--------|----------|----------|
| 7.1 | **键盘导航** | 所有交互元素（按钮、链接、表单）是否可通过 Tab 键聚焦和操作？ | 🟡 严重 |
| 7.2 | **焦点指示器** | 聚焦状态是否有清晰可见的轮廓（`box-shadow: 0 0 0 3px var(--color-primary-light)`）？ | 🟡 严重 |
| 7.3 | **ARIA 标签** | 复杂组件（抽屉、模态框、标签页）是否有合适的 `aria-*` 属性？ | 🟢 一般 |
| 7.4 | **语义化 HTML** | 是否使用了正确的标题层级（`h1` → `h2` → `h3`）？是否使用了 `<nav>`、`<main>`、`<aside>`？ | 🟢 一般 |
| 7.5 | **动画可关闭** | 是否支持 `prefers-reduced-motion`？用户关闭动画后，过渡效果是否禁用？ | 🟢 一般 |

## 九、使用流程

### 开发阶段（自测）
1. 开发完成后，开发者对照本清单逐项自测。
2. 🔴 阻断项必须全部通过，否则禁止提交代码。
3. 🟡 严重项允许最多 2 项未通过，需记录并安排修复。

### 设计走查阶段（设计师）
1. 设计师按清单逐页检查，截图标注偏差。
2. 重点检查 1.x（页面一致性）和 2.x（主题适配）。
3. 输出走查报告，按严重等级排序修复优先级。

### 新增页面评审（产品+设计+前端）
1. 新增页面上线前，三方对照清单评审。
2. 确认该页面遵循《附录 X：页面框架与布局规范》。
3. 确认组件复用率 ≥ 80%（禁止大量手写样式）。
