## 一、架构总览

### 1.1 三层架构

```
用户编辑层              存储层                      执行层
┌───────────────┐    ┌──────────────────────┐    ┌───────────────┐
│ 模板选择       │    │                      │    │               │
│ 表单编辑       │───▶│ Recipe（配方源）       │    │               │
│ DSL 表达式     │    │   ↓ compile()        │    │  通用执行器     │
│               │    │ atoms + connections   │───▶│ （零改动）      │
│ JSON 导入/导出 │───▶│ （编译产物）           │    │               │
└───────────────┘    │                      │    └───────────────┘
                     └──────────────────────┘
                                ↑
                     runtime_modifiers（运行时修饰符）
                     由指令参数注入，不属于 recipe
```

### 1.2 关键原则

| 编号 | 原则 | 说明 |
|------|------|------|
| R-001 | 引擎零改动 | 执行器只消费 `{ atoms, connections }`，不感知 recipe 层 |
| R-002 | 双层存储 | Recipe 是"源码"，atoms 是"编译产物"，保存时自动编译 |
| R-003 | 编译缓存 | Recipe 编译结果持久化，运行时直接读取，不重复编译 |
| R-004 | 静态规则 vs 动态修饰 | Recipe 定义不变的规则结构；奖励骰、难度等运行时变量通过 runtime_modifiers 注入 |
| R-005 | 策略模式编译器 | 每种 recipe 类型对应一个编译函数，通过注册机制扩展 |

### 1.3 与现有架构的兼容性

| 现有组件 | 是否修改 | 说明 |
|---------|:-------:|------|
| 通用执行器（Executor） | 否 | 只消费 atoms+connections |
| 预置原子节点（dice_roll, threshold_compare 等） | 小改 | dice_roll 扩展支持 bonus/penalty dice 参数 |
| 指令系统（Commands） | 小改 | `entry_atom` → `recipe_id`；意图解析器扩展提取修饰符 |
| 角色卡系统 | 否 | 数据结构不变 |
| 规则包继承 | 小改 | 子包可按 recipe.id 覆盖父包的 recipe |
| 前端助理台 | 否 | 指令速查接口不变 |
| 规则包热加载 | 小改 | 热加载时重新编译 recipe → atoms |

## 二、配方类型体系（Recipe Type Catalog）

### 2.1 八种基础类型 + 一种兼容类型

| # | 类型标识 | 名称 | 覆盖场景 | MVP 优先级 |
|---|---------|------|---------|-----------|
| 1 | `threshold_check` | 阈值检定 | COC技能/属性检定、DND属性/豁免/攻击检定 | P0 |
| 2 | `opposed_check` | 对抗检定 | COC对抗检定、DND竞争检定 | P0 |
| 3 | `resource_modify` | 资源修改 | 伤害、治疗、SAN损失、弹药消耗 | P0 |
| 4 | `random_table` | 随机表 | 疯狂症状表、遭遇表、战利品表 | P0 |
| 5 | `initiative` | 先攻排序 | DND先攻、COC DEX排序 | P1 |
| 6 | `growth_check` | 成长检定 | COC技能成长（幕间成长） | P0 |
| 7 | `accumulation` | 累积判定 | DND死亡豁免（累积3次成功/失败） | P1 |
| 8 | `chain` | 连锁配方 | SAN检定、攻击流程（命中+伤害） | P0 |
| 9 | `raw` | 原始原子图 | 高级用户 JSON 导入、未来画布回归预留 | P1 |

### 2.2 类型设计依据

- **1-3**：原子操作——掷骰比较、修改数值、查表，几乎所有规则由这三者构成
- **4**：TRPG 特有的"随机叙事"能力
- **5**：回合制的前置条件
- **6-7**：特定但常见的成长/累积机制
- **8 (chain)**：元类型，串联 1-7 为多步流程，表达复杂规则的关键
- **9 (raw)**：兼容层，不提供表单编辑，为直接导入原子图和未来画布预留

### 2.3 Chain 嵌套限制

- 最大嵌套深度：**1 层**（chain 内部引用的 recipe 不允许是 chain 类型）
- 复杂流程处理：将复杂 chain 打包为独立的"复合规则"，上层单步引用

```
允许：
  Recipe A (chain)
    ├── Step 1: Recipe B (threshold_check)
    ├── Step 2: Recipe C (resource_modify)  [条件: Step 1 失败]
    └── Step 3: Recipe D (resource_modify)  [条件: Step 1 成功]

禁止：
  Recipe A (chain)
    └── Step 1: Recipe B (chain)  ← 嵌套 chain，编译器拒绝
```

## 四、配方 Schema 定义

### 4.1 配方基础结构

```typescript
// ===== 配方类型枚举 =====
type RecipeType =
  | 'threshold_check'
  | 'opposed_check'
  | 'resource_modify'
  | 'random_table'
  | 'initiative'
  | 'growth_check'
  | 'accumulation'
  | 'chain'
  | 'raw';

// ===== 配方顶层结构 =====
interface Recipe {
  id: string;                      // 配方唯一标识，如 "coc7_skill_check"
  type: RecipeType;                // 配方类型
  name: string;                    // 显示名称，如 "COC7版技能检定"
  description?: string;            // 可选描述
  tags?: string[];                 // 可选标签，便于分类

  // 类型特定参数（联合类型，由 type 决定）
  params: RecipeParams;

  // ===== 编译产物（自动生成，用户不直接编辑）=====
  compiled: CompiledGraph;
}

interface CompiledGraph {
  atoms: AtomInstance[];
  connections: Connection[];
  entry_atom_id: string;           // 入口节点
  output_atom_id: string;          // 输出节点
}

// 参数联合类型
type RecipeParams =
  | ThresholdCheckParams
  | OpposedCheckParams
  | ResourceModifyParams
  | RandomTableParams
  | InitiativeParams
  | GrowthCheckParams
  | AccumulationParams
  | ChainParams
  | RawRecipeParams;
```

### 4.2 阈值检定（threshold_check）

覆盖面最广的类型。COC 的 `d100 ≤ 技能值`、DND 的 `d20 + 修正 ≥ DC` 都是它。

```typescript
interface ThresholdCheckParams {
  // ── 骰子 ──
  dice_expression: string;             // "1d100" | "1d20" | "3d6"

  // ── 目标值 ──
  target_source: 'skill' | 'attribute' | 'fixed' | 'formula';
  target_ref?: string;                 // skill/attribute 名称（如 "侦查"、"STR"）
  target_fixed?: number;               // 当 target_source='fixed' 时
  target_formula?: string;             // 当 target_source='formula' 时

  // ── 判定方向 ──
  success_direction: 'lte' | 'gte';    // lte=掷低成功（COC）, gte=掷高成功（DND）

  // ── 修正值（可选，DND 风格）──
  modifier_sources?: ModifierSource[];

  // ── 难度系统（可选）──
  difficulty?: {
    mode: 'divisor' | 'none';
    divisors?: number[];               // [1, 2, 5] = 常规/困难/极难
    default_level?: number;            // 默认难度索引，默认 0
  };

  // ── 优势/劣势（可选，DND 风格）──
  advantage_system?: {
    enabled: boolean;
    extra_dice: number;                // 额外骰子数（通常 1）
    keep: 'highest' | 'lowest';
  };

  // ── 成功等级（从上到下匹配，首个命中即最终结果）──
  tiers: SuccessTier[];
}

interface SuccessTier {
  name: string;          // 程序标识："critical" | "extreme" | "hard" | "regular" | "fail" | "fumble"
  label: string;         // 显示名称："大成功"
  condition: string;     // 表达式："roll == 1"、"roll <= target / 5"
  is_success: boolean;   // 是否算作成功
}

interface ModifierSource {
  source: 'attribute_mod' | 'proficiency' | 'fixed' | 'formula';
  ref?: string;          // "DEX_mod"、"proficiency_bonus"
  value?: number;        // source='fixed' 时
  formula?: string;      // source='formula' 时
}
```

### 4.3 对抗检定（opposed_check）

```typescript
interface OpposedCheckParams {
  // 主动方
  attacker: {
    dice_expression: string;
    target_source: 'skill' | 'attribute';
    target_ref: string;
  };
  // 被动方
  defender: {
    dice_expression: string;
    target_source: 'skill' | 'attribute';
    target_ref: string;
  };
  // 对比方式
  resolution: 'tier_compare' | 'value_compare';
  // tier_compare: 比较成功等级（COC，极难 > 困难 > 常规）
  // value_compare: 比较数值大小（DND 竞争检定）

  // 平局处理
  tie_rule: 'attacker_wins' | 'defender_wins' | 'reroll';
}
```

### 4.4 资源修改（resource_modify）

```typescript
interface ResourceModifyParams {
  resource_ref: string;                // "hp" | "mp" | "san" | 自定义资源 ID

  delta: {
    mode: 'fixed' | 'dice' | 'formula';
    value?: number;                    // fixed 模式
    expression?: string;               // dice: "1d6+2", formula: "level * 2"

  direction: 'decrease' | 'increase';

  // 边界处理
  clamp_min?: number | 'zero';        // 默认 0
  clamp_max?: 'resource_max' | number;

  // 溢出事件（可选）
  on_zero?: string;                   // 资源归零时触发的事件 ID
  on_overflow?: string;
}
```

### 4.9 连锁配方（chain）

```typescript
interface ChainParams {
  steps: ChainStep[];
}

interface ChainStep {
  step_id: string;                     // 步骤标识
  recipe_ref: string;                  // 引用另一个 recipe 的 ID（不允许引用 chain 类型）

  // 输入映射
  input_mapping?: Record<string, string>;

  // 条件执行

    depends_on: string;                // 依赖的 step_id
    when: 'success' | 'failure' | 'always' | 'expression';
    expression?: string;               // when='expression' 时
  };
}
```

## 五、运行时修饰符（Runtime Modifiers）

### 5.1 设计原理

Recipe 定义"不变的规则结构"，运行时修饰符定义"本次执行的临时调整"。二者分离，避免 recipe 爆炸。

**行业验证**：海豹骰子 `/ra b2 侦查`、Foundry VTT `2d20kh` 均采用运行时指定修饰符的方式。

### 5.2 修饰符数据结构

```typescript
interface RuntimeModifiers {
  // ── 骰子修饰 ──
  bonus_dice?: number;           // COC 奖励骰数量（1-2）
  penalty_dice?: number;         // COC 惩罚骰数量（1-2）
  advantage?: boolean;           // DND 优势
  disadvantage?: boolean;        // DND 劣势

  // ── 难度修饰 ──
  difficulty_level?: number;     // 难度等级索引（0=常规, 1=困难, 2=极难）
  dc_override?: number;          // 直接指定 DC 值

  // ── 目标值修饰 ──
  target_bonus?: number;         // 目标值加减（如场景修正 -20）
}
```

### 5.3 执行请求变更

```typescript
interface ExecuteRequest {
  ruleset_id: string;
  command: string;                     // "ra"
  params: Record<string, any>;         // { skill: "侦查" }，为意图解析后的实际参数
  context: {
    character_id: string;
    campaign_id: string;
    scene_id?: string;
  };

  // ===== 新增 =====
  runtime_modifiers?: RuntimeModifiers;
}
```

说明：

- `params` 保存的是意图解析器提取后的**实参**，例如 `{ skill: "侦查" }`。
- `CommandMapping.input_mapping` 中的占位符（如 `{skill}`）不会直接写入执行图，而是在执行前根据 `params` 做一次变量替换。
- 该替换发生在执行器装配输入上下文时，不会改写 ruleset 中保存的 recipe 或 command 定义。

示例：

```typescript
params = { skill: '侦查' };
input_mapping = { skill: '{skill}' };

// 绑定后
bound_inputs = { skill: '侦查' };
```

### 5.4 意图解析器扩展

指令中的修饰符前缀由意图解析器提取，转换为 `runtime_modifiers`：

```
输入: "/ra b2 h 侦查"
      ↓ 意图解析器
{
  command: "ra",
  params: { skill: "侦查" },
  runtime_modifiers: {
    bonus_dice: 2,
    difficulty_level: 1       // h = hard = divisors[1]
  }
}
```

解析规则（正则匹配，顺序无关）：

| 前缀 | 正则 | 映射到 |
|------|------|--------|
| `b{n}` | `/b(\d)/` | `bonus_dice: n` |
| `p{n}` | `/p(\d)/` | `penalty_dice: n` |
| `h` | `/\bh\b/` | `difficulty_level: 1` |
| `e` | `/\be\b/` | `difficulty_level: 2` |

### 5.5 dice_roll 原子节点扩展

```typescript
// dice_roll 原子执行时，检查 runtime_modifiers
function executeDiceRoll(config: DiceRollConfig, modifiers?: RuntimeModifiers): DiceResult {
  const expr = config.expression;  // "1d100"

  if (modifiers?.bonus_dice && expr === '1d100') {
    // COC 奖励骰：额外掷 N 个十位骰，取最低十位
    const units = rollDice(1, 10) - 1;          // 0-9 个位
    const tensDice = rollDice(1 + modifiers.bonus_dice, 10);
    const bestTens = Math.min(...tensDice) * 10; // 取最低十位
    const total = bestTens + units;
    return { total, natural_roll: total, rolls: tensDice, units, bonus_applied: true };
  }

  if (modifiers?.penalty_dice && expr === '1d100') {
    // COC 惩罚骰：额外掷 N 个十位骰，取最高十位
    const units = rollDice(1, 10) - 1;
    const tensDice = rollDice(1 + modifiers.penalty_dice, 10);
    const worstTens = Math.max(...tensDice) * 10;
    const total = worstTens + units;
    return { total, natural_roll: total, rolls: tensDice, units, penalty_applied: true };
  }

  if (modifiers?.advantage) {
    // DND 优势：掷 2 次取高
    const roll1 = rollDice(1, 20);
    const roll2 = rollDice(1, 20);
    return { total: Math.max(roll1, roll2), natural_roll: Math.max(roll1, roll2), rolls: [roll1, roll2] };
  }

  // 标准掷骰
  return standardDiceRoll(expr);
}
```

### 5.6 threshold_compare 原子节点扩展

```typescript
function executeThresholdCompare(
  config: ThresholdCompareConfig,
  inputs: { roll: number; target: number },
  modifiers?: RuntimeModifiers
): CompareResult {
  let effectiveTarget = inputs.target;

  // 难度调整
  if (modifiers?.difficulty_level !== undefined && config.difficulty?.divisors) {
    const divisor = config.difficulty.divisors[modifiers.difficulty_level] || 1;
    effectiveTarget = Math.floor(inputs.target / divisor);
  }

  // 目标值加减
  if (modifiers?.target_bonus) {
    effectiveTarget += modifiers.target_bonus;
  }

  // DC 覆盖
  if (modifiers?.dc_override !== undefined) {
    effectiveTarget = modifiers.dc_override;
  }

  // 遍历 tiers 匹配
  for (const tier of config.tiers) {
    const ctx = { roll: inputs.roll, target: effectiveTarget, natural_roll: inputs.roll };
    if (evaluateExpression(tier.condition, ctx)) {
      return {
        success: tier.is_success,
        tier: tier.name,
        tier_label: tier.label,
        roll: inputs.roll,
        target: effectiveTarget,
        original_target: inputs.target
      };
    }
  }
}
```

## 六、表达式语言（Recipe DSL）

### 6.1 选型决策

使用 **`expr-eval`** 库（npm: `expr-eval`），不自研。

理由：
- 轻量无依赖，gzip < 10KB
- 支持自定义函数注册
- 沙箱执行，无 `eval()` 风险
- 社区成熟，维护活跃

骰子表达式解析使用独立的 **dice parser** 模块，与 expr-eval 组合。

### 6.2 语法元素

| 类别 | 语法 | 示例 |
|------|------|------|
| 骰子字面量 | `NdM`, `NdMkh/kl` | `1d100`, `3d6`, `2d10kh1` |
| 数字 | 整数/小数 | `10`, `0.5` |
| 变量 | 标识符/路径 | `roll`, `target`, `natural_roll`, `total` |
| 角色卡引用 | `skill.X`, `attr.X`, `resource.X` | `skill.侦查`, `attr.STR` |
| 算术 | `+`, `-`, `*`, `/`, `%` | `target / 5` |
| 比较 | `==`, `!=`, `<`, `<=`, `>`, `>=` | `roll <= target` |
| 逻辑 | `&&`, `\|\|`, `!` | `roll >= 96 && target < 50` |
| 括号 | `()` | `(attr.CON + attr.SIZ) / 10` |
| 函数 | `floor`, `ceil`, `round`, `min`, `max`, `abs` | `floor(target / 2)` |

### 6.3 上下文变量表

| 使用位置 | 可用变量 |
|---------|---------|
| `tiers[].condition` | `roll`, `natural_roll`, `total`, `target`, `DC` |
| `target_formula` | `attr.*`, `skill.*`, `resource.*` |
| `modifier_sources[].formula` | `attr.*`, `level`, `proficiency_bonus` |
| `chain.condition.expression` | `steps.{step_id}.result.*` |
| `growth_check.check_condition` | `roll`, `current_value` |

### 6.4 安全约束

- 表达式最大长度：256 字符
- 函数白名单：`floor`, `ceil`, `round`, `min`, `max`, `abs`
- 变量引用深度：最多 3 层（`resource.hp.max`）
- 禁止：字符串操作、赋值、循环、外部函数调用

## 七、Recipe → Atoms 编译器

### 7.1 策略模式架构

```typescript
// 编译器接口
interface RecipeCompiler<T extends RecipeType = RecipeType> {
  type: T;
  compile(recipe: Recipe): CompiledGraph;
  validate(recipe: Recipe): ValidationResult;
}

// 编译器注册表
class CompilerRegistry {
  private compilers = new Map<RecipeType, RecipeCompiler>();

  register<T extends RecipeType>(compiler: RecipeCompiler<T>): void {
    this.compilers.set(compiler.type, compiler);
  }

  compile(recipe: Recipe): CompiledGraph {
    const compiler = this.compilers.get(recipe.type);
    if (!compiler) {
      throw new EngineError('UNKNOWN_RECIPE_TYPE', `No compiler for: ${recipe.type}`);
    }
    const validation = compiler.validate(recipe);
    if (!validation.valid) {
      throw new EngineError('RECIPE_VALIDATION_FAILED', validation.errors.join('; '));
    }
    return compiler.compile(recipe);
  }
}

// 全局注册
const registry = new CompilerRegistry();
registry.register(new ThresholdCheckCompiler());
registry.register(new OpposedCheckCompiler());
registry.register(new ResourceModifyCompiler());
registry.register(new RandomTableCompiler());
registry.register(new InitiativeCompiler());
registry.register(new GrowthCheckCompiler());
registry.register(new AccumulationCompiler());
registry.register(new ChainCompiler());
registry.register(new RawCompiler());
```

### 7.2 阈值检定编译模式

```
threshold_check params
       ↓ compile
┌───────────────────────────────────────────────────────────┐
│                                                           │
│  [target_reader] ──→ [difficulty_adjust]* ──┐             │
│                                             ├──→ [compare] ──→ [output]
│  [dice_roll] ──→ [modifier_apply]* ────────┘             │
│                                                           │
│  * = 可选节点，根据 params 决定是否生成                       │
└───────────────────────────────────────────────────────────┘
```

### 7.3 连锁配方编译模式

```
chain params
       ↓ compile（递归编译每个子步骤的 recipe）

[step1.compiled_graph]
       ↓ result
[if_else: condition?] ──match──→ [step2.compiled_graph]
                       ──else──→ [step3.compiled_graph]
                                        ↓
                                  [result_collector]
```

### 7.4 命名空间规则

每个 recipe 的 atom ID 带命名空间前缀，避免合并时冲突：

```
格式：{recipe_id}__{atom_name}
chain 子步骤：{chain_id}__{step_id}__{atom_name}

示例：
  coc7_skill_check__dice
  coc7_skill_check__compare
  coc7_san_check__check__dice
  coc7_san_check__failure_loss__resource_mod
```

### 7.5 编译缓存策略

- **编译时机**：Recipe 保存时立即编译，编译产物持久化到 `recipe.compiled` 字段
- **运行时**：直接读取 `compiled`，不重复编译
- **失效条件**：Recipe 的 `params` 发生变更时重新编译
- **规则包加载**：从数据库加载规则包时，所有 recipe 的 compiled 已就绪，无需运行时编译
- **热加载**：规则包更新时，后端重新编译受影响的 recipe，替换内存缓存
