## 一、架构总览

### 1.1 三层架构

```
用户编辑层              存储层                      执行层
┌───────────────┐    ┌──────────────────────┐    ┌───────────────┐
│ 模板选择       │    │                      │    │               │
│ 表单编辑       │───▶│ Recipe（配方源）       │    │               │
│ DSL 表达式     │    │   ↓ compile()        │    │  通用执行器     │
│               │    │ atoms + connections   │───▶│ （零改动）      │
│ JSON 导入/导出 │───▶│ （编译产物）           │    │               │
└───────────────┘    │                      │    └───────────────┘
                     └──────────────────────┘
                                ↑
                     runtime_modifiers（运行时修饰符）
                     由指令参数注入，不属于 recipe
```

### 1.2 关键原则

| 编号 | 原则 | 说明 |
|------|------|------|
| R-001 | 引擎零改动 | 执行器只消费 `{ atoms, connections }`，不感知 recipe 层 |
| R-002 | 双层存储 | Recipe 是"源码"，atoms 是"编译产物"，保存时自动编译 |
| R-003 | 编译缓存 | Recipe 编译结果持久化，运行时直接读取，不重复编译 |
| R-004 | 静态规则 vs 动态修饰 | Recipe 定义不变的规则结构；奖励骰、难度等运行时变量通过 runtime_modifiers 注入 |
| R-005 | 策略模式编译器 | 每种 recipe 类型对应一个编译函数，通过注册机制扩展 |

### 1.3 与现有架构的兼容性

| 现有组件 | 是否修改 | 说明 |
|---------|:-------:|------|
| 通用执行器（Executor） | 否 | 只消费 atoms+connections |
| 预置原子节点（dice_roll, threshold_compare 等） | 小改 | dice_roll 扩展支持 bonus/penalty dice 参数 |
| 指令系统（Commands） | 小改 | `entry_atom` → `recipe_id`；意图解析器扩展提取修饰符 |
| 角色卡系统 | 否 | 数据结构不变 |
| 规则包继承 | 小改 | 子包可按 recipe.id 覆盖父包的 recipe |
| 前端助理台 | 否 | 指令速查接口不变 |
| 规则包热加载 | 小改 | 热加载时重新编译 recipe → atoms |

## 二、配方类型体系（Recipe Type Catalog）

### 2.1 八种基础类型 + 一种兼容类型

| # | 类型标识 | 名称 | 覆盖场景 | MVP 优先级 |
|---|---------|------|---------|-----------|
| 1 | `threshold_check` | 阈值检定 | COC技能/属性检定、DND属性/豁免/攻击检定 | P0 |
| 2 | `opposed_check` | 对抗检定 | COC对抗检定、DND竞争检定 | P0 |
| 3 | `resource_modify` | 资源修改 | 伤害、治疗、SAN损失、弹药消耗 | P0 |
| 4 | `random_table` | 随机表 | 疯狂症状表、遭遇表、战利品表 | P0 |
| 5 | `initiative` | 先攻排序 | DND先攻、COC DEX排序 | P1 |
| 6 | `growth_check` | 成长检定 | COC技能成长（幕间成长） | P0 |
| 7 | `accumulation` | 累积判定 | DND死亡豁免（累积3次成功/失败） | P1 |
| 8 | `chain` | 连锁配方 | SAN检定、攻击流程（命中+伤害） | P0 |
| 9 | `raw` | 原始原子图 | 导入兼容迁移（P1）+ 运行时/编辑器开放（P2） | P1/P2 |

### 2.2 类型设计依据

- **1-3**：原子操作——掷骰比较、修改数值、查表，几乎所有规则由这三者构成
- **4**：TRPG 特有的"随机叙事"能力
- **5**：回合制的前置条件
- **6-7**：特定但常见的成长/累积机制
- **8 (chain)**：元类型，串联 1-7 为多步流程，表达复杂规则的关键
- **9 (raw)**：分阶段兼容层，P1 仅用于导入迁移封装，P2 再开放运行时执行与编辑器入口

### 2.3 Chain 嵌套限制

- 最大嵌套深度：**1 层**（chain 内部引用的 recipe 不允许是 chain 类型）
- 复杂流程处理：将复杂 chain 打包为独立的"复合规则"，上层单步引用

```
允许：
  Recipe A (chain)
    ├── Step 1: Recipe B (threshold_check)
    ├── Step 2: Recipe C (resource_modify)  [条件: Step 1 失败]
    └── Step 3: Recipe D (resource_modify)  [条件: Step 1 成功]

禁止：
  Recipe A (chain)
    └── Step 1: Recipe B (chain)  ← 嵌套 chain，编译器拒绝
```

## 四、配方 Schema 定义

### 4.1 配方基础结构

```typescript
// ===== 配方类型枚举 =====
type RecipeType =
  | 'threshold_check'
  | 'opposed_check'
  | 'resource_modify'
  | 'random_table'
  | 'initiative'
  | 'growth_check'
  | 'accumulation'
  | 'chain'
  | 'raw';

// ===== 配方顶层结构 =====
interface Recipe {
  id: string;                      // 配方唯一标识，如 "coc7_skill_check"
  type: RecipeType;                // 配方类型
  name: string;                    // 显示名称，如 "COC7版技能检定"
  description?: string;            // 可选描述
  tags?: string[];                 // 可选标签，便于分类

  // 类型特定参数（联合类型，由 type 决定）
  params: RecipeParams;

  // ===== 编译产物（自动生成，用户不直接编辑）=====
  compiled: CompiledGraph;
}

interface CompiledGraph {
  atoms: AtomInstance[];
  connections: Connection[];
  entry_atom_id: string;           // 入口节点
  output_atom_id: string;          // 输出节点
}

// 参数联合类型
type RecipeParams =
  | ThresholdCheckParams
  | OpposedCheckParams
  | ResourceModifyParams
  | RandomTableParams
  | InitiativeParams
  | GrowthCheckParams
  | AccumulationParams
  | ChainParams
  | RawRecipeParams;
```

### 4.2 阈值检定（threshold_check）

覆盖面最广的类型。COC 的 `d100 ≤ 技能值`、DND 的 `d20 + 修正 ≥ DC` 都是它。

```typescript
interface ThresholdCheckParams {
  // ── 骰子 ──
  dice_expression: string;             // "1d100" | "1d20" | "3d6"

  // ── 目标值 ──
  target_source: 'skill' | 'attribute' | 'fixed' | 'formula';
  target_ref?: string;                 // skill/attribute 名称（如 "侦查"、"STR"）
  target_fixed?: number;               // 当 target_source='fixed' 时
  target_formula?: string;             // 当 target_source='formula' 时

  // ── 判定方向 ──
  success_direction: 'lte' | 'gte';    // lte=掷低成功（COC）, gte=掷高成功（DND）

  // ── 修正值（可选，DND 风格）──
  modifier_sources?: ModifierSource[];

  // ── 难度系统（可选）──
  difficulty?: {
    mode: 'divisor' | 'none';
    divisors?: number[];               // [1, 2, 5] = 常规/困难/极难
    default_level?: number;            // 默认难度索引，默认 0；越界时自动夹紧到有效范围末端
  };

  // ── 优势/劣势（可选，DND 风格）──
  advantage_system?: {
    enabled: boolean;
    extra_dice: number;                // 额外骰子数（通常 1）
    keep: 'highest' | 'lowest';
  };

  // ── 成功等级（从上到下匹配，首个命中即最终结果）──
  tiers: SuccessTier[];
}

interface SuccessTier {
  name: string;          // 程序标识："critical" | "extreme" | "hard" | "regular" | "fail" | "fumble"
  label: string;         // 显示名称："大成功"
  condition: string;     // 表达式："roll == 1"、"roll <= target / 5"
  is_success: boolean;   // 是否算作成功
}

interface ModifierSource {
  source: 'attribute_mod' | 'proficiency' | 'fixed' | 'formula';
  ref?: string;          // "DEX_mod"、"proficiency_bonus"
  value?: number;        // source='fixed' 时
  formula?: string;      // source='formula' 时
}
```

### 4.3 对抗检定（opposed_check）

```typescript
interface OpposedCheckParams {
  // 主动方
  attacker: {
    dice_expression: string;
    target_source: 'skill' | 'attribute';
    target_ref: string;
  };
  // 被动方
  defender: {
    dice_expression: string;
    target_source: 'skill' | 'attribute';
    target_ref: string;
  };
  // 对比方式
  resolution: 'tier_compare' | 'value_compare';
  // tier_compare: 比较成功等级（COC，极难 > 困难 > 常规）
  // value_compare: 比较数值大小（DND 竞争检定）

  // 平局处理
  tie_rule: 'attacker_wins' | 'defender_wins' | 'reroll';
  // 当 tie_rule='reroll' 时，最多重掷 3 轮；仍平局则按 defender_wins 收敛
}
```

### 4.4 资源修改（resource_modify）

```typescript
interface ResourceModifyParams {
  resource_ref: string;                // "hp" | "mp" | "san" | 自定义资源 ID

  delta: {
    mode: 'fixed' | 'dice' | 'formula';
    value?: number;                    // fixed 模式
    expression?: string;               // dice: "1d6+2", formula: "level * 2"
  };

  direction: 'decrease' | 'increase';

  // 边界处理
  clamp_min?: number | 'zero';        // 默认 0；当传入 'zero' 时入库规范化为 0
  clamp_max?: 'resource_max' | number;

  // 溢出事件（可选）
  on_zero?: string;                   // 资源归零时触发的事件 ID（先计算并 clamp，再按最终值触发）
  on_overflow?: string;               // 同上：按 clamp 后最终值判断是否触发
}
```

```typescript
interface AccumulationParams {
  dice_expression: string;             // "1d20"

  failure_target: number;              // 3

  critical_success_effect?: string;    // "natural_roll == 20" 时恢复 1HP
```

### 4.9 连锁配方（chain）

```typescript
interface ChainParams {
  steps: ChainStep[];
}

interface ChainStep {
  step_id: string;                     // 步骤标识
  recipe_ref: string;                  // 引用另一个 recipe 的 ID（不允许引用 chain 类型）

  // 输入映射
  input_mapping?: Record<string, string>;

  // 条件执行
  condition?: {
    depends_on: string;                // 依赖的 step_id
    when: 'success' | 'failure' | 'always' | 'expression';
    expression?: string;               // when='expression' 时；可访问所有前序步骤输出 + 当前步骤输入参数
  };
}
```

## 五、运行时修饰符（Runtime Modifiers）

### 5.1 设计原理

Recipe 定义"不变的规则结构"，运行时修饰符定义"本次执行的临时调整"。二者分离，避免 recipe 爆炸。

**行业验证**：海豹骰子 `/ra b2 侦查`、Foundry VTT `2d20kh` 均采用运行时指定修饰符的方式。

### 5.2 修饰符数据结构

```typescript
interface RuntimeModifiers {
  // ── 骰子修饰 ──
  bonus_dice?: number;           // COC 奖励骰数量（1-9）
  penalty_dice?: number;         // COC 惩罚骰数量（1-9）
  advantage?: boolean;           // DND 优势
  disadvantage?: boolean;        // DND 劣势

  // ── 难度修饰 ──
  difficulty_level?: number;     // 难度等级索引（0=常规, 1=困难, 2=极难）
  dc_override?: number;          // 直接指定 DC 值

  // ── 目标值修饰 ──
  target_bonus?: number;         // 目标值加减（如场景修正 -20）
}
```

### 5.3 执行请求变更

```typescript
interface ExecuteRequest {
  ruleset_id: string;
  command: string;                     // "ra"
  params: Record<string, any>;         // { skill: "侦查" }
  context: {
    character_id: string;
    campaign_id: string;
    scene_id?: string;
  };

  // ===== 新增 =====
  runtime_modifiers?: RuntimeModifiers;
}
```

### 5.4 意图解析器扩展

指令中的修饰符前缀由意图解析器提取，转换为 `runtime_modifiers`：

```
输入: "/ra b2 h 侦查"
      ↓ 意图解析器
{
  command: "ra",
  params: { skill: "侦查" },
  runtime_modifiers: {
    bonus_dice: 2,
    difficulty_level: 1       // h = hard = divisors[1]
  }
}
```

解析规则（正则匹配；除 `h/e` 冲突外顺序无关）：

| 前缀 | 正则 | 映射到 |
|------|------|--------|
| `b{n}` | `/b([1-9])/` | `bonus_dice: n` |
| `p{n}` | `/p([1-9])/` | `penalty_dice: n` |
| `h` | `/\bh\b/` | `difficulty_level: 1` |
| `e` | `/\be\b/` | `difficulty_level: 2` |

冲突处理：
- 同一指令同时出现 `b{n}` 与 `p{n}`：返回 `RUNTIME_MODIFIER_CONFLICT` 并拒绝执行。
- 同一指令同时出现 `h` 与 `e`：取最后出现的一个。
- `b{n}` / `p{n}` 的 `n` 仅允许 1-9；超出范围返回 `MODIFIER_OUT_OF_RANGE` 并拒绝执行。
- `advantage=true` 与 `disadvantage=true` 同时出现：相互抵消，按普通掷骰执行。
- COC 修饰符（`bonus_dice/penalty_dice`）与 DND 修饰符（`advantage/disadvantage`）不允许跨体系混用；不属于当前 recipe 体系的修饰符返回 `UNSUPPORTED_MODIFIER` 并拒绝执行。

### 5.5 dice_roll 原子节点扩展

```typescript
// dice_roll 原子执行时，检查 runtime_modifiers
function executeDiceRoll(config: DiceRollConfig, modifiers?: RuntimeModifiers): DiceResult {
  const expr = config.expression;  // "1d100"

  // DND 优势/劣势同时出现时相互抵消
  if (modifiers?.advantage && modifiers?.disadvantage) {
    return standardDiceRoll(expr);
  }

  if (modifiers?.bonus_dice && expr === '1d100') {
    // COC 奖励骰：额外掷 N 个十位骰，取最低十位
    const units = rollDice(1, 10) - 1;          // 0-9 个位
    const tensDice = rollDice(1 + modifiers.bonus_dice, 10);
    const bestTens = Math.min(...tensDice) * 10; // 取最低十位
    const total = bestTens + units;
    return { total, natural_roll: total, rolls: tensDice, units, bonus_applied: true };
  }

  if (modifiers?.penalty_dice && expr === '1d100') {
    // COC 惩罚骰：额外掷 N 个十位骰，取最高十位
    const units = rollDice(1, 10) - 1;
    const tensDice = rollDice(1 + modifiers.penalty_dice, 10);
    const worstTens = Math.max(...tensDice) * 10;
    const total = worstTens + units;
    return { total, natural_roll: total, rolls: tensDice, units, penalty_applied: true };
  }

  if (modifiers?.advantage) {
    // DND 优势：掷 2 次取高
    const roll1 = rollDice(1, 20);
    const roll2 = rollDice(1, 20);
    return { total: Math.max(roll1, roll2), natural_roll: Math.max(roll1, roll2), rolls: [roll1, roll2] };
  }

  if (modifiers?.disadvantage) {
    // DND 劣势：掷 2 次取低
    const roll1 = rollDice(1, 20);
    const roll2 = rollDice(1, 20);
    return { total: Math.min(roll1, roll2), natural_roll: Math.min(roll1, roll2), rolls: [roll1, roll2] };
  }

  // 标准掷骰
  return standardDiceRoll(expr);
}
```

### 5.6 threshold_compare 原子节点扩展

```typescript
function executeThresholdCompare(
  config: ThresholdCompareConfig,
  inputs: { roll: number; target: number },
  modifiers?: RuntimeModifiers
): CompareResult {
  let effectiveTarget = inputs.target;

  // 难度调整
  if (modifiers?.difficulty_level !== undefined && config.difficulty?.divisors) {
    const maxIndex = config.difficulty.divisors.length - 1;
    const level = Math.max(0, Math.min(modifiers.difficulty_level, maxIndex));
    const divisor = config.difficulty.divisors[level] || 1;
    effectiveTarget = Math.floor(inputs.target / divisor);
  }

  // DC 覆盖
  if (modifiers?.dc_override !== undefined) {
    effectiveTarget = modifiers.dc_override;
  } else if (modifiers?.target_bonus) {
    // 仅在未提供 dc_override 时应用目标值加减
    effectiveTarget += modifiers.target_bonus;
  }

  // 遍历 tiers 匹配
  for (const tier of config.tiers) {
    const ctx = { roll: inputs.roll, target: effectiveTarget, natural_roll: inputs.roll };
    if (evaluateExpression(tier.condition, ctx)) {
      return {
        success: tier.is_success,
        tier: tier.name,
        tier_label: tier.label,
        roll: inputs.roll,
        target: effectiveTarget,
        original_target: inputs.target
      };
    }
  }

  // 兜底：全部未命中时返回失败并标记告警
  return {
    success: false,
    tier: 'fail',
    tier_label: '失败（兜底）',
    roll: inputs.roll,
    target: effectiveTarget,
    original_target: inputs.target,
    warning_code: 'NO_TIER_MATCHED'
  };
}
```

## 六、表达式语言（Recipe DSL）

### 6.1 选型决策

使用 **`expr-eval`** 库（npm: `expr-eval`），不自研。

理由：
- 轻量无依赖，gzip < 10KB
- 支持自定义函数注册
- 沙箱执行，无 `eval()` 风险
- 社区成熟，维护活跃

骰子表达式解析使用独立的 **dice parser** 模块，与 expr-eval 组合。

### 6.2 语法元素

| 类别 | 语法 | 示例 |
|------|------|------|
| 骰子字面量 | `NdM`, `NdMkh/kl` | `1d100`, `3d6`, `2d10kh1` |
| 数字 | 整数/小数 | `10`, `0.5` |
| 变量 | 标识符/路径 | `roll`, `target`, `natural_roll`, `total` |
| 角色卡引用 | `skill.X`, `attr.X`, `resource.X` | `skill.侦查`, `attr.STR` |
| 算术 | `+`, `-`, `*`, `/`, `%` | `target / 5` |
| 比较 | `==`, `!=`, `<`, `<=`, `>`, `>=` | `roll <= target` |
| 逻辑 | `&&`, `\|\|`, `!` | `roll >= 96 && target < 50` |
| 括号 | `()` | `(attr.CON + attr.SIZ) / 10` |
| 函数 | `floor`, `ceil`, `round`, `min`, `max`, `abs` | `floor(target / 2)` |

### 6.3 上下文变量表

| 使用位置 | 可用变量 |
|---------|---------|
| `tiers[].condition` | `roll`, `natural_roll`, `total`, `target`, `DC` |
| `target_formula` | `attr.*`, `skill.*`, `resource.*` |
| `modifier_sources[].formula` | `attr.*`, `level`, `proficiency_bonus` |
| `chain.condition.expression` | `steps.<step_id>.result.*`, `input.*` |
| `growth_check.check_condition` | `roll`, `current_value` |

### 6.4 安全约束

- 表达式最大长度：256 字符
- 函数白名单：`floor`, `ceil`, `round`, `min`, `max`, `abs`
- 变量引用深度：最多 3 层（`resource.hp.max`）
- 禁止：字符串操作、赋值、循环、外部函数调用
- `condition` 表达式必须返回布尔值；非布尔结果视为配置错误并中断该 recipe 执行
- 表达式求值错误（未定义变量、语法错误）或结果为 `NaN/Infinity` 时，视为执行错误并中断该 recipe 执行

## 七、Recipe → Atoms 编译器

### 7.1 策略模式架构

```typescript
// 编译器接口
interface RecipeCompiler<T extends RecipeType = RecipeType> {
  type: T;
  compile(recipe: Recipe): CompiledGraph;
  validate(recipe: Recipe): ValidationResult;
}

// 编译器注册表
class CompilerRegistry {
  private compilers = new Map<RecipeType, RecipeCompiler>();

  register<T extends RecipeType>(compiler: RecipeCompiler<T>): void {
    this.compilers.set(compiler.type, compiler);
  }

  compile(recipe: Recipe): CompiledGraph {
    const compiler = this.compilers.get(recipe.type);
    if (!compiler) {
      throw new EngineError('UNKNOWN_RECIPE_TYPE', `No compiler for: ${recipe.type}`);
    }
    const validation = compiler.validate(recipe);
    if (!validation.valid) {
      throw new EngineError('RECIPE_VALIDATION_FAILED', validation.errors.join('; '));
    }
    return compiler.compile(recipe);
  }
}

// 全局注册
const registry = new CompilerRegistry();
registry.register(new ThresholdCheckCompiler());
registry.register(new OpposedCheckCompiler());
registry.register(new ResourceModifyCompiler());
registry.register(new RandomTableCompiler());
registry.register(new InitiativeCompiler());
registry.register(new GrowthCheckCompiler());
registry.register(new AccumulationCompiler());
registry.register(new ChainCompiler());
registry.register(new RawCompiler());
```

```
│                                                           │
│  [target_reader] ──→ [difficulty_adjust]* ──┐             │

```

```
       ↓ compile（递归编译每个子步骤的 recipe）

[step1.compiled_graph]
       ↓ result
[if_else: condition?] ──match──→ [step2.compiled_graph]
                       ──else──→ [step3.compiled_graph]
                                        ↓
                                  [result_collector]
```

### 7.4 命名空间规则

每个 recipe 的 atom ID 带命名空间前缀，避免合并时冲突：

```
格式：{recipe_id}__{atom_name}
chain 子步骤：{chain_id}__{step_id}__{atom_name}

示例：
  coc7_skill_check__dice
  coc7_skill_check__compare
  coc7_san_check__check__dice
  coc7_san_check__failure_loss__resource_mod
```

### 7.5 编译缓存策略

- **编译时机**：Recipe 保存时立即编译，编译产物持久化到 `recipe.compiled` 字段
- **运行时**：直接读取 `compiled`，不重复编译
- **失效条件**：满足任一条件即重新编译：`params` 变更、编译器版本变更、DSL 函数白名单/规则变更
- **规则包加载**：从数据库加载规则包时，所有 recipe 的 compiled 已就绪，无需运行时编译
- **热加载**：规则包更新时，后端重新编译受影响的 recipe，替换内存缓存

### 12.2 导入规则

| 输入格式 | 识别方式 | 处理 |
|---------|---------|------|
| Recipe JSON（含 type + params） | 检查 `type` 字段存在 | 重新编译，生成 compiled |
| Raw Atoms JSON（含 atoms + connections） | 检查 `atoms` 数组存在 | 作为兼容导入格式处理，包装为 `type: "raw"` 的 recipe |
| 无法识别 | — | 返回错误 |

> 默认推荐使用 Recipe JSON。Raw Atoms JSON 仅作为兼容层保留，用于高级用户和旧数据迁移场景，不作为常规编辑产物。

版本字段格式约束：
- `version` 必须为 `major.minor` 数字格式（示例：`1.0`）。
- 非数字格式（如 `v1`、`latest`、`1.0.0-beta`）返回 `INVALID_VERSION_FORMAT` 并拒绝导入。

版本兼容规则：
- 主版本（major）高于服务端支持版本：拒绝导入，返回 `VERSION_UNSUPPORTED`。
- 主版本一致但次版本（minor）更高：允许导入；记录 `MINOR_VERSION_DOWNLEVEL`，并忽略未知字段。
- 未知字段处理：忽略并记录 `UNKNOWN_FIELDS_IGNORED`。

最小错误码集合（V1.0）：
- `UNKNOWN_RECIPE_TYPE`

## 十三、决策记录

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D-01 | 存储策略 | 双层：Recipe（源）+ atoms（编译产物） | 用户可回到表单继续编辑 |
| D-02 | 配方类型范围 | 8+1 种通用类型 | 覆盖 COC/DND/FATE 等主流系统 |
| D-03 | Chain 嵌套 | 限制 1 层，不允许 chain 嵌套 chain | 复杂流程打包为独立规则 |
| D-04 | 国际化 | MVP 只做中文，字段预留 `_i18n` 后缀 | 用户群全中文，阶段二再做 |
| D-05 | Recipe 版本 | 复用规则包版本机制，不单独做 | Recipe 是规则包的组成部分 |
| D-06 | 社区模板 | MVP 官方 15 个，阶段一开放社区 | 需审核和质量控制配套 |
| D-07 | 编译器架构 | 策略模式 + 注册机制，MVP 即采用 | 低成本高回报 |
| D-08 | 表达式引擎 | expr-eval（不自研）+ 独立 dice parser | 成熟安全，扩展性好 |
| D-09 | 编译缓存 | 保存时编译，运行时直接读取 compiled | 参考 QLExpress 指令集缓存 |
| D-10 | 奖励骰/惩罚骰 | runtime_modifiers 注入，非 recipe 定义 | 参考海豹骰子，修饰符与规则分离 |
| D-11 | 孤注一掷 | MVP 不实现 | 参考海豹骰子，由 KP/玩家口头协商 |
| D-12 | 幸运消费 | MVP 不实现 | 同上 |
| D-13 | 热加载 | P1 实现，规则包更新时重编译 + WebSocket 通知 | 参考 Ice 秒级热加载 |
| D-14 | 导入版本兼容 | major 超前拒绝；同 major 高 minor 允许并记录告警 | 保证兼容边界可预期，避免静默错误 |
| D-15 | 错误与告警码 | 固化最小错误码/告警码集合，供前后端共享 | 便于 i18n、监控聚合和稳定契约 |
| D-16 | 导入校验与事务 | 结构校验类型级、关联校验记录级；记录级独立事务 | 在数据完整性与可用性间取得平衡 |
| D-17 | 错误契约统一 | 引入 EngineErrorCode + FailedStage（含 import）；新增导入扩展码与版本格式错误码 | 消除模块间“字符串自由定义”导致的契约漂移 |

## 十四、规则数据批量导入（Static Data Import）

### 14.1 规则逻辑 vs 规则数据

| 维度 | 规则逻辑（Recipe） | 规则数据（Static Data） |
|------|------------------|----------------------|
| 本质 | "检定怎么判定" | "侦查默认值是 25%" |
| 数量 | 少（每规则包 10-20 个） | 大（职业 200+、技能 100+、武器几十种） |
| 存储 | `rulesets.recipes` | 独立数据表（附录 E） |
| 编辑方式 | 表单 / 模板 | JSON 批量导入 |
| 是否含逻辑 | 是（编译为原子图） | 否（纯数值和标识符） |
| 引擎如何使用 | 编译 → 执行 | 运行时查表读取 |

规则数据随规则包一起分发，但存储在独立的数据表中。一个 COC 7th 规则包发布时，连带的数据包括：200+ 职业定义、100+ 技能定义、数十种武器/物品、若干随机表。

### 14.2 导入文件格式

每个规则包可附带一个 **规则数据包**（Rule Data Bundle），格式为单个 JSON 文件：

```typescript
interface RuleDataBundle {
  // 元信息
  meta: {
    ruleset_id: string;          // 关联的规则包 ID
    version: string;             // 数据版本
    data_version: string;        // 数据包版本（独立于规则包版本）
    source?: string;             // 数据来源（如 "COC 7th 守秘人手册"）
  };

  // 四类数据（均为数组，可选）
  skills?: SkillData[];
  occupations?: OccupationData[];
  items?: ItemData[];
```


### 14.4 职业数据（OccupationData）

COC 7th 有 200+ 个职业，每个职业定义本职技能、技能点公式、信用评级范围。

```typescript
interface OccupationData {
  occupation_id: string;         // "private_detective"
  name: string;                  // "私家侦探"
  name_en?: string;              // "Private Detective"
  description?: string;          // 职业描述

  // 技能点公式
  skill_point_formula: string;   // 规则包 DSL 字符串表达式，如 "EDU * 2 + STR * 2"、"EDU * 4"
  // 注意：此处固定使用 recipe DSL 字符串表达式，由 expr-eval 求值，不改为 AST 或预置公式 ID。
  // 当存在“二选一”语义时，使用显式函数表达（如 max(a, b)），不使用 || 作为业务语义。

  // 信用评级范围
  credit_rating: {
    min: number;                 // 9
    max: number;                 // 30
  };

  // 本职技能
  occupation_skills: OccupationSkillBinding[];

  // 默认装备（可选）
  starting_equipment?: string[]; // item_id 列表

  // 时代适用性（可选）
  era?: string[];                // ["1920s", "modern"]（不填则通用）
}

interface OccupationSkillBinding {
  // 三种绑定方式

  // 方式1：固定技能
  skill_id?: string;             // "spot_hidden"

  // 方式2：从分类中选
  choose_from_category?: {
    category: SkillCategory;
    count: number;               // 选几个
  };

  // 方式3：从列表中选
  choose_from_list?: {
    skills: string[];            // skill_id 列表
    count: number;
  };

  // 方式4：任意个人兴趣技能
  any_personal?: {
    count: number;
  };
}
```

### 14.5 物品/武器数据（ItemData）

COC 7th 的武器有特殊属性：伤害、射程、攻击次数、弹容量、故障值等。

```typescript
interface ItemData {
  item_id: string;               // "colt_45_auto"
  name: string;                  // ".45自动手枪"
  name_en?: string;              // "Colt .45 Auto"
  category: ItemCategory;

  // 通用属性
  description?: string;
  weight?: number;               // 重量，统一以千克（kg）存储
  cost?: string;                 // 价格描述

  // 武器专属属性（category = 'melee_weapon' | 'ranged_weapon'）
  weapon?: WeaponProperties;

  // 护甲专属属性（category = 'armor'）
  armor?: ArmorProperties;

  // 自由扩展
  properties?: Record<string, any>;

  era?: string[];                // ["1920s", "modern"]
}

type ItemCategory =
  | 'melee_weapon'      // 近战武器
  | 'ranged_weapon'     // 远程武器
  | 'thrown_weapon'     // 投掷武器
  | 'armor'            // 护甲
  | 'consumable'       // 消耗品
  | 'tool'             // 工具
  | 'special'          // 特殊物品
  | 'other';

interface WeaponRange {
  unit: 'm' | 'ft';
  type: 'single' | 'multi';
  value?: number;                // 单段射程，如 15m
  ranges?: number[];             // 多段射程，如 [10, 20, 50]
}

interface AttackRate {
  base_attacks: number;          // 基础每轮攻击次数，如 1
  burst_count?: number;          // 连射/额外发数，如 3 表示 1(3)
}

interface WeaponProperties {
  damage: string;                // 骰子表达式："1d10+2"、"1d3+db"（db=伤害加值）
  base_range?: WeaponRange;      // 基础射程（远程），结构化表示，供战斗引擎直接消费

  ammo_capacity?: number;        // 弹容量（远程）
  malfunction?: number;          // 故障值：100 表示不会故障，96 表示掷出 96+ 故障
  skill_id: string;              // 使用此武器关联的技能 ID

  min_str?: number;              // 最低力量要求
  is_two_handed?: boolean;       // 是否双手武器
}

interface ArmorProperties {
  armor_points: number;          // 护甲值
  penalty_dex?: number;          // DEX 惩罚
  penalty_stealth?: boolean;     // 潜行惩罚
}
```

### 14.8 导入行为规则

| 规则 | 说明 |
|------|------|
| **幂等性** | 按 `*_id` 匹配，存在则更新，不存在则新建 |
| **事务性** | 按记录独立事务提交；单条失败不影响同类型其他记录，也不影响其他类型 |
| **校验优先** | 混合策略：先做结构校验（类型级）；结构校验失败则该类型全部跳过。通过结构校验后执行关联校验（记录级）；关联校验失败仅跳过该记录 |
| **冲突字段处理** | `skills.base_value` 与 `base_formula` 同时存在时，保留 `base_formula`、忽略 `base_value`，并在导入报告记录 warning |
| **单位换算** | 重量导入源为 lb 时统一换算为 kg 存储，按 `kg = lb * 0.45359237` 并四舍五入保留 1 位小数 |
| **权限** | 规则包作者、具有编辑权限的协作者、平台管理员可导入；所有导入行为写入审计日志 |
| **版本追踪** | 导入时记录 `data_version`，支持判断"数据是否需要更新" |
| **关联校验** | 职业引用的 `skill_id` 必须在 skills 数据中存在（同一导入包或数据库已有）；若缺失，则该职业记录校验失败并跳过，其他职业与其他数据类型继续导入 |

### 14.10 与 Recipe 系统的关系

规则数据和 Recipe 的协作关系：

```
用户输入 "/ra 侦查"
         ↓
意图解析器提取 skill = "侦查"
         ↓
执行器查找 recipe "coc7_skill_check"
         ↓
执行 character_skill_reader 原子：
  → 从 skill_definitions 查到 "侦查" 的 skill_id = "spot_hidden"
  → 从角色卡读取 skills["spot_hidden"] = 50
         ↓
执行 dice_roll 原子：掷 1d100 = 23
         ↓
执行 threshold_compare 原子：23 <= 50 → 成功
         ↓
返回："侦查检定：成功（23/50）"
```

```
用户创建角色卡，选择职业"私家侦探"
         ↓
前端调用 occupation_apply 原子（附录 F 已定义）：
  → 从 occupation_definitions 查到 "private_detective"
  → 计算技能点：EDU * 2 + max(STR * 2, DEX * 2)
  → 绑定本职技能列表
  → 返回给前端分配界面
```

**关键点**：`skill_definitions` 中的 `aliases` 字段解决了"用户输入中文技能名 → 匹配到 skill_id"的问题。当用户输入 `/ra 侦查` 时，`character_skill_reader` 原子通过 aliases 查表，将 "侦查" 映射到 `spot_hidden`，再从角色卡读取对应值。

## 十六、规则执行总链路（Rule Execution Pipeline）

> **定位**：本章是全系统执行行为的单一权威定义。步骤 2（编译缓存）、步骤 3（修饰符优先级）、步骤 4（消息权限）均以本章定义的阶段名和字段口径为准，不得在本章以外重新定义。

### 16.1 链路总览

```
┌─────────────────────────────────────────────────────────────────┐
│                     Rule Execution Pipeline                     │
│                                                                 │
│  用户输入                                                        │
│    │                                                            │
│  ①  指令文本解析（IntentParse）                                  │
│    │ → ParsedIntent                                             │
│  ②  指令匹配与验证（CommandMatch）                               │
│    │ → MatchedCommand                                           │
│  ③  修饰符提取与校验（ModifierExtract）                          │
│    │ → NormalizedModifiers                                      │
│  ④  Recipe 定位（RecipeLookup）                                 │
│    │ → CompiledGraph                                            │
│  ⑤  上下文装载（ContextLoad）                                   │
│    │ → ExecutionContext                                         │
│  ⑥  节点图执行（GraphExecute）                                  │
│    │ → NodeExecutionLog[]                                       │
│  ⑦  结果归集与日志落库（ResultCollect）                          │
│    │ → ExecuteResponse                                         │
│  调用方                                                          │
└─────────────────────────────────────────────────────────────────┘
```

### 16.2 各阶段定义

#### ① 指令文本解析（IntentParse）

| 项目 | 内容 |
|------|------|
| **输入** | 用户原始文本字符串（如 `/ra b2 h 侦查`） |
| **处理** | 分词、前缀识别、参数提取 |
| **阶段产物** | `ParsedIntent`（见下） |
| **失败条件** | 文本为空；无法识别任何指令前缀 |
| **失败处理** | 中断；返回 `failed_stage: 'intent_parse'`，`error_code: 'INTENT_PARSE_FAILED'` |

```typescript
interface ParsedIntent {
  raw_text: string;           // 原始输入
  command_name: string;       // 如 "ra"
  raw_params: string[];       // 分词后的参数序列，如 ["b2", "h", "侦查"]
  raw_modifiers: string[];    // 识别出的修饰符原文，如 ["b2", "h"]
}
```

#### ② 指令匹配与验证（CommandMatch）

| 项目 | 内容 |
|------|------|
| **输入** | `ParsedIntent` + 当前规则包（`RulesetPackage`） |
| **处理** | 按优先级顺序匹配：`custom_commands` → 平台预置且在 `supported_commands` 中声明的指令 → 平台通用指令 |
| **阶段产物** | `MatchedCommand`（见下） |
| **失败条件** | 无匹配；当前规则包未声明该指令；指令 `gm_only: true` 但调用者非 GM |
| **失败处理** | 中断；`failed_stage: 'command_match'`，对应 `error_code: 'COMMAND_NOT_FOUND'` / `'COMMAND_NOT_SUPPORTED'` / `'PERMISSION_DENIED'` |

```typescript
interface MatchedCommand {
  command_name: string;
  recipe_id: string;              // 最终关联的 recipe 标识
  input_mapping: Record<string, string>;  // 参数名 → 提取值
  merge_config: MergedCommandConfig;      // 平台默认 + 规则包 override 合并后的配置
}
```

#### ③ 修饰符提取与校验（ModifierExtract）

| 项目 | 内容 |
|------|------|
| **输入** | `MatchedCommand.merge_config` + `ParsedIntent.raw_modifiers` |
| **处理** | 将原始修饰符字符串规范化为 `NormalizedModifiers`；校验值域与冲突 |
| **阶段产物** | `NormalizedModifiers`（见下） |
| **失败条件** | 修饰符值超范围；`b/p` 同时存在；`advantage_system` 未启用但出现 advantage/disadvantage |
| **失败处理** | 中断；`failed_stage: 'modifier_extract'`，见第十六章错误码表 |

```typescript
interface NormalizedModifiers {
  bonus_dice?: number;            // b1–b9，与 penalty_dice 互斥
  penalty_dice?: number;          // p1–p9，与 bonus_dice 互斥
  difficulty_level?: number;      // 0 起，越界时自动夹紧到 divisors 有效末端
  dc_override?: number;           // 覆盖目标值
  target_bonus?: number;          // 叠加到目标值（低于 dc_override 优先级）
  advantage?: boolean;            // 与 disadvantage 同时出现时相互抵消
  disadvantage?: boolean;
}
```

> **冲突规则**：`b` 与 `p` 同时存在 → 语法错误，立即中断；`advantage` 与 `disadvantage` 同时存在 → 相互抵消，两者置 false，记录 `warning_code: MODIFIER_IGNORED`。  
> **详细冲突优先级**在步骤 3（§ 十七）中完整定义，本节仅描述中断点。

#### ④ Recipe 定位（RecipeLookup）

| 项目 | 内容 |
|------|------|
| **输入** | `MatchedCommand.recipe_id` + `ruleset_id` |
| **处理** | 1. 查询缓存表（`recipe_compiled_cache`）中是否存在有效编译产物；2. 若缓存命中，直接返回；3. 若缓存未命中，触发按需编译（见步骤 2，§ 十七） |
| **阶段产物** | `CompiledGraph`（`{ atoms, connections, entry_atom_id, output_atom_id }`） |
| **失败条件** | `recipe_id` 不存在；编译产物加载失败；图结构非法（环路、缺入口/出口节点） |
| **失败处理** | 中断；`failed_stage: 'recipe_lookup'`，`error_code: 'RECIPE_NOT_FOUND'` / `'RECIPE_VALIDATION_FAILED'` |

#### ⑤ 上下文装载（ContextLoad）

| 项目 | 内容 |
|------|------|
| **输入** | `ExecuteRequest.context`（`character_id`、`campaign_id`、`scene_id`） |
| **处理** | 读取角色卡、规则包版本、团信息；验证角色卡与规则包版本兼容性 |
| **阶段产物** | `ExecutionContext`（见下） |
| **失败条件** | 角色卡不存在；角色卡与规则包不兼容；必要字段缺失（如技能值不存在） |
| **失败处理** | 中断；`failed_stage: 'context_load'`，`error_code: 'MISSING_CHARACTER_DATA'` |

```typescript
interface ExecutionContext {
  character: CharacterCard;
  ruleset: RulesetPackage;
  campaign_id: string;
  scene_id?: string;
  caller_role: 'gm' | 'player' | 'system';
}
```

#### ⑥ 节点图执行（GraphExecute）

| 项目 | 内容 |
|------|------|
| **输入** | `CompiledGraph` + `ExecutionContext` + `NormalizedModifiers` + `MatchedCommand.input_mapping` |
| **处理** | 拓扑排序节点 → 顺序执行每个原子节点（纯函数）→ 将输出传递到下游节点；`runtime_modifiers` 在执行开始前注入参数覆盖 |
| **阶段产物** | `NodeExecutionLog[]` |
| **失败条件** | 节点执行抛出异常；DSL 表达式返回非布尔值（condition 节点）；表达式求值得 NaN/Infinity；超时（单节点 `>500ms`） |
| **失败处理** | 中断当前链路；`failed_stage: 'graph_execute'`；已执行节点的日志**必须保留**并包含在响应中 |
| **重要约束** | 同一次执行内随机数来源固定（不可重用已用随机数）；不重试，失败即中断 |

```typescript
interface NodeExecutionLog {
  node_id: string;
  node_type: string;
  input: Record<string, any>;
  output: Record<string, any>;
  duration_ms: number;
  status: 'success' | 'skipped' | 'failed';
  error_code?: EngineErrorCode;
  error_message?: string;
}
```

#### ⑦ 结果归集与日志落库（ResultCollect）

| 项目 | 内容 |
|------|------|
| **输入** | `NodeExecutionLog[]` + `ExecutionContext` |
| **处理** | 从 `output_atom_id` 节点提取最终输出；归集日志；写入聊天消息（含 `dice_result` 结构）；异步落入执行日志表 |
| **阶段产物** | `ExecuteResponse` |
| **失败条件** | 输出节点日志缺失（极端情况） |
| **失败处理** | 记录系统告警；返回部分日志和 `error_code: 'RESULT_COLLECT_FAILED'` |

## 十七、编译缓存与失效策略（Compile Cache & Invalidation）

> **定位**：本章依赖 § 十六 定义的 `FailedStage`（`compile`、`validate`）、`ExecuteResponse` 和 `RecipeLookup` 阶段。本章只定义编译何时发生、何时可复用、何时失效，不修改 § 十六 的阶段顺序。

### 17.1 编译哈希（Compile Hash）

编译缓存以 `compiled_hash` 作为缓存键。只有参与哈希的字段变更才触发重编译。

#### 参与哈希的字段

| 字段 | 说明 |
|------|------|
| `recipe.type` | 配方类型 |
| `recipe.params`（序列化后） | 所有业务参数，JSON 字符串规范化（key 排序后序列化） |
| `compiler_version` | 编译器版本字符串（平台内置，随平台升级变更） |
| `dsl_whitelist_version` | DSL 白名单规则版本（每次白名单更新递增） |
| `parent_recipe_ids`（有序列表） | 继承链上所有祖先 recipe 的 `id + version`，从近到远排列 |

#### 不参与哈希的字段

| 字段 | 原因 |
|------|------|
| `recipe.name` | 仅展示，不影响执行 |
| `recipe.description` | 仅展示 |
| `recipe.tags` | 仅分类 |
| `recipe.id` | 标识符本身，不影响编译逻辑 |
| `meta.display_name` | 展示字段 |

### 17.2 编译触发条件

以下任一条件满足，必须重新编译（不得复用缓存）：

| 触发条件 | 说明 |
|---------|------|
| `recipe.params` 任意字段变更 | 包括新增、删除、修改 |
| `recipe.type` 变更 | 类型变更导致编译函数不同 |
| `compiler_version` 升级 | 平台编译器逻辑变更 |
| `dsl_whitelist_version` 升级 | DSL 规则扩展或收紧 |
| 继承链上任一祖先 recipe 触发重编译 | 子包缓存连带失效 |
| 热加载规则包（`ruleset hot reload`） | 重新编译该规则包内所有 recipe |

以下变更**不触发**重编译，直接更新元数据即可：

| 不触发重编译的变更 |
|-----------------|
| `recipe.name`、`description`、`tags` 变更 |
| 仅修改 `command.description`（指令说明文案） |
| 仅修改 `meta.display_name` |

### 17.3 缓存命中规则

查询 `recipe_compiled_cache` 时，满足以下**全部条件**才算命中：

1. `ruleset_id` + `recipe_id` 存在记录
2. `compiled_hash` 与当前计算结果一致
3. `cache_status = 'valid'`（未被手动失效）
4. 若存在继承链，所有祖先的 `compiled_hash` 均未变更

命中时直接返回 `CompiledGraph`，跳过编译步骤。

### 17.4 缓存失效与重算

#### 主动失效触发

| 事件 | 失效范围 |
|------|---------|
| recipe params 变更 | 当前 recipe 及所有继承它的子 recipe |
| 平台发布新编译器版本 | 全量失效（可分批延迟重编译） |
| 规则包热加载 | 该规则包内所有 recipe |
| 管理员手动触发失效 | 指定 recipe 或指定规则包全量 |

#### 失效后处理

- 失效后将 `cache_status` 置为 `'invalid'`，不删除记录（保留 `compiled_at` 等审计字段）
- 下次执行时在 `RecipeLookup` 阶段发现 `cache_status = 'invalid'`，触发按需编译
- 按需编译成功后更新记录；失败时 `cache_status` 置 `'compile_failed'`，保留旧版本（见 §17.5）

### 17.5 编译失败回退策略

编译失败分三个场景，处理方式不同：

| 场景 | 行为 |
|------|------|
| **预览编译失败**（编辑器中实时预览） | 前端展示编译错误详情；不影响已保存的生产版本；`failed_stage: 'compile'` |
| **保存时编译失败** | 拒绝保存；返回 `error_code: 'RECIPE_VALIDATION_FAILED'` 或 `'UNKNOWN_RECIPE_TYPE'`；现有生产缓存保持不变 |
| **运行时按需编译失败**（缓存失效后执行时触发） | 中断本次执行；返回 `failed_stage: 'recipe_lookup'`，`error_code: 'RECIPE_VALIDATION_FAILED'`；不回退到旧缓存（旧缓存已标记 `invalid`，用旧缓存会产生语义歧义） |

> **原则**：宁可执行失败，不使用语义已失效的旧编译产物。

### 17.6 编译产物存储结构

```typescript
interface RecipeCompiledCache {
  id: string;                        // 主键
  ruleset_id: string;
  recipe_id: string;
  compiled_hash: string;             // SHA-256，基于 §17.1 参与字段计算
  compiled_graph: CompiledGraph;     // atoms + connections + entry/output atom id
  cache_status: 'valid' | 'invalid' | 'compile_failed';
  compiler_version: string;          // 编译时的平台编译器版本
  dsl_whitelist_version: string;     // 编译时的 DSL 白名单版本
  source_recipe_version: string;     // 对应 recipe 的版本号（major.minor 格式）
  compiled_at: string;               // ISO 8601
  invalidated_at?: string;           // 失效时间，null 表示未失效
  invalidation_reason?: string;      // 'params_changed' | 'compiler_upgrade' | 'hot_reload' | 'manual'
}
```

```sql
-- 唯一索引：同一 ruleset+recipe 只保留最新一条有效缓存
CREATE UNIQUE INDEX uk_recipe_cache ON recipe_compiled_cache (ruleset_id, recipe_id);
-- 查询索引：按哈希快速定位
CREATE INDEX idx_recipe_cache_hash ON recipe_compiled_cache (compiled_hash);
```

### 17.7 版本格式约束

- `source_recipe_version` 固定为 `major.minor` 数字格式（如 `"1.2"`）
- 非数字格式在编译时拒绝，返回 `error_code: 'INVALID_VERSION_FORMAT'`
- `major` 超前（当前平台不支持）拒绝编译，返回 `error_code: 'VERSION_UNSUPPORTED'`
- 同 `major` 高 `minor` 允许编译，记录 `warning_code: 'MINOR_VERSION_DOWNLEVEL'`

## 十八、运行时修饰符与异常边界（Runtime Modifiers & Error Boundaries）

> **定位**：本章依赖 § 十六 的 `ModifierExtract` 阶段、`NormalizedModifiers` 接口、`GraphExecute` 阶段，以及 § 十七 的编译缓存规则。本章完整定义修饰符解析细则和节点/链路失败边界，供步骤 4（消息权限）引用"异常时的一致性"策略。

### 18.1 修饰符解析规则

#### 原始输入格式

修饰符从 `ParsedIntent.raw_modifiers` 中提取，格式为字符串列表（如 `["b2", "h", "e"]`）。

| 修饰符原文 | 映射字段 | 示例 |
|-----------|---------|------|
| `b{n}`（n=1–9） | `bonus_dice = n` | `b2` → `bonus_dice: 2` |
| `p{n}`（n=1–9） | `penalty_dice = n` | `p1` → `penalty_dice: 1` |
| `h` | `difficulty_level = 1`（困难） | — |
| `e` | `difficulty_level = 2`（极难） | — |
| `dc={n}` | `dc_override = n` | `dc=15` → `dc_override: 15` |
| `+{n}` / `-{n}` | `target_bonus = ±n` | `+5` → `target_bonus: 5` |
| `adv` | `advantage = true` | — |
| `dis` | `disadvantage = true` | — |

#### 缺省值规则

未出现的修饰符字段**不注入**（保持 `undefined`），由各原子节点使用自身默认值，不在修饰符层设默认值。唯一例外：`difficulty_level` 未指定时，`threshold_compare` 使用 `default_level`（见 § 四 §4.2）。

### 18.2 修饰符值域与冲突规则

| 规则 | 处理方式 | 错误码 |
|------|---------|--------|
| `bonus_dice` / `penalty_dice` 值域 1–9 | 超出范围中断 | `MODIFIER_OUT_OF_RANGE` |
| `b` 与 `p` 同时出现 | 立即中断，不执行 | `RUNTIME_MODIFIER_CONFLICT` |
| `h` 与 `e` 同时出现 | 取**最后出现**者；记录 `MODIFIER_IGNORED` 告警 | 不中断 |
| `advantage` 与 `disadvantage` 同时出现 | 两者均置 `false`，相互抵消；记录 `MODIFIER_IGNORED` 告警 | 不中断 |
| `dc_override` 与 `target_bonus` 同时出现 | `dc_override` 优先；`target_bonus` 被忽略；记录 `MODIFIER_IGNORED` 告警 | 不中断 |
| 规则体系不支持该修饰符（如 COC 规则包出现 `advantage`） | 中断 | `UNSUPPORTED_MODIFIER` |
| `difficulty_level` 越界（超过 divisors 有效末端） | 自动夹紧到有效末端；记录 `MODIFIER_IGNORED` 告警 | 不中断 |

### 18.3 修饰符优先级顺序

在原子节点执行前，`runtime_modifiers` 注入参数按以下顺序生效（后者不覆盖前者，仅各自独立注入）：

```
1. dc_override         → 直接覆盖目标值（最高优先级）
2. target_bonus        → 叠加到目标值（dc_override 存在时忽略）
3. difficulty_level    → 决定 divisors 分级系数
4. bonus_dice / penalty_dice → 影响骰子池逻辑
5. advantage / disadvantage → 影响保留最高/最低骰
```

> `dc_override` 与 `target_bonus` 的优先级关系：两者描述"目标值如何确定"，语义互斥。`dc_override` 是绝对值替换，`target_bonus` 是相对值叠加；同时出现时 `dc_override` 完全覆盖，`target_bonus` 无效。

### 18.4 节点失败边界

#### 单节点失败

| 情况 | 行为 |
|------|------|
| 节点抛出异常 | 中断链路；`failed_stage: 'graph_execute'`；`failed_node_id` 为该节点 `id` |
| DSL `condition` 返回非布尔值 | 中断；`error_code: 'DSL_NON_BOOLEAN_CONDITION'` |
| 表达式求值得 `NaN` / `Infinity` | 中断；`error_code: 'DSL_EVAL_ERROR'` |
| 节点执行超时（>500ms） | 中断；`error_code: 'EXPRESSION_TIMEOUT'` |

#### 节点失败后日志保留规则

**已成功执行的节点日志必须保留**，包含在 `ExecuteResponse.logs` 中，`status: 'success'`。  
失败节点日志也必须返回，`status: 'failed'`，含 `error_code` 和 `error_message`。  
失败后未执行的节点**不在 logs 中出现**（不写入 `status: 'skipped'` 占位）。

```typescript
// 失败时的完整响应示例
{
  success: false,
  output: undefined,
  logs: [
    { node_id: "get_skill", status: "success", output: { value: 50 }, ... },
    { node_id: "dice",      status: "success", output: { total: 23 }, ... },
    { node_id: "compare",   status: "failed",  error_code: "DSL_EVAL_ERROR", ... }
    // "output" 节点未执行，不出现在 logs
  ],
  warnings: [],
  failed_stage: "graph_execute",
  error_code: "DSL_EVAL_ERROR",
  failed_node_id: "compare"
}
```

### 18.5 Chain 步骤失败边界

Chain 类型 recipe 的每个 step 本质是一次独立 `RecipeLookup` + `GraphExecute`。

| 情况 | 行为 |
|------|------|
| step N 失败 | 中断后续所有 step；`failed_node_id` 指向 step N 中失败的原子节点 |
| step N 依赖的前序步骤输出不存在 | 中断；`error_code: 'STEP_RESULT_UNAVAILABLE'` |
| step N 条件为 `false`（跳过） | `status: 'skipped'`；不中断；后续 step 按各自条件继续评估 |
| chain expression 变量引用不存在的 step 输出 | 中断；`error_code: 'STEP_RESULT_UNAVAILABLE'` |

> chain 的 `expression` 可访问所有**已完成步骤**的输出（`steps.<step_id>.result.*`）和当前步骤的输入参数（`input.*`）。访问尚未执行的步骤输出视为 `STEP_RESULT_UNAVAILABLE`。

### 18.6 随机数与重试约束

- 同一次 `ExecuteRequest` 内所有骰子的随机数来源固定，不跨次复用
- **不重试**：节点失败即中断，不自动重试同一节点
- 重试是上层调用方的职责（用户重新输入指令），执行器无重试逻辑
- 所有 `dice_roll` 节点的原始 `rolls` 数组**必须**记录在 `NodeExecutionLog.output` 中，供结果展示和审计

- [x] 所有冲突场景处理方式明确（中断/告警/抵消/夹紧）

### 19.3 测试命名规范与最小必测集合

#### 命名规范

```
should_<expected_result>_when_<condition>
```

示例：
- `should_return_regular_success_when_roll_lte_skill_value`
- `should_interrupt_with_RUNTIME_MODIFIER_CONFLICT_when_b_and_p_coexist`
- `should_preserve_prior_logs_when_node_fails_mid_graph`
