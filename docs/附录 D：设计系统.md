## 一、设计原则与红线

### 1.1 核心哲学

**"秩序优先于氛围，品牌一致高于个性表达"**

- **平台层中性**：导航、按钮使用 Slate 灰阶承载结构，品牌色仅用于"需要被注意"的地方
- **品牌色锁定**：雾霾蓝 `#5B8DB8`（日间）/ `#6B9DC8`（夜间）为主色，灰红 `#B85450`（日间）/ `#C86460`（夜间）为危险/强调色，**禁止修改色相**
- **页面框架强制复用**：所有后台型页面必须复用 `PageLayout` 容器，禁止手写独立布局
- **窄边栏红线**：宽度 < 300px 的边栏内**绝对禁止**放置垂直标签表单、操作按钮、复杂配置项
- **内容为王**：背景退后，卡片突出，避免视觉噪音

### 1.2 绝对红线（违反即视为 Bug）

| 红线 | 说明 | 常见违规场景 |
|------|------|-------------|
| **禁止窄边栏内嵌表单** | 左侧/右侧边栏（<300px）只允许列表、导航、只读卡片 | 跑团房间左侧放"场景/背景音乐/天气"下拉框 |
| **禁止主操作按钮位置混乱** | 主操作（品牌色/深色）必须固定在页面右上角，次操作在左 | 素材库按钮在标题下方，我的作品按钮顺序颠倒 |
| **禁止 Stats 卡片样式不统一** | 所有统计卡片必须左对齐、标签-数值-辅助结构、统一内边距 | 仪表盘左对齐，我的作品居中对齐 |
| **禁止同一功能两处维护** | 顶部 Tab 与左侧边栏不能同时承载同一层信息 | 跑团房间顶部"场景"Tab + 左侧"场景"下拉框 |
| **禁止硬编码颜色** | 所有颜色必须使用 `--color-*` 或 `--surface-*` 语义变量 | ModuleEditor 大量 `#f5f5f5`、`#ddd` |
| **禁止无文档新增页面** | 任何新页面必须先在本文档中定义框架，再进入开发 | 创作者后台完全缺失 |

## 二、页面框架规范（所有后台页面强制复用）

> **适用范围**：创作者后台、个人中心、资产库管理页、GM 控制台等所有"后台型"页面。  
> **核心原则**：所有后台页面必须复用统一的 `PageLayout` 容器，禁止每个页面独立手写布局。

### 2.1 页面容器（PageLayout）

所有后台页面必须包裹在统一的 `PageLayout` 组件内。该组件提供以下固定插槽：

```
┌─────────────────────────────────────────────────────────────┐
│ PageLayout（max-width: 1280px，居中，padding: 24px）         │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ Header（标题区）                                         │ │
│ │  左：标题 + 描述（可选）        右：主操作按钮组          │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ Stats（统计卡片区，可选）                                │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ FilterBar（筛选工具栏，可选）                            │ │
│ │  左：筛选标签/下拉          右：搜索框 + 排序             │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ Content（内容区）                                        │ │
│ │  列表 / 网格 / 表单 / 空状态                              │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

#### 容器规则

| 属性 | 值 | 说明 |
|------|-----|------|
| 最小高度 | `100vh - 64px`（减去顶部导航） | 保证无内容时也不塌陷 |
| 背景色 | `var(--surface-page)` | 跟随日间/夜间模式 |
| 全局内边距 | `24px`（桌面）/ `16px`（平板）/ `12px`（移动端） | 所有区域共享同一内边距 |
| 最大内容宽度 | `1280px` | 居中显示，超宽屏不无限拉伸 |
| 区域间距 | `24px`（桌面）/ `16px`（移动端） | Header → Stats → FilterBar → Content 之间统一间距 |

### 2.2 Header（标题区）

**强制规则**：
- 高度固定：`auto`（由内容撑开，但最小高度 `48px`）
- 布局：`display: flex; justify-content: space-between; align-items: center;`
- 左组：页面标题（`--text-primary`, `24px`, `font-weight: 600`）+ 描述文字（`--text-secondary`, `14px`, `margin-top: 4px`）
- 右组：主操作按钮组
  - **主操作按钮（品牌色）必须位于最右侧**
  - **次操作按钮位于主按钮左侧，间距 `12px`**
  - 按钮顺序从左到右：次操作 → 主操作
  - 禁止在标题下方、内容区内部、卡片内部放置"新建/上传"类主操作

**错误示例**：
```
❌ [主操作] [次操作]        ← 顺序颠倒
❌ 标题
    [主操作]               ← 按钮在标题下方
❌ 卡片内右上角 [新建]       ← 主操作藏在卡片里
```

**正确示例**：
```
✅ 创作者仪表盘                              [管理模组] [进入规则工坊]
   集中查看规则集、模组与最近编辑动作...
```

### 2.3 Stats（统计卡片区）

**使用场景**：仪表盘、我的作品等需要展示关键数据的页面。

**强制规则**：
- 必须使用统一的 `DashboardStats` 组件，禁止手写
- 卡片网格：`display: grid; grid-template-columns: repeat(4, 1fr); gap: 16px;`
- 平板（<1024px）：`repeat(2, 1fr)`
- 移动端（<640px）：固定 `repeat(2, 1fr)`
- 卡片内部结构统一：
  ```
  ┌─────────────────┐
  │ 标签（14px，--text-secondary）│
  │ 数值（32px，--text-primary，font-weight: 700）│
  │ 辅助说明（12px，--text-muted）│
  └─────────────────┘
  ```
- **对齐方式统一为左对齐**，禁止居中对齐
- 内边距统一：`20px`
- 圆角统一：`var(--radius-lg)`（8px）

### 2.4 FilterBar（筛选工具栏）

**强制规则**：
- 高度固定：`48px`（桌面）/ `auto`（移动端可换行）
- 布局：`display: flex; justify-content: space-between; align-items: center;`
- 左组：筛选标签（Tag/Tab 切换），间距 `8px`
- 右组：搜索框（最小宽度 `240px`）+ 排序下拉（如有）
- 与下方内容区间距：`16px`
- 筛选标签样式必须使用 `FilterTag` 组件，禁止手写样式

**位置规则**：
- 筛选栏必须位于统计卡片区下方（如有）或标题区下方（如无统计区）
- **禁止将筛选标签放在内容卡片内部作为"卡片头部"**

### 2.5 Content（内容区）

**强制规则**：
- 背景色：`transparent`（继承 PageLayout 的 `--surface-page`）
- 卡片网格：
  - 桌面（≥1280px）：按内容类型映射。
    - 素材预览类：`repeat(4, 1fr)`
    - 管理卡片类：`repeat(2, 1fr)`
    - 列表类：`repeat(1, 1fr)`
  - 平板（≥768px）：`repeat(2, 1fr)`
  - 移动端：`repeat(1, 1fr)`
- 卡片间距：`16px`（桌面）/ `12px`（移动端）
- 空状态：必须使用统一的 `EmptyState` 组件，居中显示，包含 SVG 占位图 + 标题 + 描述 + 操作按钮（可选）

### 2.6 栅格系统

后台页面统一使用 12 列栅格，但内容区实际采用简化版：

```css
.page-content {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 16px;
}

/* 常见布局模式 */
.layout-full     { grid-column: span 12; }   /* 全宽：列表、表单 */
.layout-main     { grid-column: span 8; }    /* 主内容：2/3 */
.layout-sidebar  { grid-column: span 4; }    /* 侧边栏：1/3 */
.layout-half     { grid-column: span 6; }    /* 双栏：1/2 */
```

**创作者后台统一使用 `layout-full`**（单栏最大宽度 1280px），不采用左右分栏，避免与左侧导航竞争。

### 2.7 表单排版模式

#### 决策树

```
容器宽度 ≥ 600px ?
  ├─ 是 → 使用【垂直标签模式】（标签在上，控件在下）
  │        适用于：设置页、创建房间表单、发布招募帖
  └─ 否 → 使用【水平标签模式】（标签在左，控件在右）
           适用于：窄边栏（<300px）、工具栏内联配置、导演模式侧边面板
```

#### 垂直标签模式（标准表单页）

```
标签（14px，--text-secondary，margin-bottom: 6px）
[输入框 / 下拉框 / 文本域]（高度 40px，padding 10px 14px）
辅助文字（12px，--text-muted，margin-top: 4px）
```

- 表单项间距：`20px`
- 标签字体：`--text-secondary`，`font-weight: 500`
- 输入框背景：`var(--surface-page)`（日间）/ `var(--surface-card)`（夜间）

#### 水平标签模式（窄边栏/工具栏）

```css
.form-row-compact {
  display: flex;
  align-items: center;
  gap: 8px;
  padding: 6px 0;
  min-height: 32px;  /* Dense 密度 */
}

.form-row-compact label {
  width: 60px;
  flex-shrink: 0;
  font-size: 12px;
  color: var(--text-secondary);
  text-align: right;
}

.form-row-compact select,
.form-row-compact input {
  flex: 1;
  min-width: 0;
  height: 28px;  /* Dense 密度 */
  padding: 0 8px;
  font-size: 12px;
}
```

**红线**：窄边栏（<300px）内**绝对禁止**使用垂直标签模式。如果配置项超过 3 个，必须改用折叠面板或移至宽页面。

### 2.8 控件密度分级

| 等级 | 名称 | 控件高度 | 间距 | 字体 | 使用场景 |
|------|------|----------|------|------|----------|
| Dense | 紧凑 | 28-32px | 8px | 12px | 边栏、工具栏、导演模式面板 |
| Normal | 标准 | 40px | 16px | 14px | 常规表单、筛选栏 |
| Comfortable | 舒适 | 48px | 24px | 16px | 设置页、低频操作 |

### 2.9 响应式断点

| 断点 | 宽度 | 布局调整 |
|------|------|----------|
| Desktop | ≥1280px | 完整布局，4列网格 |
| Laptop | ≥1024px | 3列网格，边栏可折叠 |
| Tablet | ≥768px | 2列网格，部分边栏隐藏 |
| Mobile | <768px | 单列，筛选栏换行，操作按钮下沉 |

## 四、各页面详细设计

### 4.1 首页（冷启动友好 + 强组车引导）

**定位**：用户打开平台的第一站，展示**永不空**的内容，并强力引导用户参与组车。

**布局**：两列（主内容区 2/3，右侧边栏 1/3）

**主内容区**：

#### 4.1.1 快速组车卡片

**功能定位**：为未明确目标的用户提供核心入口。

**包含入口**：
- **找团玩**：跳转至社区-招募板的"找团玩"Tab。
- **当 KP**：跳转至社区-招募板的"当KP"Tab。
- **发布求组帖**：直接打开发布求组帖的表单模态框。
- **发布招募帖**：直接打开发布招募帖的表单模态框。
- **可观战的团**：跳转至招募板并自动筛选"可观战"的招募帖。

**交互规则**：
- 所有入口点击后执行对应跳转或打开模态框。
- 未登录用户点击时，先弹出登录/注册模态框。

#### 4.1.2 为你推荐（卡片网格，3列）
- 基于用户偏好推荐的**模组**和**规则包**混合展示
- 冷启动时展示平台精选的免费/热门内容（官方预置10+个）
- 卡片：封面、标题、类型标签（模组/规则）、作者、价格
- 操作：`[开团]` → 触发简化开团流程（见 5.1 节）

#### 4.1.3 组车动态（固定纵向列表）
- 默认以纵向列表展示最新**招募帖**和**求组帖**，首屏默认展示6条，带标签区分：
  - `[招募]` 蓝色标签：标题、GM、规则、人数进度
  - `[求组]` 绿色标签：玩家昵称、期望规则、可参与时间
- 点击卡片跳转社区-招募板对应帖子详情
- 冷启动时由官方/运营填充示例内容

**右侧边栏**：

#### 4.1.4 新手入门指南（固定模块）
- 图文/视频教程、快速创建角色卡、第一个模组推荐
- 每个条目可点击跳转帮助中心

#### 4.1.5 平台动态（精简）
- 平台公告、新功能上线、优秀创作者作品推荐

### 4.2 资产库（两层结构 + 状态标签优化）

**页面结构**：一级Tab：`发现` / `我的`

#### 4.2.1 发现（原"浏览"）
- **二级Tab**：模组集市 / 规则集市
- **模组集市**：
  - 三级Tab：推荐、新上、**公示**、关注
  - 筛选栏：规则、题材、难度、人数、风格、排序
  - 卡片网格（4列），**每个卡片增加状态标签**：
    - **未拥有**：按价格单义处理：`price = 0` 显示 `[免费获取]`；`price > 0` 显示 `[购买]`。
    - **已拥有**：显示绿色标签"已在库中"，操作按钮 `[开团]`
  - 公示期卡片：显示倒计时 + `[提出异议]` 按钮
- **规则集市**：类似结构，卡片显示规则包名称、作者、类型、价格；已拥有显示"已在库中"

#### 4.2.2 我的
- **二级Tab**：模组 / 规则 / 人物卡 / 我创作的（仅创作者可见）
- 展示用户已购买、收藏、自创的内容
- 每个资产卡片操作：`[开团]`（已拥有资产）、`[编辑]`（自创草稿）、`[删除]`等

> **边界澄清**：用户购买模组后，在"发现"中该卡片会变为"已在库中"状态，点击 `[开团]` 可直接使用，无需去"我的"页。同时，"我的-模组"中也会出现该模组，作为永久资产列表。

### 4.3 我的团

**定位**：用户管理自己**参与或正在观看**的团。

> **⚠️ 关键约束**：
> 1. 平台**不设独立的"房间大厅"或"公开房间列表"**。
> 2. 所有公开招募性质的团，均通过**社区-招募板**发布招募帖进行。
> 3. **玩家加入房间的路径**：
>    - 申请招募帖 → GM 确认 → 房间出现在"我的房间"列表
>    - 接受邀请 → 房间出现在"我的房间"列表
>    - 直接创建私密团 → 房间出现在"我的房间"列表
> 4. **OB 观看的路径**：
>    - 在招募板筛选"可观战" → 点击 `[观看团]` → 以 OB 身份进入该团的剧情场（只读）
>    - OB 进入后，该房间**临时出现**在"我的房间"列表中，退出后消失
>    - OB 身份**不可发言、不可掷骰**，仅观看剧情场

**内容区**：列表 —— **我的房间**

**创建房间页面**：
- **必填**：房间名、规则包（下拉选择）。**规则包一经选定不可更改**。
- **可选**：模组（下拉选择："无模组" / 从资产库选择已有模组）。

- **发布选项**：
  - ☐ 发布到招募板（勾选后展开招募信息表单）
- **点击【创建】后**：
  1. 房间立即创建成功，获得房间码。
  2. **若勾选了"发布到招募板"**：
     - 系统自动在招募板生成一条关联此房间的招募帖。

  3. 房间出现在创建者的"我的团-我的房间"列表中。
  4. 所有公开招募性质的团，均通过招募帖进行，**平台不设独立的"房间大厅"或"公开房间列表"**。

**发布到招募板（展开表单）**：

#### 4.4.5 成团流程

**触发条件**：
- 人数已满时自动触发成团。
- GM 可在未满员时手动点击【成团】触发。

**流程**：
1. 系统检查该招募帖是否已关联 `campaign`（即是否来自路径 B 先建团后发帖）。
   - **若已关联**：直接将该房间的成员列表更新为所有通过申请的玩家，并推送通知。
   - **若未关联**（路径 C：先发帖后成团）：
    - **a. 模组确认**：
      - 若发帖时模组状态为"已选定"，成团时直接使用该已选定模组。
      - 若发帖时模组状态为"无模组"，成团时直接创建空白团（无预设模组内容）。
       - 若发帖时模组状态为"待定"，弹出模态框：
         - 成团 - 选择模组  
           ○ 从资产库选择已有模组 [下拉▼]  
           ○ 创建一个空白模组（即兴团）  
           [取消] [确认成团]
     - **b. 创建房间**：系统根据招募帖的规则包和选定的模组状态自动创建房间（私密）。
     - **c. 导入内容**：若绑定了模组，自动导入场景、NPC、线索等。
2. 系统通过站内通知和私信向所有通过申请的成员发送房间码。
3. 房间自动出现在所有成员"我的团-我的房间"列表中。
4. 招募帖状态变为"已关闭"。

**边界情况**：
- 若成团时 GM 取消模组选择，则流程中止，招募帖保持原状态。
- 若成团时模组选择"创建一个空白模组"，则创建的房间无预设内容，GM 需在房间内手动添加。

#### 4.4.6 邀请入团流程（新增完整设计）

**触发**：GM在"当KP"Tab的求组帖卡片上点击 `[邀请入团]`

**界面元素**：
- 标题："邀请玩家「[玩家昵称]」加入你的游戏"
- 单选框：
  - ○ 邀请至现有房间
  - ○ 为此玩家新建一个房间
- 下拉选择器（当选择"现有房间"时显示）：列出 GM 所有进行中的房间
- 模组选择（当选择"新建房间"时显示）：默认使用玩家期望规则，可切换
- 按钮：【取消】【发送邀请】

**交互规则**：
- GM 在"当KP"列表的求组帖卡片上点击 `[邀请入团]` 时触发此模态框。
- 默认选中"邀请至现有房间"，下拉框显示 GM 进行中的房间列表。
- 选择"为此玩家新建一个房间"时，下方显示模组选择器，默认使用玩家在求组帖中填写的期望规则。
- 点击【发送邀请】后，系统创建邀请记录，并向玩家推送通知。
- 玩家在通知中点击"接受"后按邀请类型执行：
  - 邀请类型为"现有房间"：加入该现有房间。
  - 邀请类型为"新建房间"：进入由该邀请创建的新房间。

**数据来源**：
- 玩家昵称：从求组帖中获取。
- 现有房间列表：从 `campaigns` 表中查询 `gm_user_id = 当前GM` 且 `status = 'running' or 'preparing'` 的记录。
- 模组选择器：从 GM 的资产库中查询已拥有的模组。

#### 4.7.6 时间控制与预约移动

##### 全局剧情时间显示

- **所有成员**：顶部栏显示当前全局剧情时间（只读）
- **GM 特权**：
  - 点击推进按钮（`+30m`、`+1h`）执行固定步进推进。
  - 点击时间数字（`第N日 HH:MM`）打开自定义时间选择器（滚轮，精确到分钟）。
  - 两个入口独立生效，不互斥。

##### 时间推进确认弹窗（GM）

**触发**：
- 固定步进推进：GM 点击时间推进按钮（+30 分钟、+1 小时）。
- 自定义推进：GM 点击时间数字并在选择器内确认目标时间。

**弹窗内容**：
- 提示文本："推进全局时间至 第X日 HH:MM"
- 列出将触发执行的所有预约移动（角色、起点、终点、预计到达时间）。
- 若某移动的目标场景已被删除，该项显示红色警告，并注明"将被自动取消"。
- 若某移动的目标场景类型不是剧情场，该项显示红色警告，并注明"将被自动取消"。
- 按钮：【取消】【确认推进】

**确认后行为**：服务端在事务中执行时间推进、更新角色位置、记录位置历史，并通过 Socket.IO 广播结果。

##### 玩家申请移动

**入口**：
- 助理台指令速查中的 `[申请移动]` 按钮
- 输入 `/move` 指令

**界面元素**：
- 标题："申请移动"
- 下拉选择器：目标场景（列出当前团所有剧情场）
- 交通方式下拉（仅当团启用场景连通时显示）：步行 / 骑行 / 驾车
- 预计耗时（自动计算，只读）
- 预计到达时间（自动计算，只读）
- 按钮：【取消】【提交申请】

**交互规则**：
- 入口：
  - 助理台指令速查中的 `[申请移动]` 按钮。
  - 输入 `/move` 指令。
- 选择目标场景后，若启用场景连通且选择了交通方式，系统根据连通表自动计算预计耗时和到达时间。
- 若未启用场景连通，则只显示目标场景选择，不显示交通方式和耗时。
- 点击【提交申请】后，生成一条 `status = 'pending'` 的预约移动记录，并向 GM 发送待审批通知。

**数据来源**：
- 目标场景列表：从 `scenes` 表中查询当前团的 `type = 'spatial'` 的记录。
- 耗时计算：从 `scene_connections` 表中查询最短路径并累加耗时。

##### GM 审批面板

**入口**：GM 控制台 → "待审批移动"标签页。

**界面元素**：
- 标题："待审批移动"
- 表格列：申请人 | 当前位置 | 目标场景 | 交通方式 | 预计耗时 | 申请时间 | 操作
- 操作按钮：【批准】【拒绝】【修改时间】（每个申请一行）

**交互规则**：
- 入口：GM 控制台 → "待审批移动"标签页。
- 点击【批准】：弹出时间修改框（预设到达时间 = 当前全局时间 + 预计耗时），GM 可调整。确认后预约移动状态变为 `approved`，并通知玩家。
- 点击【拒绝】：预约移动状态变为 `cancelled`，通知玩家申请被拒绝（可选填理由）。
- 点击【修改时间】：仅修改到达时间，状态保持 `pending`，并通知玩家时间已调整。
- 若目标场景已被删除，该行显示红色警告，且【批准】按钮禁用。

**数据来源**：
- 待审批列表：从 `scheduled_moves` 表中查询 `status = 'pending'` 且 `campaign_id = 当前团` 的记录。
- 角色信息：关联 `character_sheets` 表获取角色名。
- 场景信息：关联 `scenes` 表获取场景名。

**入口**：
- 左侧导航在场角色列表中，右键角色 → "强制移动"
- 轨迹矩阵单元格右键 → "移动此角色到此场"

**弹窗**：

- 立即执行：取消该角色所有未执行预约，直接更新位置和个人时间为当前全局时间。
- 定时执行：创建一个已批准的预约移动（跳过玩家申请环节），到期自动执行。
- 聊天区插入 `[GM强制]` 标记的系统消息。

##### 预约移动执行（系统自动）

当 GM 推进全局时间时，系统自动检查所有 `status='approved'` 且 `execute_at_story <= 新时间` 的预约移动，按时间升序依次执行：

1. **离开原场景**：更新 `campaign_character_instances.current_spatial_scene_id = NULL`，位置历史中旧记录的 `story_time_left` 设为离开时间。
2. **在途状态**：角色不显示在任何场景，轨迹矩阵中对应时间段留白。
3. **到达目标场景**：更新 `current_spatial_scene_id = 目标场景`，个人剧情时间 = 到达时间，位置历史插入新记录（`story_time_entered = 到达时间`）。
4. **广播**：通过 Socket.IO 推送 `position_changed` 事件，所有客户端实时更新界面。

#### 4.7.7 技能同步提示组件

**触发场景**：
1. **检定时检测到跨团技能成长**：玩家发起技能检定（如 `ra 侦查`）时，系统对比 Template 与当前 Instance 的技能值，若 Template 更高，则弹出确认框。
2. **进入房间时检测到跨团技能成长**：玩家进入房间时，后台检测到该角色卡在其他团中有技能成长，顶部显示可关闭横幅。

**弹窗样式**：

```
┌─────────────────────────────────────────────────┐
│ 🔄 检测到技能成长                                │
├─────────────────────────────────────────────────┤
│ 你在其他团中的「侦查」技能已提升至 55。          │
│ 当前团的技能值为 50。是否立即同步？              │
│                                                 │
│ [暂不同步] [立即同步]                            │
└─────────────────────────────────────────────────┘
```

- 点击「立即同步」：Instance 技能值更新为 Template 值，弹窗关闭，检定继续使用新值。
- 点击「暂不同步」：保留 Instance 旧值，本次团内不再提示该技能的同步，但 GM 可手动触发。

**顶部横幅样式**：

```
┌──────────────────────────────────────────────────────────────────┐
│ ℹ️ 你的角色卡在其他团中有技能成长（侦查 50→55，图书馆 40→45） [同步] [忽略] ✕ │
└──────────────────────────────────────────────────────────────────┘
```

- 背景色：`--color-info-bg`，文字色：`--color-info`。
- 点击「同步」：批量同步所有有成长的技能，横幅消失。
- 点击「忽略」：关闭横幅，本次登录会话内不再显示。
- 点击「✕」：仅临时关闭横幅，刷新页面或重新进入房间后可再次显示。

**交互规则**：
- 若技能值差距 ≥5 点，不弹窗，直接强制同步并显示轻提示："技能「侦查」已自动同步至 55"。

#### 4.7.8 轨迹矩阵（会员功能，需开团时启用）

**界面元素**：
- 横向滚动表格：
  - 纵轴（行）：时间切片固定为每 30 分钟。
  - 横轴（列）：剧情场列表（按创建顺序排列）。
- 单元格内容：
  - 灰色单元格：已发生的时间点，显示角色头像。3 个及以下平铺展示，超过 3 个折叠为“+N”。
  - 红色竖线：标记当前全局剧情时间所在的列。
  - 白色单元格 + 虚线框：未来时间点，显示已批准的预约移动预览。
- 右键菜单：移动此角色到此场 / 查看角色状态快照。

**交互规则**：
- 入口：GM 控制台 → "轨迹矩阵"标签页（仅当团创建时启用此模块才显示）。
- 点击单元格 → 弹出该时刻该场的角色状态快照（角色卡摘要）。
- 右键单元格 → 弹出菜单，可触发强制移动或查看快照。
- 支持选择时间范围导出剧情回顾（CSV/JSON）。
- 拖拽预约移动的虚线框可调整到达时间（需重新审批）。
- **只读约束**：GM 不可直接编辑单元格内容。

**数据来源**：
- 时间切片：根据 `campaigns.global_story_time` 和配置的粒度生成。
- 场景列表：从 `scenes` 表中查询当前团的 `type = 'spatial'` 的记录。
- 历史位置：从 `position_history` 表中查询，按 `story_time_entered` 和 `story_time_left` 确定每个角色在特定时间切片的位置。
- 预约移动预览：从 `scheduled_moves` 表中查询 `status = 'approved'` 且 `execute_at_story > 当前时间` 的记录。

##### 移动端适配（时间轴视图）

**默认视图**：垂直时间轴，按时间倒序排列，每条节点显示：
- 时间（如"第1日 15:30"）
- 该时刻发生的场景切换事件摘要（如"张三 进入 图书馆"）
- 可点击展开查看该时刻所有场景的角色位置快照（卡片列表）

**场景筛选**：顶部下拉选择特定场景，时间轴只显示该场景的角色位置变化。

**GM 操作**：长按时间节点弹出动作菜单（强制移动、查看快照）。

> 技术实现：使用虚拟滚动列表渲染时间轴，快照数据按需加载。

#### 4.7.9 场景连通配置（高阶 GM 功能，会员专享）

**移动端**：仅支持只读查看路径列表，编辑提示"请在电脑上操作"。

**界面元素**：
- 标题："场景连通路径配置"

**交互规则**：

## 五、关键交互流程

### 5.1 简化开团流程

当用户从首页"快速组车卡片"或资产库"已拥有模组/规则包"点击 `[开团]` 时，系统将：
1. 自动创建私密团并按入口资产类型落库：
  - 从“模组资产”进入：绑定 `module_id` 与对应 `ruleset_id`。
  - 从“规则包资产”进入（无模组）：`module_id = null`，仅绑定 `ruleset_id`，创建空白团。
2. 跳过房间名填写、招募选项等步骤，直接进入房间。
3. 房间默认名规则：有模组时为"{模组名} 的团"；无模组时为"{规则包名} 的团"。GM 可后续在房间设置中修改。

此流程旨在将"从拥有资产到开始游戏"的点击次数降至最低。

### 5.2 用户目标路径汇总

| 用户目标 | 路径 | 点击次数 |
|----------|------|----------|
| 开一个私密团（和朋友玩） | 资产库点击`[开团]` → 填房间名 → 创建 | 2次（含表单确认） |
| 开一个公开招募团 | 资产库点击`[开团]` → 填房间名 + 勾选"公开招募" → 创建 → 跳转招募板 → 补充信息发布 | 4-5次 |
| GM招募玩家 | 社区→招募板→发布招募帖 → 填写表单 → 发布 | 3-4次 |
| 玩家找团 | 社区→招募板→找团玩 → 筛选 → 申请加入 | 3次 |
| GM邀请求组玩家 | 社区→招募板→当KP → 点击`[邀请入团]` → 选择现有/新建房间 → 发送 | 3次 |
| 玩家接受邀请 | 收到通知 → 点击接受 | 2次 |
| 观看一场公开招募团的游戏 | 社区→招募板→找团玩 → 筛选"可观战" → 点击`[观看直播]` | 3-4次 |
